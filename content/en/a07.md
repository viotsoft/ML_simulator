# Module A7. Workflow or agent?

> **Level:** Middle AI · **Time:** ~50 minutes · **Format:** situation → theory → practice → quiz

---

## 🏢 The situation

Success: 78% of drafts go out without edits and Igor is happy. Marina expands the scope:

> "Now let the agent gather the lead research itself. Visit the company site, check their job openings, find recent news — and write a genuinely personal email. Give it tools and let it work."

You build an autonomous agent: four tools and the goal "gather context and write the email". You run it on 20 leads.

Forty minutes later:

- one agent made 34 search calls about a single company and stopped on the limit;
- another decided it had too little data and wrote about "your industry in general";
- a third crawled a competitor's careers page because it appeared in the results;
- fourteen worked beautifully;
- the bill for one hour matched all of last week.

Lena looks at the traces: "Why did you let it decide the order at all? You know the order yourself."

## 🎯 Your task

1. Understand where autonomy adds value and where it only adds variance and cost.
2. Rewrite context gathering as a deterministic graph.
3. Keep agency exactly where it is genuinely needed.

### The three-question test

Before letting the model decide the order of actions, answer:

1. **Do I know the sequence in advance?** If yes, it is a workflow. "Site → jobs → news → email" is known.
2. **Is the number of variants finite?** Five lead types with different routes is branching in code, not model reasoning.
3. **What do I do if the agent chooses badly?** If the answer is "I don't know" or "I'd notice in a week", it is too early for autonomy.

In our case: known, finite, noticed late. So — a graph.

### Where autonomy is justified

- **Research:** "find who owns data at this company" — the route depends on what turns up.
- **Debugging and investigation:** "figure out why this run failed" — steps depend on findings.
- **The long tail:** cases where writing a dedicated branch is not worth it.

The signature: you cannot write the list of steps in advance, because step two depends on step one in an **unpredictable** way.

### Budgets instead of hope

If autonomy really is needed, it is bounded explicitly:

| Limit | Why |
| --- | --- |
| Max loop steps | Protects against runaway loops (that 34-call agent) |
| Max calls per tool | One tool cannot eat the whole budget |
| Token budget per task | A predictable bill |
| Timeout for the whole task | Nobody waits forever |
| Domain allowlist | The agent cannot wander onto a competitor's site |

Hitting a limit is not an error, it is a normal outcome. Return the partial result and record why it stopped.

## 💻 Practice

The same context gathering — as a graph. The model runs on each step; the order lives in code.

```python
import os, json, anthropic
from urllib.parse import urlparse

client = anthropic.Anthropic(api_key=os.environ["ANTHROPIC_API_KEY"])
MODEL = "claude-sonnet-5"
ALLOWED_HOSTS = {"careers.", "jobs.", "blog.", "www."}     # allowlisted prefixes

# --- Graph steps: each does one thing and returns structure ---
def step_company_page(lead):
    html = fetch(lead["website"])                       # your fetch function
    return extract(html, "Describe what the company does, 2 sentences", max_tokens=200)

def step_jobs(lead):
    url = find_careers_url(lead["website"])
    if not url or not same_site(url, lead["website"]):   # never wander to another site
        return None
    return extract(fetch(url), "List open roles related to data and ML", max_tokens=300)

def step_news(lead):
    items = search_news(lead["company"], limit=3)        # your news source
    return items or None

def collect_context(lead):
    """The order is known, so it lives in code. Every step is optional."""
    ctx, notes = {}, []
    for name, fn in [("about", step_company_page), ("jobs", step_jobs), ("news", step_news)]:
        try:
            value = fn(lead)
        except Exception as e:
            notes.append(f"{name}: failed ({type(e).__name__})")
            continue
        if value:
            ctx[name] = value
        else:
            notes.append(f"{name}: empty")
    return ctx, notes


def write_with_context(lead):
    ctx, notes = collect_context(lead)
    # Branching in code, not "let the model decide"
    if not ctx.get("jobs") and not ctx.get("news"):
        return None, f"no hook found: {'; '.join(notes)}"   # an honest refusal beats generic filler
    draft = generate_grounded(lead, ctx)                    # from A5
    return draft, None
```

And here is where autonomy stays — the research sub-step "find the data owner", whose route is genuinely unknown:

```python
MAX_STEPS = 6
MAX_PER_TOOL = 3

def find_data_owner(company, tools):
    """An autonomous sub-step on a hard budget. Hitting the limit is a normal outcome."""
    messages = [{"role": "user", "content": f"Find who owns data or ML at {company}."}]
    used = {}
    for step in range(MAX_STEPS):
        resp = client.messages.create(model=MODEL, max_tokens=700, tools=tools, messages=messages)
        if resp.stop_reason != "tool_use":
            return {"answer": resp.content[0].text, "steps": step, "stopped": "answered"}
        messages.append({"role": "assistant", "content": resp.content})
        results = []
        for block in [b for b in resp.content if b.type == "tool_use"]:
            used[block.name] = used.get(block.name, 0) + 1
            if used[block.name] > MAX_PER_TOOL:
                results.append({"type": "tool_result", "tool_use_id": block.id,
                                "content": "call limit for this tool exhausted",
                                "is_error": True})
                continue
            if block.name == "fetch_url" and not allowed(block.input.get("url", "")):
                results.append({"type": "tool_result", "tool_use_id": block.id,
                                "content": "domain not on the allowlist", "is_error": True})
                continue
            results.append({"type": "tool_result", "tool_use_id": block.id,
                            "content": run_tool(block.name, block.input)})
        messages.append({"role": "user", "content": results})
    return {"answer": None, "steps": MAX_STEPS, "stopped": "budget"}   # an outcome, not an error


def allowed(url):
    host = urlparse(url).netloc
    return any(host.startswith(p) or host.endswith(".com") for p in ALLOWED_HOSTS)
```

What changed compared to "give it four tools and a goal":

1. **The step order lives in code.** Thirty-four calls on one company became structurally impossible.
2. **A refusal instead of filler.** No jobs and no news means we hand the lead to a human rather than write "about your industry in general".
3. **A domain allowlist.** The agent cannot walk onto a competitor's site even if it ranks.
4. **Per-tool and per-loop limits.** Stopping on budget is a normal, logged outcome with a partial result.

**Assignment.** Take your own autonomous prototype and measure from the traces: average steps, the spread, and the cost of the worst run. Then move the known part of the route into a graph and compare. Average cost usually drops 2–4×, and variance by an order of magnitude.

## 📌 Remember

- Autonomy is not a maturity level, it is the price of not knowing the route.
- If you know the order of steps, put it in code. Cheaper, more predictable, easier to fix.
- Three questions before granting autonomy: do I know the order, are the variants finite, will I notice a bad choice.
- Autonomy earns its keep in research, debugging and the long tail — where step two depends on step one unpredictably.
- Every loop is bounded: steps, calls per tool, tokens, time, domains.
- Stopping on budget is a normal outcome with a partial result, not an exception.

**Further reading:** Anthropic's "Building effective agents" on the workflow/agent distinction; material on the ReAct loop and its cost; and your own traces — the most persuasive argument in this debate.
