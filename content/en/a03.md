# Module A3. The inbox simulator: an agent triages campaign replies

> **Level:** Junior AI · **Time:** ~55 minutes · **Format:** situation → theory → practice → quiz

---

## 🏢 The situation

Ten days in. The agent drafts, Igor sends. And then the thing you built it for arrives: **replies**.

180 emails in a week. Igor opens his inbox and loses patience:

> "Look at this: three real 'let's talk', two 'remove me from your list' — and a hundred and seventy-five auto-replies saying 'I'm on vacation until the 14th'. I spend an hour a day finding the three emails that matter. At least before I knew who I was writing to."

Marina asks at standup: "Can the agent triage the inbox itself?"

It can. And it is a **different task** from writing: there is no creativity here, there is consistency. The same email must always land in the same category — otherwise Igor stops trusting the folders.

## 🎯 Your task

1. Classify inbound mail: interest, rejection, unsubscribe, auto-reply, wrong person, junk.
2. Extract the facts the CRM needs: when they will be back, who they refer you to, what objection they raised.
3. Route it: what Igor sees today, what goes to the CRM, and what he must never see.

---

## 📚 Theory

### Classification is not generation

| | Email draft (A2) | Inbox triage (A3) |
| --- | --- | --- |
| Temperature | 0.7 — variety helps | **0** — consistency is mandatory |
| Output | Free text inside a schema | A strict enum from a fixed list |
| Cost of a mistake | A human fixes it before sending | The email lands in the wrong folder and is lost |
| How to measure | Share of edits | Per-category accuracy on a labeled set |

The core rule: **the category list is closed and declared in the schema as an enum**. "Invent a suitable category" guarantees a zoo of "Interest", "interested", "Maybe interested".

### Categories are designed from the action, not from the meaning

A bad category list describes shades of feeling. A good one describes **what happens next**:

| Category | What the system does | Who sees it |
| --- | --- | --- |
| `interested` | Top of Igor's list, flagged in CRM | Igor, today |
| `not_now` | Return date into CRM, reminder set | Igor, on that date |
| `wrong_person` | Pull out the referred contact | Igor, today |
| `unsubscribe` | **Immediately** to the stop list | Nobody, but always logged |
| `auto_reply` | Quietly archived | Nobody |
| `other` | Manual review | Igor, once a week |

The `other` category is mandatory. Without it the model will shove a strange email into the nearest category — and you will never find out.

Hence the practical rule: **lower the threshold for expensive categories**. If the model thinks an email might be an unsubscribe, it is an unsubscribe. Losing one warm lead is cheaper than ignoring a direct request.

### Few-shot: examples beat explanations

You can describe in words the difference between "I'm swamped right now, write me in March" (`not_now`) and "we don't need this" (`rejected`), but three examples in the prompt work better than two paragraphs of instructions. Take examples from real mail — especially the **borderline** ones the model got wrong.

## 💻 Practice

```python
# pip install anthropic
import os, json, anthropic

client = anthropic.Anthropic(api_key=os.environ["ANTHROPIC_API_KEY"])
MODEL = "claude-sonnet-5"

CATEGORIES = ["interested", "not_now", "rejected", "wrong_person",
              "unsubscribe", "auto_reply", "other"]

TRIAGE_TOOL = {
    "name": "triage",
    "description": "Triage an inbound email and return a decision",
    "input_schema": {
        "type": "object",
        "properties": {
            "category": {"type": "string", "enum": CATEGORIES},   # closed list
            "confidence": {"type": "number", "description": "0..1 confidence in the category"},
            "return_date": {"type": ["string", "null"], "description": "ISO date if they ask to be contacted later"},
            "referred_contact": {"type": ["string", "null"], "description": "Who they refer us to instead"},
            "objection": {"type": ["string", "null"], "description": "The objection in one phrase, if any"},
            "reason": {"type": "string", "description": "Why this category, one sentence"},
        },
        "required": ["category", "confidence", "reason"],
    },
}

# Borderline examples matter more than explanations
SYSTEM = """You triage replies to a B2B outbound campaign. Always call triage.

Examples:
"Thanks, interesting, but let's talk in March — we're closing the quarter" → not_now, return_date in March
"I don't handle this, write to Anna Kovaleva, she owns data" → wrong_person
"Unsubscribe me" / "stop" / "don't write again" → unsubscribe
"I'm on vacation until October 14, write after that" → auto_reply (an autoresponder, not interest!)
"We already have a similar solution and we're happy with it" → rejected, objection about the existing solution
If an email fits no category — other. Never invent new categories."""


def triage(email_text):
    resp = client.messages.create(
        model=MODEL, max_tokens=500,
        temperature=0,                    # same email, same category
        system=SYSTEM, tools=[TRIAGE_TOOL],
        tool_choice={"type": "tool", "name": "triage"},
        messages=[{"role": "user", "content": email_text}],
    )
    return next(b for b in resp.content if b.type == "tool_use").input


# Asymmetric errors: an unsubscribe is never guessed, it is over-detected
UNSUB_HINTS = ("unsubscribe", "remove me", "stop writing", "take me off", "opt out")

def route(email_text, result):
    text = email_text.lower()
    if any(h in text for h in UNSUB_HINTS) or result["category"] == "unsubscribe":
        return "STOP_LIST", "unsubscribe — to the stop list immediately"
    if result["confidence"] < 0.6:
        return "MANUAL", f"low confidence ({result['confidence']:.2f}) — send to manual review"
    return {
        "interested":   ("TODAY", "show Igor today"),
        "wrong_person": ("TODAY", "pull out the referred contact"),
        "not_now":      ("CRM", "set a reminder for the return date"),
        "rejected":     ("CRM", "record the objection and close"),
        "auto_reply":   ("ARCHIVE", "archive quietly"),
        "other":        ("MANUAL", "weekly review"),
    }[result["category"]]


INBOX = [
    "Hi! Sounds interesting, tell me more. Could we talk on Thursday?",
    "I'm on vacation until October 14. For urgent matters contact Marina.",
    "Please unsubscribe me from this list.",
    "Thanks, but I don't handle this. Write to Anna Kovaleva, she owns data here.",
]

for text in INBOX:
    r = triage(text)
    bucket, why = route(text, r)
    extra = r.get("referred_contact") or r.get("return_date") or ""
    print(f"[{bucket:8}] {r['category']:12} conf={r['confidence']:.2f} · {why}")
    if extra:
        print(f"           extracted: {extra}")
```

What matters here:

1. **The `enum` in the schema closes the category list.** The model physically cannot return "maybe interested".
2. **`temperature=0`** — the same text always yields the same category. Otherwise Igor notices yesterday's email in a different folder and stops trusting the system.
3. **Unsubscribes are handled outside the model too.** A simple keyword check plus the model's decision: either one triggers. This is where over-caution beats accuracy.
4. **A confidence threshold** sends doubtful mail to a human instead of failing silently.
5. **Extraction happens alongside classification.** One call returns the category, the return date and the referred contact — no need to call the model twice.

**Assignment.** Take 20 real (or invented) replies, label them by hand, run them through the agent and count: how many matched, where it erred, and whether a single unsubscribe missed the stop list. That last number must be zero — if it is not, fix the rule, not the prompt.

---

## 📌 Remember

- Classification is a consistency task: temperature 0 and a closed `enum`, not free text.
- Categories are designed from the system's action, not from shades of meaning. The `other` category is mandatory.
- Misclassifications carry different costs: tune the system to err on the cheap side.
- Unsubscribes are never guessed. Duplicate the check with a plain rule outside the model.
- A confidence threshold is the cheapest way to turn a silent error into a human task.
- Borderline examples in the prompt beat a paragraph of explanation.
