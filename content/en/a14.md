# Module A14. Debugging a bad run

> **Level:** Senior AI · **Time:** ~50 minutes · **Format:** situation → theory → practice → quiz

## 🏢 The situation

A customer sends a screenshot of an email inviting them to "continue the implementation discussion we had at the conference". There was no conference. The customer politely asks whether they have been confused with someone else.

Igor forwards it to you. You open the logs and find:

```

2026-03-14 11:42:09 INFO  outreach lead=lead-8842 status=sent
```

That is all. Nothing about what the context collector found, which prompt version ran, what the model returned, or which memory facts were injected.

Marina asks: "How long until you can tell me why this happened?" The honest answer is "I can't": the run cannot be reproduced, and guessing from one email is pointless.

## 🎯 Your task

1. Understand how debugging an agent differs from debugging an ordinary service.
2. Record runs so they can still be investigated a month later.
3. Learn to reproduce a specific run, not "something roughly similar".

## 📚 Theory

### Why ordinary logs are not enough

An ordinary service is deterministic: the same input gives the same output, and the stack trace shows where it broke. An agent is different:

| | Ordinary service | Agent |
| --- | --- | --- |
| Reproducibility | Same input → same output | Same input → different output |
| Where the error is | Visible in the stack | Could be any of 6 steps |
| What to record | Input, output, exception | The whole decision chain and each step's data |
| Who is "at fault" | A line of code | The prompt, retrieved context, memory, model — or a combination |

So run recording is not "logs for debugging", it is **the primary working tool**. Without it, every complaint becomes guesswork.

### What goes into a span

The minimum without which investigation is impossible:

- **Identifiers:** the run's trace_id, the task id, the lead_id — so it links to the customer's complaint.
- **The step's input and output** in full. Not "found 3 documents" but which ones.
- **Versions:** prompt, model, tool schema, code.
- **Metrics:** duration, tokens, cost.
- **Decisions:** which branch was taken and why ("hold mode, because there is an open deal").

And the hygiene rule from A10: personal data in traces lives under the same lifetime as in memory and is deleted by the same operation.

### Replay

A good trace lets you **re-run** the execution: take the recorded input, context and prompt version, and run it again. Two modes:

1. **Replay as-is** — on the same version, to see the model's spread.
2. **Replay with a change** — on a new prompt version, to check whether the fix addresses this complaint.

The second mode turns a one-off complaint into a golden-set case (A6) automatically.

## 💻 Practice

```python
import os, json, time, uuid, contextvars, sqlite3, datetime as dt

trace_db = sqlite3.connect("traces.db", check_same_thread=False)
trace_db.execute("""CREATE TABLE IF NOT EXISTS spans (
    trace_id TEXT, span_id TEXT, parent_id TEXT, name TEXT, started TEXT,
    duration_ms INTEGER, status TEXT, lead_id TEXT,
    input TEXT, output TEXT, meta TEXT)""")
trace_db.execute("CREATE INDEX IF NOT EXISTS idx_trace ON spans(trace_id)")
trace_db.execute("CREATE INDEX IF NOT EXISTS idx_lead ON spans(lead_id)")

_ctx = contextvars.ContextVar("span_ctx", default=(None, None))   # (trace_id, parent_span)


class span:
    """A context manager: every step is wrapped in a span."""
    def __init__(self, name, lead_id=None, **meta):
        self.name, self.lead_id, self.meta = name, lead_id, meta
        self.input = self.output = None

    def __enter__(self):
        trace_id, parent = _ctx.get()
        self.trace_id = trace_id or uuid.uuid4().hex
        self.span_id, self.parent = uuid.uuid4().hex[:12], parent
        self.token = _ctx.set((self.trace_id, self.span_id))
        self.t0, self.started = time.monotonic(), dt.datetime.now(dt.timezone.utc).isoformat()
        return self

    def __exit__(self, exc_type, exc, tb):
        _ctx.reset(self.token)
        trace_db.execute(
            "INSERT INTO spans VALUES (?,?,?,?,?,?,?,?,?,?,?)",
            (self.trace_id, self.span_id, self.parent, self.name, self.started,
             int((time.monotonic() - self.t0) * 1000),
             "error" if exc else "ok", self.lead_id,
             json.dumps(self.input, default=str)[:20000],
             json.dumps(self.output, default=str)[:20000],
             json.dumps({**self.meta, "error": repr(exc) if exc else None}, default=str)))
        trace_db.commit()
        return False        # never swallow the exception


# --- Usage: wrap every step, not only model calls ---
def handle_outreach_traced(lead, campaign_id):
    with span("outreach", lead_id=lead["id"], campaign=campaign_id) as root:
        root.input = lead
        with span("collect_context", lead_id=lead["id"]) as s:
            s.output = ctx = collect_context(lead)                    # A7
        with span("recall_memory", lead_id=lead["id"]) as s:
            s.output = memory = recall(lead["id"])                    # A10
        with span("write_email", lead_id=lead["id"],
                  prompt_version=PROMPT_VERSION, model=MODELS["large"]) as s:
            s.input = {"context": ctx, "memory": memory}              # exactly what went to the model
            resp = build_email(lead, memory, ctx)                     # A12
            s.output = draft = next(b for b in resp.content if b.type == "tool_use").input
            s.meta["tokens"] = {"in": resp.usage.input_tokens, "out": resp.usage.output_tokens}
        root.output = {"subject": draft["subject"]}
        return draft


# --- Investigating a complaint: find the run by customer and read the chain ---
def explain(lead_id, date=None):
    rows = trace_db.execute(
        "SELECT trace_id, name, duration_ms, status, input, output, meta FROM spans "
        "WHERE lead_id = ? ORDER BY started DESC LIMIT 20", (lead_id,)).fetchall()
    for trace_id, name, ms, status, inp, out, meta in rows:
        print(f"[{status}] {name} · {ms} ms · {json.loads(meta)}")
        if name == "recall_memory":
            print("   facts in context:", json.loads(out))     # this is where "the conference" was
        if name == "write_email":
            print("   prompt version:", json.loads(meta).get("prompt_version"))


# --- Replay: same input, new prompt version ---
def replay(trace_id, prompt_version=None):
    row = trace_db.execute(
        "SELECT input, meta FROM spans WHERE trace_id=? AND name='write_email'",
        (trace_id,)).fetchone()
    saved_input, saved_meta = json.loads(row[0]), json.loads(row[1])
    version = prompt_version or saved_meta["prompt_version"]
    return regenerate(saved_input["context"], saved_input["memory"], version)


# --- A complaint becomes a golden-set case automatically ---
def promote_to_golden(trace_id, name, expectation):
    row = trace_db.execute("SELECT input FROM spans WHERE trace_id=? AND name='outreach'",
                           (trace_id,)).fetchone()
    case = {"name": name, "lead": json.loads(row[0]), "expect": expectation, "from_trace": trace_id}
    cases = json.load(open("checks/golden_set.json", encoding="utf-8"))
    cases.append(case)
    json.dump(cases, open("checks/golden_set.json", "w", encoding="utf-8"), indent=2)
```

How this changes complaint handling:

1. **`explain(lead_id)` shows the chain in seconds.** In our case the `recall_memory` span holds the fact "met at the conference" — and the question moves to where it came from, not to the prompt.
2. **The `write_email` span records exactly the context** that went to the model. Not an approximation — the real one.
3. **`replay(trace_id, "v4")`** checks whether a new prompt version fixes this specific complaint.
4. **`promote_to_golden`** turns the incident into a permanent case — exactly the mechanic described in A6.

**Assignment.** Take the last complaint or strange output from your agent and try to answer "which step is at fault" from your current logs. If you could not in ten minutes, you have just measured the cost of having no tracing.

---

## 📌 Remember

- Agents are non-deterministic: input/output logs are not enough, you need the whole decision chain.
- A trace is a tree of spans; a span records input, output, versions, metrics and the decision taken.
- Wrap every step, not only model calls: the culprit is often retrieval or memory.
- The recorded context must be exact, not approximate, or replay is meaningless.
- Replay with a new prompt version answers "does this fix address this specific complaint".
- Personal data in traces follows the same rules as in memory and is deleted along with it.

**Further reading:** the OpenTelemetry specification (the trace/span model); LLM tracing practices in LangSmith, Langfuse and Braintrust; and module A6 — a trace without a golden set fixes one case, together they fix a class.
