## 🏢 The situation

Datacore's research system now reaches into six MCP servers. Dasha likes the coverage but brings two observations you are expected to explain.

**Observation one.** "Sometimes it retells the contents of a website as if it were our internal document, complete with page numbers." You look at the tool list. Two entries:

```
analyze_content  — "Analyzes content and returns key findings."
analyze_document — "Analyzes a document and returns key findings."
```

The first is for web pages, the second for PDFs from the internal archive. Not even a human could tell them apart from those descriptions. The model picks almost at random.

It gets worse. `analyze_document` does three different things: pull out metrics, write a summary, and check a claim against a source. One name, three jobs, one vague output contract.

And right next to it, a third detail: the system prompt says "when working with documents, always clarify the details". The word "document" in that sentence pulls even web-page requests toward `analyze_document`, because the model catches the keyword before it reads the descriptions.

**Observation two.** "It hangs for ages and then says it could not do it." The logs show the same response from every tool for every kind of problem:

```
{"error": "Operation failed"}
```

The agent sees that and does the only thing it can: retries. Five times in a row. In three of those five cases the retry is pointless: the account has no access to the archive, and that will not change in a second or in an hour.

## 🎯 Your task

1. Rewrite the descriptions so tool selection stops being a lottery.
2. Split the catch-all `analyze_document` into tools with clear contracts.
3. Make errors structured, so the agent knows what to retry and what to explain to the customer.

## 📚 Theory

### The description is the selection interface

The domain's central claim: **tool descriptions are the primary mechanism LLMs use for tool selection**. Not the name, not the parameter schema — the description. Minimal descriptions lead to unreliable selection among similar tools.

What a description must contain:

- **purpose** — what the tool does and, crucially, what it does not do;
- **input format** — what exactly it accepts (a page URL? a document id? free text?);
- **example queries** — one or two typical ones;
- **edge cases** — what comes back when nothing is found;
- **the boundary with its neighbours** — "unlike `X`, use this when…".

And a point that is easy to miss: **the system prompt can override good descriptions**. The phrase "when working with documents, clarify the details" creates a keyword association. The exam asks for the skill of **reviewing system prompts for such wording** — so when diagnosing misrouting, look at the prompt, not only at the descriptions.

### An error is an interface too

Dasha's second observation is about the agent being unable to make a sensible decision because every error looks the same. The guide is direct: **uniform responses like "Operation failed" prevent the agent from making appropriate recovery decisions**.

The categories that must be distinguishable:

| Category | Examples | Retry? |
| --- | --- | --- |
| `transient` | timeout, service unavailable, 503 | yes, with a delay |
| `validation` | malformed id, missing required field | no — fix the input |
| `business` | policy violation, limit exceeded | no — explain to the customer |
| `permission` | no access to the archive | no — escalate or request access |

An MCP error response is built around the **`isError`** flag plus structured metadata:

```json
{
  "isError": true,
  "errorCategory": "permission",
  "isRetryable": false,
  "message": "No access to the legal document archive",
  "customerMessage": "This document is available to the legal team only."
}
```

The `isRetryable` field saves literal money: the agent stops spending five attempts on something that will not change. The `customerMessage` field exists for business errors — so the agent can explain the reason to a human in plain language instead of relaying a technical failure.

### Two fine distinctions

**Local recovery vs propagation.** A subagent fixes a transient error itself: retried, worked, moved on. What travels up to the coordinator is only **what could not be resolved locally** — together with the partial results and a note of what was attempted. Otherwise the coordinator receives a stream of noise and cannot tell a real problem from a network hiccup.

**An access failure vs a valid empty result.** These are different things, and confusing them is expensive:

```
{"isError": true, "errorCategory": "permission"}   ← we could not look
{"results": [], "total": 0}                        ← we looked, there is nothing
```

The first needs a decision (retry? escalate?); the second is a valid successful response, and the agent should calmly say "no matches found". A tool that returns an error for an empty result sends the agent hunting for a problem that does not exist.

## 💻 Practice

MCP tools with real descriptions and structured errors. Note the length of the descriptions — that is not verbosity, that is the interface.

```python
# pip install anthropic
import os, json, time, anthropic

client = anthropic.Anthropic(api_key=os.environ["ANTHROPIC_API_KEY"])
MODEL = "claude-sonnet-5"

TOOLS = [
    {
        "name": "extract_web_results",
        "description": (
            "Extracts facts from a PUBLIC WEB PAGE given its URL. "
            "Input: a full http(s) page address. Output: a list of "
            "{claim, quote, source_url} objects. "
            "Example: extract_web_results(url='https://example.com/pricing') → a competitor's tiers. "
            "If the page is unreachable it returns isError with a category. If no facts are found "
            "it returns an empty results list, which is NOT an error. "
            "Unlike extract_data_points, it only works with web pages and has no access "
            "to the company's internal archive."
        ),
        "input_schema": {"type": "object", "properties": {"url": {"type": "string"}}, "required": ["url"]},
    },
    {
        "name": "extract_data_points",
        "description": (
            "Extracts numeric metrics from an INTERNAL ARCHIVE DOCUMENT by its identifier. "
            "Input: a doc_id of the form DOC-XXXX. Output: a list of {metric, value, unit, page}. "
            "Example: extract_data_points(doc_id='DOC-1042') → quarterly revenue with page numbers. "
            "Use it when you need NUMBERS from a document. "
            "To retell a document use summarize_content; to check a specific claim use "
            "verify_claim_against_source; for web pages use extract_web_results."
        ),
        "input_schema": {"type": "object", "properties": {"doc_id": {"type": "string"}}, "required": ["doc_id"]},
    },
    {
        "name": "summarize_content",
        "description": (
            "Returns a summary of an internal document by doc_id. "
            "Output: {summary, key_topics[]}. It does not extract numbers — use extract_data_points for that."
        ),
        "input_schema": {"type": "object", "properties": {"doc_id": {"type": "string"}}, "required": ["doc_id"]},
    },
    {
        "name": "verify_claim_against_source",
        "description": (
            "Checks a SPECIFIC claim against a specific document. "
            "Input: claim (the statement text) and doc_id. "
            "Output: {verdict: supported|contradicted|not_found, evidence, page}. "
            "Use it for fact-checking, not for gathering new data."
        ),
        "input_schema": {"type": "object",
                         "properties": {"claim": {"type": "string"}, "doc_id": {"type": "string"}},
                         "required": ["claim", "doc_id"]},
    },
]

def mcp_error(category: str, message: str, retryable: bool, customer: str | None = None):
    err = {"isError": True, "errorCategory": category, "isRetryable": retryable, "message": message}
    if customer:
        err["customerMessage"] = customer
    return err

CALLS = {"extract_data_points": 0}

def run_tool(name, args):
    if name == "extract_web_results":
        if not args["url"].startswith("http"):
            return mcp_error("validation", "url must start with http(s)://", retryable=False)
        return {"results": []}          # a valid empty result, not an error

    if name == "extract_data_points":
        CALLS["extract_data_points"] += 1
        if args["doc_id"] == "DOC-9000":
            return mcp_error("permission", "No access to the legal document archive", retryable=False,
                             customer="This document is available to the legal team only.")
        if CALLS["extract_data_points"] == 1:
            return mcp_error("transient", "Archive timeout (503)", retryable=True)
        return {"results": [{"metric": "Q3 revenue", "value": 12.4, "unit": "M", "page": 12}]}

    if name in ("summarize_content", "verify_claim_against_source"):
        return {"summary": "…", "key_topics": ["pricing", "market"]}
    return mcp_error("validation", f"unknown tool {name}", retryable=False)

def agent(question: str, max_iterations: int = 12):
    messages = [{"role": "user", "content": question}]
    system = ("You are a research agent. Retry transient errors once. "
              "Never retry errors with isRetryable=false: explain the reason, using customerMessage "
              "when it is present. An empty results list is a valid 'nothing found' answer.")
    for _ in range(max_iterations):
        resp = client.messages.create(model=MODEL, max_tokens=1024, system=system,
                                      tools=TOOLS, messages=messages)
        if resp.stop_reason != "tool_use":
            return "".join(b.text for b in resp.content if b.type == "text")
        messages.append({"role": "assistant", "content": resp.content})
        results = []
        for b in resp.content:
            if b.type != "tool_use":
                continue
            out = run_tool(b.name, b.input)
            print(f"    → {b.name}({b.input}) = {json.dumps(out)[:100]}")
            results.append({"type": "tool_result", "tool_use_id": b.id,
                            "content": json.dumps(out),
                            "is_error": bool(out.get("isError"))})
        messages.append({"role": "user", "content": results})
    return None

if __name__ == "__main__":
    print(agent("Get the Q3 revenue from document DOC-1042."))
    print("\n---\n")
    print(agent("Get the metrics from document DOC-9000."))
```

**Assignment.**

1. Replace the descriptions with one-liners ("Analyzes content", "Analyzes a document") and run ten mixed queries about web pages and documents. Measure the misrouting rate.
2. Add "when working with documents, always clarify the details" to the system prompt and watch web-page requests start going to the document tools. That is the keyword trap from the guide.
3. Strip the structure from the errors — return `{"error": "Operation failed"}` in every case — and count how many times the agent retries `DOC-9000`, which is permanently inaccessible.

## 🎯 On the exam

- **Objective 2.1**: descriptions as the selection mechanism, what belongs in them, renaming to remove overlap, splitting a catch-all tool, the influence of system prompt keywords.
- **Objective 2.2**: the `isError` flag, the four error categories, `isRetryable`, `customerMessage` for business errors, local recovery vs propagation to the coordinator, access failure vs valid empty result.
- Scenarios: **Multi-Agent Research System** and **Customer Support Resolution Agent** — both are built on MCP tools.
- Trap on 2.1: "add a rule to the system prompt about which tool to use when". It sometimes helps, but the exam expects the **descriptions** to be fixed — a prompt should not compensate for a bad interface.
- Trap on 2.2: "add exponential retries for all errors". Retries only help transient failures; structured metadata exists precisely so attempts are not wasted.
- Keep the empty-result case in mind: a tool that errors on "nothing found" generates pointless retries.

---

## 📌 Remember

- The model selects a tool from its description. The description is the interface: purpose, input format, examples, edge cases, and the boundary with similar tools.
- Overlapping descriptions are fixed by renaming and sharpening; a catch-all tool is fixed by splitting it into purpose-specific tools with clear contracts.
- A keyword in the system prompt can override a good description. When diagnosing misrouting, check the prompt too.
- An error comes back structured: `isError`, a category (`transient`/`validation`/`business`/`permission`), `isRetryable`, a readable message, and a `customerMessage` where the answer reaches a human.
- Transient failures are fixed locally; only unresolved ones propagate — with partial results and a note of what was attempted.
- An empty result is not an error. It is a successful "no matches".
