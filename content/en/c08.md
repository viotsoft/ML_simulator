## 🏢 The situation

You fixed the descriptions in C7 and routing became predictable. Two weeks later it degrades again — for a different reason.

In the meantime the team wired up three more MCP servers. There are now **eighteen** tools, handed to all four subagents as one identical list, "so nobody has to wait for anyone". The result:

- the synthesis subagent, which by definition should gather no new data, reaches for web search and brings back facts with no sources;
- the document subagent calls `fetch_url` with a document id instead of an address and gets a validation error;
- a simple request now takes three extra calls on average — the model shops around among similar tools.

In parallel, a configuration mess surfaces. Kostya added a Jira server for himself; Dasha wants the same one and it does not work for her. You look: Kostya put the server in his personal config and pasted the token in as plain text. Another server, a shared one, sits in the repository — with its key in the clear, which now needs rotating.

And one last thing: the agent keeps searching the repo with `Grep` even though a code MCP server with indexed search is connected and does the job better. Its description reads "Search code."

## 🎯 Your task

1. Distribute tools by role and understand why eighteen is worse than five.
2. Get `tool_choice` straight: when `auto`, when `any`, when a forced call.
3. Split MCP configuration into project and personal, and get the secrets out of the repository.

## 📚 Theory

### Too many tools is not "a rich selection"

The principle from the guide: **giving an agent access to too many tools (for example 18 instead of 4–5) degrades tool selection reliability**, because decision complexity grows. And separately: agents holding tools outside their specialisation tend to misuse them — exactly like your synthesiser with web search.

The moves the exam tests:

- **restrict each subagent's set** to its role;
- **replace a generic tool with a constrained one**: instead of `fetch_url`, which pulls anything from anywhere, `load_document`, which validates that the URL points at a document;
- **provide a narrow cross-role tool for a high-frequency need**: `verify_fact` for the synthesiser, so every check does not go through the coordinator, while complex cases still do.

### tool_choice: three modes

| Value | What it does | When you need it |
| --- | --- | --- |
| `"auto"` | the model decides whether to call a tool | normal agent operation |
| `"any"` | the model must call some tool | when chatter instead of action is unacceptable |
| `{"type": "tool", "name": "..."}` | this specific tool is called | when the first step is fixed |

The guide's example of forced selection: make `extract_metadata` run **first**, before the enrichment tools, and handle subsequent steps in follow-up turns. Forcing sets the first step — not the whole route.

`"any"` solves a different problem: the model answering with text instead of calling a tool. If your step's contract is "there must be a call", `"any"` guarantees it.

### MCP configuration: project vs personal

Two scopes, and confusing them causes exactly the mess Kostya and Dasha hit:

- **`.mcp.json` in the project** — shared team servers. Lives in the repository, applies to everyone working on it.
- **`~/.claude.json`, user scope** — personal and experimental servers. Does not affect colleagues.

Secrets do not go into the project file. That is what **environment variable expansion** is for:

```json
{
  "mcpServers": {
    "jira": {
      "command": "npx",
      "args": ["-y", "@company/jira-mcp"],
      "env": { "JIRA_TOKEN": "${JIRA_TOKEN}" }
    }
  }
}
```

The file is committed; the token is not. Each developer keeps `JIRA_TOKEN` in their own environment.

Three more facts from this objective:

- **Tools from all configured servers are discovered at connection time and available simultaneously.** That is where the list explosion comes from — three servers connected, eighteen tools appear.
- **MCP resources** are a mechanism for exposing content catalogs (issue summaries, documentation hierarchies, database schemas) so the agent does not burn calls on exploration. A resource answers "what is here at all"; a tool answers "do this".
- **For standard integrations use an existing community server** (Jira being the canonical case) and reserve custom servers for team-specific workflows.

And the cause of that last complaint: the agent prefers `Grep` to your indexed search because the MCP tool's description is two words long. The guide asks you to **enhance MCP tool descriptions**, explaining capabilities and outputs in detail — otherwise built-in tools win the selection simply by being clearer.

## 💻 Practice

Role scoping, a forced first step, and a project config with no secrets.

```python
# pip install anthropic
import os, json, anthropic

client = anthropic.Anthropic(api_key=os.environ["ANTHROPIC_API_KEY"])
MODEL = "claude-sonnet-5"

ALL_TOOLS = {
    "search_web": {"name": "search_web", "description":
        "Searches the public web for a query. Returns a list of {title, url, snippet}.",
        "input_schema": {"type": "object", "properties": {"query": {"type": "string"}}, "required": ["query"]}},
    "load_document": {"name": "load_document", "description":
        "Loads an archive document by URL. Validates that the address points at a document "
        "(pdf/docx) on the internal domain; arbitrary addresses are rejected with a validation error. "
        "The constrained replacement for a generic fetch_url.",
        "input_schema": {"type": "object", "properties": {"url": {"type": "string"}}, "required": ["url"]}},
    "extract_metadata": {"name": "extract_metadata", "description":
        "Extracts document metadata: type, date, author, page count, language. "
        "Call it FIRST: the enrichment tools rely on its output.",
        "input_schema": {"type": "object", "properties": {"doc_id": {"type": "string"}}, "required": ["doc_id"]}},
    "enrich_entities": {"name": "enrich_entities", "description":
        "Enriches a document with entities (companies, amounts, dates). Requires document metadata.",
        "input_schema": {"type": "object", "properties": {"doc_id": {"type": "string"}}, "required": ["doc_id"]}},
    "verify_fact": {"name": "verify_fact", "description":
        "Checks ONE claim against sources already collected. A narrow cross-role tool: available to "
        "the synthesiser for frequent simple checks. Complex investigations go through the coordinator.",
        "input_schema": {"type": "object", "properties": {"claim": {"type": "string"}}, "required": ["claim"]}},
}

# Each role gets only its own tools (4–5), plus one cross-role tool where it is genuinely needed
ROLE_TOOLS = {
    "web":    ["search_web"],
    "docs":   ["load_document", "extract_metadata", "enrich_entities"],
    "synth":  ["verify_fact"],          # NOT search_web: the synthesiser gathers no new data
    "report": [],
}

def tools_for(role: str):
    return [ALL_TOOLS[n] for n in ROLE_TOOLS[role]]

def call(role: str, prompt: str, tool_choice=None, max_tokens: int = 1024):
    kwargs = {"model": MODEL, "max_tokens": max_tokens,
              "messages": [{"role": "user", "content": prompt}]}
    tools = tools_for(role)
    if tools:
        kwargs["tools"] = tools
        if tool_choice:
            kwargs["tool_choice"] = tool_choice
    resp = client.messages.create(**kwargs)
    return resp

if __name__ == "__main__":
    # 1. auto — the normal mode: the model decides
    r = call("docs", "Analyse document DOC-1042 and tell me what is in it.")
    print("auto      →", [b.name for b in r.content if b.type == "tool_use"] or "text, no call")

    # 2. any — guarantee a call rather than a discussion
    r = call("docs", "Analyse document DOC-1042 and tell me what is in it.", tool_choice={"type": "any"})
    print("any       →", [b.name for b in r.content if b.type == "tool_use"])

    # 3. forced first step: metadata first, enrichment on the following turn
    r = call("docs", "Enrich document DOC-1042 with entities.",
             tool_choice={"type": "tool", "name": "extract_metadata"})
    print("forced    →", [b.name for b in r.content if b.type == "tool_use"])

    # 4. the synthesiser physically cannot wander into web search
    r = call("synth", "Verify the claim '40% market share' and search the web if you need to.")
    print("synth     →", [b.name for b in r.content if b.type == "tool_use"] or "text, no call")
```

## 🎯 On the exam

- **Objective 2.3**: selection degradation at 18 tools instead of 4–5, misuse of out-of-specialisation tools, role scoping, replacing a generic tool with a constrained one, a narrow cross-role tool, the three `tool_choice` modes.
- **Objective 2.4**: `.mcp.json` vs `~/.claude.json`, `${VAR}` expansion, simultaneous availability of all servers' tools, MCP resources as content catalogs, enhancing MCP tool descriptions, community servers over custom ones.
- Scenarios: **Developer Productivity with Claude**, **Multi-Agent Research System**, **Code Generation with Claude Code**.
- Trap on 2.3: "give every agent every tool so nobody is blocked". That is precisely what the guide names as the cause of unreliable selection.
- Trap on `tool_choice`: forced selection sets the **first** step, not the whole route. "Force the right tool at every step" is no longer an agent.
- Trap on 2.4: "put the token in .mcp.json, the repository is private anyway". The expected answer is environment variable expansion.
- If a question has the agent preferring a built-in tool over your MCP one, the cause is almost always a thin MCP tool description.

## 📌 Remember

- Many tools degrade selection. The guide's reference point is 4–5 per role, not one shared list.
- A tool outside an agent's specialisation will be misused. The synthesiser does not need web search.
- Replace a generic tool with a constrained one that validates its input; for a frequent simple need give a narrow cross-role tool and leave complex cases to the coordinator.
- `tool_choice`: `auto` normally, `any` when you need a call rather than text, forced selection to pin the first step.
- `.mcp.json` for team servers in the repository, `~/.claude.json` for personal ones. Secrets only via `${VAR}`.
- Tools from all connected servers are available simultaneously; MCP resources expose the catalog and save exploratory calls.
- A thin MCP tool description loses to the built-ins: the description is still the selection interface.
