# Module A2. Your first agent: a draft email from one CRM row

> **Level:** Junior AI · **Time:** ~50 minutes · **Format:** situation → theory → practice → quiz

---

## 🏢 The situation

The Design Doc is signed. Marina gave you two weeks for the first slice: **20 draft emails a day, a human sends them**.

Igor, Head of Sales, brings a CRM export — 340 rows. Company, industry, role, date of the last event. He looks at you with suspicion:

> "My SDR spends 12 minutes on an email. If your thing writes garbage, I'll spend more time fixing drafts than writing them myself. Also: our CRM has rows where the job title is 'n/a' and the company is just 'LLC'. What then?"

A good question. It is the one that separates a demo from a system: **a demo works on the pretty row, a system works on all 340**.

## 🎯 Your task

1. Build an agent that turns one CRM row into a draft email.
2. Get back **structure**, not prose — something the next stage of the pipeline can consume.
3. Survive bad data, network failures and model "creativity" without killing the whole batch.

---

## 📚 Theory

### What makes an LLM an agent rather than a text generator

Three things a plain prompt does not have:

1. **Tools** — the model can call your function (search the CRM, verify a domain) and see the result.
2. **A loop** — it sees that result and decides what to do next.
3. **An output contract** — the result arrives in a format your code reads, not a human.

Today we build the simplest version: one call, a hard output contract, no loop. That is not a "fake agent" — it is the correct first step. We add the loop in A7, once there is something worth looping over.

### Structured output: a contract instead of hope

Free-form text cannot be passed down a pipeline. "Here is the email, hopefully the subject is on line one" is not an integration.

| Approach | What happens when it breaks | Production-ready |
| --- | --- | --- |
| Ask for text, parse with a regex | The model rephrases — your parser breaks silently | No |
| Ask for JSON in the prompt | Sometimes arrives with "Sure! Here is the JSON:" | With validation — yes |
| Tool calling with a schema | The model must fill in the schema fields | Yes |

**Tool calling** is not only "go call an API". It is also how you force the model to answer by schema: you describe a function `save_draft(subject, body, self_check)`, the model "calls" it, and you simply read the arguments. The provider validates the schema, not your regex.

### Bad data is the norm, not the exception

Igor is right about "n/a" and "LLC". The rule: **filter before the model, not after**. Checking required fields costs a fraction of a millisecond; a model call costs seconds and money. A row with no role and no trigger cannot be personalized — skipping it is more honest than producing "Hello, n/a!".

### Retries: what to repeat and what not to

| Error | Retry? | Why |
| --- | --- | --- |
| Timeout, 429, 5xx | Yes, with exponential backoff | A temporary problem on their side |
| The model returned an invalid schema | Yes, once | It happens; twice is a symptom of the prompt |
| 401, wrong key | No | A retry changes nothing |
| The row failed validation | No | Data does not improve by repetition |

And most importantly: one failed lead must not take down a batch of 340. Catch errors at the level of a single unit of work.

## 💻 Practice

```python
# pip install anthropic
import os, time, json, anthropic

client = anthropic.Anthropic(api_key=os.environ["ANTHROPIC_API_KEY"])
MODEL = "claude-sonnet-5"

# The output contract: the model must fill in these fields
DRAFT_TOOL = {
    "name": "save_draft",
    "description": "Save a draft email for a lead",
    "input_schema": {
        "type": "object",
        "properties": {
            "subject": {"type": "string", "description": "Subject, up to 60 characters"},
            "body": {"type": "string", "description": "Body, up to 120 words"},
            "personalization": {"type": "string", "description": "The specific reason we are writing to them"},
            "self_check": {
                "type": "object",
                "properties": {
                    "invented_facts": {"type": "boolean"},
                    "mentions_price": {"type": "boolean"},
                    "has_question": {"type": "boolean"},
                },
                "required": ["invented_facts", "mentions_price", "has_question"],
            },
        },
        "required": ["subject", "body", "personalization", "self_check"],
    },
}

SYSTEM = """You write a first cold email on behalf of Datacore — a platform for teams
shipping ML into their product. Always call the save_draft tool.

NEVER: quote prices or terms; invent facts about the recipient; exceed 120 words.
REQUIRED: one specific reason why you are writing to them, and one question at the end."""


def usable(lead):
    """Filter before the model: without a role and a trigger there is nothing to personalize."""
    if not lead.get("company") or len(lead["company"]) < 3:
        return False, "no company name"
    if not lead.get("role") or lead["role"].lower() in {"n/a", "-", "unknown"}:
        return False, "no job title"
    if not lead.get("trigger"):
        return False, "no trigger event to hook on"
    return True, None


def draft_for(lead, attempts=3):
    for attempt in range(1, attempts + 1):
        try:
            resp = client.messages.create(
                model=MODEL, max_tokens=800, temperature=0.7, system=SYSTEM,
                tools=[DRAFT_TOOL], tool_choice={"type": "tool", "name": "save_draft"},
                messages=[{"role": "user", "content": json.dumps(lead)}],
            )
            block = next(b for b in resp.content if b.type == "tool_use")
            return block.input, resp.usage
        except anthropic.APIStatusError as e:
            if e.status_code in (429, 500, 502, 503, 529) and attempt < attempts:
                time.sleep(2 ** attempt)   # exponential backoff
                continue
            raise
        except StopIteration:
            if attempt < attempts:
                continue               # the model skipped the tool — try once more
            raise RuntimeError("the model returned no draft matching the schema")


LEADS = [
    {"company": "NordFin", "industry": "fintech", "role": "Head of Data",
     "trigger": "posted an ML engineer job opening"},
    {"company": "LLC", "industry": "", "role": "n/a", "trigger": ""},   # Igor's junk row
]

ok_count = skipped = failed = 0
for lead in LEADS:
    fine, why = usable(lead)
    if not fine:
        skipped += 1
        print(f"— skipped {lead.get('company')!r}: {why}")
        continue
    try:
        draft, usage = draft_for(lead)
    except Exception as e:                 # one bad lead does not kill the batch
        failed += 1
        print(f"✗ {lead['company']}: {e}")
        continue
    c = draft["self_check"]
    if c["invented_facts"] or c["mentions_price"] or not c["has_question"]:
        failed += 1
        print(f"✗ {lead['company']}: failed self-check {c}")
        continue
    ok_count += 1
    print(f"✓ {lead['company']} · {draft['subject']}")
    print(f"  hook: {draft['personalization']}")

print(f"\nResult: ready {ok_count}, skipped {skipped}, rejected {failed}")
```

What matters here:

1. **`tool_choice` forces the tool call.** We do not parse text or hope for JSON — the provider validates the schema.
2. **Validation before the model.** Igor's junk row never reaches a paid call and never becomes "Hello, n/a".
3. **Only transient errors are retried**, with growing backoff. A schema error is retried once — beyond that it is a prompt problem, not bad luck.
4. **Ready / skipped / rejected counters.** This is the first version of your quality metric: if "rejected" grows, blame the prompt; if "skipped" grows, blame the CRM data.

**Assignment.** Run 10 rows from your own export (or invent them). Count how many were filtered out by validation and how many failed the self-check. Then answer Igor's question with a number: out of 20 emails, how many will he have to rewrite by hand?

---

## 📌 Remember

- A first agent is one call with a hard output contract, not an autonomous loop.
- Asking for JSON in the prompt works, but forcing a schema-backed tool call is more reliable.
- Temperature follows the cost of variety: 0 where code reads the output, higher where a human picks the best of several.
- Filter bad rows before calling the model: it is cheaper, faster and more honest.
- Retry only transient errors. A wrong key and bad data are not cured by repetition.
- A failure on one lead must not kill the batch. The unit of work is the unit of failure.
