## 📚 Theory

### Three levels of checks

| Level | What it checks | Cost | When to run |
| --- | --- | --- | --- |
| Deterministic checks | Length, banned phrases, presence of a question, schema | Free, milliseconds | On every response in production |
| LLM-as-judge | Tone, relevance, grounding in facts | Cents, seconds | On every prompt change |
| A human | Disputed cases, calibrating the judge | Expensive, minutes | Weekly, on a sample |

The beginner's mistake is jumping straight to the third level ("let's show Igor twenty emails") or getting stuck on the first ("length is fine, so we're fine"). What works is the combination: code catches the crude, the judge catches the qualitative, the human calibrates the judge.

### The golden set: what it is and where it comes from

It is a set of inputs with **reference properties** of the output. Not a reference text (no two emails are the same), but properties: must mention the lead's trigger, must not promise a price, must end with a question.

Where to get it:

1. **From real data** — 30–50 CRM rows of varying quality, junk rows included.
2. **From incidents** — every "that email was wrong" becomes a permanent case. This is the most valuable part of the set.
3. **From edge cases** — a very long company name, a missing trigger, an exotic industry.

Fifty cases are enough to catch regressions. You do not need a thousand.

Two more traps: judges tend to favour longer answers, and answers produced by the same model that is judging. Both are mitigated by randomized pairwise comparison and an explicit criterion.

### What to measure in our case

- **Grounding** (share of claims with a source) — deterministic, from A5.
- **Prohibitions honored** (no price, nothing invented) — code plus judge.
- **Personalization** (the hook ties to the lead's trigger) — judge.
- **The product proxy metric** — share of drafts Igor sent without edits. The only real number, but it arrives with a delay.

Offline metrics exist so you do not wait a week. The product metric decides who was right.

## 💻 Practice

```python
# pip install anthropic
import os, json, random, statistics, anthropic

client = anthropic.Anthropic(api_key=os.environ["ANTHROPIC_API_KEY"])
JUDGE_MODEL = "claude-sonnet-5"

JUDGE_TOOL = {
    "name": "verdict",
    "description": "A verdict on a single criterion",
    "input_schema": {
        "type": "object",
        "properties": {
            "answer": {"type": "string", "enum": ["yes", "no", "unclear"]},
            "evidence": {"type": "string", "description": "A quote from the email supporting the verdict"},
        },
        "required": ["answer", "evidence"],
    },
}

CRITERIA = {
    "grounded": "Is every product claim supported by the FACTS block? "
                "Answer no if there is even one claim absent from the facts.",
    "personalized": "Does the email's hook rely on a specific event from the lead data "
                    "(rather than generic industry talk)?",
    "no_price": "Is the email free of prices, discounts and delivery dates?",
}

def judge(criterion_key, email, context):
    resp = client.messages.create(
        model=JUDGE_MODEL, max_tokens=300, temperature=0,
        system="You are a strict reviewer. Answer on one criterion only. Always call verdict. "
               "If you are unsure, say unclear — that is not a failure.",
        tools=[JUDGE_TOOL], tool_choice={"type": "tool", "name": "verdict"},
        messages=[{"role": "user", "content":
                   f"CRITERION: {CRITERIA[criterion_key]}\n\nCONTEXT:\n{context}\n\nEMAIL:\n{email}"}],
    )
    return next(b for b in resp.content if b.type == "tool_use").input


def evaluate(golden_set, generate_fn):
    """Run the set: deterministic checks plus a judge per criterion."""
    scores = {k: [] for k in CRITERIA}
    hard_fails = []
    for case in golden_set:
        draft, ctx = generate_fn(case["lead"])
        if draft is None:
            hard_fails.append((case["name"], "generation refused"))
            continue
        problems = hard_checks(draft, case["lead"])       # from A4
        if problems:
            hard_fails.append((case["name"], ", ".join(problems)))
        for key in CRITERIA:
            v = judge(key, draft["body"], ctx)
            scores[key].append(1 if v["answer"] == "yes" else 0)
    report = {k: round(statistics.mean(v), 3) if v else None for k, v in scores.items()}
    return report, hard_fails


# --- Calibrating the judge: without this the numbers cannot be trusted ---
def calibrate(labeled):
    """labeled: [{email, context, criterion, human: 'yes'|'no'}] — 20 hand-labeled cases."""
    agree = sum(1 for x in labeled
                if judge(x["criterion"], x["email"], x["context"])["answer"] == x["human"])
    rate = agree / len(labeled)
    print(f"judge–human agreement: {rate:.0%}")
    if rate < 0.8:
        print("  ⚠ the judge is unreliable — sharpen the criterion wording before using it")
    return rate


if __name__ == "__main__":
    golden = json.load(open("checks/golden_set.json", encoding="utf-8"))
    report, fails = evaluate(golden, write_email)      # write_email from A5
    print("Metrics:", report)
    print("Hard failures:", len(fails))
    for name, why in fails[:5]:
        print(f"  ✗ {name}: {why}")
```

How to use this:

1. **Before every change** to a prompt or model — run the golden set. Record the numbers next to the prompt version.
2. **Compare versions** as numbers, not feelings: "grounded 0.82 → 0.94, personalized 0.71 → 0.69". You see both the gain and its price.
3. **Calibrate the judge** monthly and after every change of the judge model.
4. **Incident → case.** Every bad email from Igor joins the set with a name. The set grows with your understanding of the product.

**Assignment.** Build a golden set of 20 cases (10 ordinary, 5 edge, 5 from real complaints). Run the current version and record the numbers. Then break the prompt on purpose — remove the line banning prices — and confirm the metric caught it. If it did not, your set is not working yet.

## 📌 Remember

- "Feels better" is not a result. A number on a fixed set is.
- A golden set fixes output properties, not reference text. Fifty cases are enough.
- Every incident becomes a permanent case — that is how the set becomes the team's memory.
- An LLM judge works under four conditions: one criterion, a short scale, pairwise comparison, calibration.
- An uncalibrated judge measures noise. Measure agreement with a human before trusting the numbers.
- Offline metrics buy speed, the product metric decides correctness. You need both.

**Further reading:** papers on LLM-as-a-judge and its systematic biases (position bias, length bias); ML track module 6 on why a single metric lies; and eval-set practices in OpenAI Evals and Braintrust.
