# Module A12. The $12,000 invoice

> **Level:** Middle AI · **Time:** ~50 minutes · **Format:** situation → theory → practice → quiz

---

## 🏢 The situation

Victor, the CFO, forwards the model provider's invoice with one line: "Is this for one month?"

**$12,480.** In January it was $900.

You dig in and find not one cause but four:

1. The content factory (A8) makes four calls per article, and the editor and fact-checker each receive **the entire text** every time.
2. Customer memory (A10) started going into emails — small on its own, but it rides along on every call.
3. Someone set the largest model everywhere, including inbox triage, where the small one would do.
4. The same RAG documentation flies into context on each of 3000 emails.

Victor is not against spending. He is against nobody being able to name the price in advance: "Tell me the cost of one email and one article. I'll work out what we can afford from there."

## 🎯 Your task

1. Learn to compute cost per unit of work instead of reading the invoice at month's end.
2. Cut it several times over without losing quality — with four techniques.
3. Set budgets so that an invoice like this becomes impossible.

### Routing: not every task needs the large model

A simple rule: **the stricter the output contract, the smaller the model you need**. Classification into a closed enum (A3), field extraction, a short summary — small-model work. Writing an email, planning an article, investigating an incident — large-model work.

How to choose honestly: run both models on the golden set from A6. If the small one loses 1% of quality and costs five times less, the choice is obvious. If it loses 15%, do not economize.

A useful pattern is **escalation**: the small model answers, and if its confidence falls below a threshold, the task goes to the large one. Expensive calls are spent only on hard cases.

### Prefix caching: the most underrated technique

Your system prompt with examples and the documentation chunks are identical on each of 3000 calls. Providers let you cache that **prefix**: it is billed at a reduced rate on repeat requests.

The condition is a stable beginning of the request. Hence the assembly order:

```
[system + examples + shared documentation]   ← stable, cached
[customer memory]                            ← varies per customer
[this specific lead's data]                  ← varies every time
```

Put anything variable first and the cache never engages. That is the most common mistake in this topic.

### What not to economize on

- **Checks.** A fact-checker is cheaper than one email about "1C integration".
- **Refusals.** Refusing to generate is the cheapest call there is.
- **Evals.** A golden-set run costs pennies against a week of working blind.

## 💻 Practice

```python
import os, json, anthropic

client = anthropic.Anthropic(api_key=os.environ["ANTHROPIC_API_KEY"])

# Price per million tokens — put in the current numbers from your provider's price list
PRICING = {
    "small": {"in": 0.80, "out": 4.00},
    "large": {"in": 3.00, "out": 15.00},
}
MODELS = {"small": "claude-haiku-4-5-20251001", "large": "claude-sonnet-5"}

# Routing: a strict output contract → the small model
TASK_TIER = {
    "triage": "small",        # enum classification (A3)
    "extract_facts": "small", # field extraction (A10)
    "summarize": "small",
    "plan_article": "large",  # reasoning
    "write_email": "large",
    "factcheck": "large",     # the cost of a mistake is high — no savings here
}

spend = {"in": 0, "out": 0, "cached": 0, "calls": 0}

def call(task, system_blocks, user, tools=None, **kw):
    """system_blocks: [(text, cacheable?)] — the stable part comes first."""
    tier = TASK_TIER[task]
    system = []
    for text, cacheable in system_blocks:
        block = {"type": "text", "text": text}
        if cacheable:
            block["cache_control"] = {"type": "ephemeral"}   # cache the stable prefix
        system.append(block)

    resp = client.messages.create(
        model=MODELS[tier], system=system,
        messages=[{"role": "user", "content": user}],
        tools=tools or [], **kw)

    u = resp.usage
    spend["calls"] += 1
    spend["in"] += u.input_tokens * PRICING[tier]["in"] / 1e6
    spend["out"] += u.output_tokens * PRICING[tier]["out"] / 1e6
    spend["cached"] += getattr(u, "cache_read_input_tokens", 0)
    return resp


# --- Escalation: the expensive model only for hard cases ---
def triage_with_escalation(email_text):
    r = call("triage", [(TRIAGE_SYSTEM, True)], email_text,
             tools=[TRIAGE_TOOL], tool_choice={"type": "tool", "name": "triage"},
             max_tokens=400, temperature=0)
    result = next(b for b in r.content if b.type == "tool_use").input
    if result["confidence"] >= 0.8:
        return result, "small"
    # not confident — ask the large model
    TASK_TIER["triage"] = "large"
    try:
        r = call("triage", [(TRIAGE_SYSTEM, True)], email_text,
                 tools=[TRIAGE_TOOL], tool_choice={"type": "tool", "name": "triage"},
                 max_tokens=400, temperature=0)
        return next(b for b in r.content if b.type == "tool_use").input, "large (escalated)"
    finally:
        TASK_TIER["triage"] = "small"


# --- Budget: the hard fuse against a $12,000 invoice ---
class Budget:
    def __init__(self, daily_usd):
        self.limit = daily_usd
        self.spent = 0.0
    def check(self, estimated):
        if self.spent + estimated > self.limit:
            raise RuntimeError(f"daily budget exhausted: {self.spent:.2f} of {self.limit}")
    def add(self, actual):
        self.spent += actual

budget = Budget(daily_usd=40)

def cost_per_unit():
    """The answer for Victor: the cost of one unit of work."""
    return {
        "per_email": round((spend["in"] + spend["out"]) / max(spend["calls"], 1), 4),
        "total_spent": round(spend["in"] + spend["out"], 2),
        "tokens_read_from_cache": spend["cached"],
    }


# --- Assembling context in the right order ---
def build_email(lead, memory, docs):
    return call(
        "write_email",
        system_blocks=[
            (OUTREACH_SYSTEM + "\n\n" + docs, True),      # stable → cached
        ],
        user=(f"CUSTOMER MEMORY:\n{json.dumps(memory)}\n\n"
              f"LEAD:\n{json.dumps(lead)}"),              # variable → after the cache
        tools=[DRAFT_TOOL], tool_choice={"type": "tool", "name": "save_draft"},
        max_tokens=800, temperature=0.7)
```

What each technique bought us:

1. **Routing.** Triaging 180 inbound emails a day moved to the small model — about 70% off that task with no quality loss (verified on the golden set).
2. **Prefix caching.** The documentation and system prompt stopped being billed 3000 times a day.
3. **Context trimming.** The editor in the content factory receives a section, not the whole article; memory is eight facts, not the full history.
4. **Budget.** A daily cap turns "a surprise at month's end" into an understandable error today.

## 📌 Remember

- Cost is measured per unit of work, not from the invoice at month's end.
- Model routing is the first lever: the stricter the output contract, the smaller the model you need.
- Prefix caching only works with a stable request opening: immutable content first, variable content after.
- Escalation delivers large-model quality at small-model prices for most cases.
- Never economize on checks, refusals and evals — they are cheaper than the consequences.
- A daily budget is a fuse: it turns a future surprise invoice into a clear error today.
