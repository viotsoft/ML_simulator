## 🏢 The situation

In module C4 you closed the compliance gap with a prerequisite gate. Viktor is happy, but Kostya has a new complaint, and it is a strange one:

> "The agent is confused about time. It tells customers 'your order was delivered yesterday' when it was delivered three weeks ago. And the other way round. About one conversation in ten."

You look at where the agent gets its dates. The tools come from three different MCP servers, each written by a different team in a different year:

```
billing-mcp    → {"paid_at": 1793491200}                    Unix timestamp
orders-mcp     → {"delivered_at": "2026-08-14T09:20:00Z"}   ISO 8601
legacy-crm-mcp → {"contact_date": "14/08/26", "status": 3}  DD/MM/YY + numeric code
```

Three date formats in one conversation. Plus `status: 3`, which means "delivered" — but only the legacy CRM knows that. The model parses this as best it can and gets it wrong once in ten conversations.

Kostya suggests describing all the formats in the system prompt. You already know from C4 how probabilistic solutions to deterministic problems end.

A second issue surfaces too: you wired that refund gate straight into the support agent's loop. Now the same limit is needed for the research agent, which can order paid reports, and for the internal developer tool. Copying an `if` into three places is a bad idea.

## 🎯 Your task

1. Work out where hooks sit in a tool call's lifecycle, and how `PostToolUse` differs from intercepting an outgoing call.
2. Normalise heterogeneous data before the model ever sees it.
3. Move the "refund above the limit → escalate" rule out of the loop and into a hook, so it behaves identically in every agent.

## 📚 Theory

### Two interception points

A hook is your code, invoked by the Agent SDK at a specific moment in a tool's lifecycle. The exam expects you to tell two positions apart.

**Outgoing call interception** — before execution. This is where policy lives: block an action that violates a rule and **redirect to an alternative workflow**. The guide's canonical example: a refund above a threshold is not executed but routed to human escalation.

**`PostToolUse`** — after execution, before the model sees the result. This is where transformation happens: reduce heterogeneous formats to one, expand numeric codes into meaningful values, trim noise.

### Normalisation is not cosmetics

Kostya's problem is the exact example the guide spells out: **Unix timestamps, ISO 8601, numeric status codes from different MCP tools**. As long as each server returns its own shape, the model spends attention parsing formats instead of doing the task — and it gets the boundaries wrong.

```
Before PostToolUse                       After PostToolUse
{"paid_at": 1793491200}                  {"paid_at": "2026-10-01T00:00:00Z"}
{"delivered_at": "2026-08-14T09:20:00Z"} {"delivered_at": "2026-08-14T09:20:00Z"}
{"contact_date": "14/08/26",              {"contact_date": "2026-08-14T00:00:00Z",
 "status": 3}                              "status": "delivered"}
```

The point is not tidiness but that after normalisation **all dates are comparable**, and "delivered yesterday" stops depending on which server answered.

### Hooks over prompts — again, and not by accident

The guide repeats the point from objective 1.4, now about hooks: **choose hooks over prompt-based enforcement when business rules require guaranteed compliance**. The difference between 1.4 and 1.5 is *where* the mechanism sits: 1.4 is about prerequisites and step ordering, 1.5 is about the SDK's interception machinery itself.

In practice: a rule wired into one agent's loop is a temporary fix. A rule extracted into a hook applies to every agent that has the hook attached, independent of what their prompts say.

| Requirement | Mechanism |
| --- | --- |
| "Answer politely and in the customer's language" | system prompt |
| "Never refund more than 500 without a human" | call interception hook |
| "All dates in ISO 8601" | `PostToolUse` |
| "Verify identity first" | prerequisite gate (C4) |
| "Prefer short answers" | system prompt |

## 💻 Practice

Two hooks and one agent. The rules live outside the loop: the loop knows nothing about them.

```python
# pip install anthropic
import os, json, re, anthropic
from datetime import datetime, timezone

client = anthropic.Anthropic(api_key=os.environ["ANTHROPIC_API_KEY"])
MODEL = "claude-sonnet-5"
REFUND_LIMIT = 500

STATUS_CODES = {1: "created", 2: "shipped", 3: "delivered", 4: "returned"}

# ---------- hook 1: outgoing call interception (policy) ----------
def before_tool(name: str, args: dict):
    """Returns None (allow) or a reason string describing the block and the alternative."""
    if name == "process_refund" and args.get("amount", 0) > REFUND_LIMIT:
        return (f"BLOCKED by policy: a refund of {args['amount']} exceeds the {REFUND_LIMIT} limit. "
                "Call escalate_to_human with a structured summary "
                "(customer_id, root_cause, amount, recommended_action).")
    return None

# ---------- hook 2: PostToolUse (normalisation) ----------
def normalize_value(key: str, value):
    if key == "status" and isinstance(value, int):
        return STATUS_CODES.get(value, f"unknown_{value}")
    if isinstance(value, int) and key.endswith(("_at", "_date")) and value > 1_000_000_000:
        return datetime.fromtimestamp(value, tz=timezone.utc).isoformat().replace("+00:00", "Z")
    if isinstance(value, str) and re.fullmatch(r"\d{2}/\d{2}/\d{2}", value):
        d, m, y = value.split("/")
        return f"20{y}-{m}-{d}T00:00:00Z"
    return value

def post_tool_use(name: str, result: dict) -> dict:
    """Reduce heterogeneous formats to one shape BEFORE the model sees the result."""
    if not isinstance(result, dict):
        return result
    out = {k: normalize_value(k, v) for k, v in result.items()}
    changed = {k: (result[k], out[k]) for k in out if out[k] != result[k]}
    if changed:
        print(f"    ↻ normalised in {name}: {changed}")
    return out

# ---------- tools from three different MCP servers ----------
TOOLS = [
    {"name": "get_payment", "description": "Payment for an order (billing-mcp).",
     "input_schema": {"type": "object", "properties": {"order_id": {"type": "string"}}, "required": ["order_id"]}},
    {"name": "get_order", "description": "Order and delivery (orders-mcp).",
     "input_schema": {"type": "object", "properties": {"order_id": {"type": "string"}}, "required": ["order_id"]}},
    {"name": "get_contact", "description": "Last contact with the customer (legacy-crm-mcp).",
     "input_schema": {"type": "object", "properties": {"customer_id": {"type": "string"}}, "required": ["customer_id"]}},
    {"name": "process_refund", "description": "Issues a refund.",
     "input_schema": {"type": "object", "properties": {"customer_id": {"type": "string"}, "amount": {"type": "number"}},
                      "required": ["customer_id", "amount"]}},
    {"name": "escalate_to_human", "description": "Escalation with a structured summary.",
     "input_schema": {"type": "object", "properties": {
         "customer_id": {"type": "string"}, "root_cause": {"type": "string"},
         "amount": {"type": "number"}, "recommended_action": {"type": "string"}},
         "required": ["customer_id", "root_cause", "recommended_action"]}},
]

def run_tool(name, args):
    return {
        "get_payment": {"paid_at": 1793491200, "amount": 4900, "status": 2},
        "get_order":   {"delivered_at": "2026-08-14T09:20:00Z", "carrier": "DHL"},
        "get_contact": {"contact_date": "14/08/26", "status": 3, "channel": "email"},
        "process_refund": {"ok": True, "refunded": args.get("amount")},
        "escalate_to_human": {"ok": True, "ticket": "H-1043"},
    }.get(name, {"error": f"unknown_tool:{name}"})

def agent(question: str, max_iterations: int = 12):
    messages = [{"role": "user", "content": question}]
    for _ in range(max_iterations):
        resp = client.messages.create(model=MODEL, max_tokens=1024, tools=TOOLS, messages=messages)
        if resp.stop_reason != "tool_use":
            return "".join(b.text for b in resp.content if b.type == "text")
        messages.append({"role": "assistant", "content": resp.content})
        results = []
        for b in resp.content:
            if b.type != "tool_use":
                continue
            blocked = before_tool(b.name, b.input)                    # hook 1
            if blocked:
                print(f"    ⛔ {b.name}: {blocked}")
                results.append({"type": "tool_result", "tool_use_id": b.id,
                                "content": blocked, "is_error": True})
                continue
            out = post_tool_use(b.name, run_tool(b.name, b.input))     # hook 2
            results.append({"type": "tool_result", "tool_use_id": b.id,
                            "content": json.dumps(out)})
        messages.append({"role": "user", "content": results})
    return None

if __name__ == "__main__":
    print(agent("Customer C-88214, order 88214: when was it delivered, when did the payment go through, "
                "and when did we last contact them? Refund 4900 for the defect."))
```

**Assignment.**

1. Disable `post_tool_use` and ask "how many days passed between the payment and the delivery". Compare the answers with and without normalisation across five runs.
2. Test the redirect: 4900 is above the 500 limit, so the agent should move to `escalate_to_human`. Then reduce the block message to a bare `"BLOCKED"` and watch it retry the refund instead of escalating.
3. Add a fourth "server" returning a date as `"August 14, 2026"` and extend the normaliser. Note that the agent needed no changes — the rule lives in the hook.

## 🎯 On the exam

- **Objective 1.5** is covered: `PostToolUse` for result transformation, outgoing call interception for policy, choosing hooks over prompts for guarantees.
- Scenarios: **Customer Support Resolution Agent** (refund limit, escalation), **Developer Productivity with Claude** and **Multi-Agent Research System** (heterogeneous formats from different MCP servers).
- Trap: the option "describe all the date formats in the system prompt so the model understands them". The model will cope most of the time — which is again a probabilistic answer to a deterministic problem.
- Identify the hook position from the wording: "before the model processes the result" → `PostToolUse`; "prevent the action from happening" → call interception.
- Remember the **redirect**: the correct answer is usually not "block" but "block and route to an alternative workflow" — escalation, another tool, a confirmation request.

---

## 📌 Remember

- A hook is your deterministic code inside a tool's lifecycle. Two positions: before execution (policy) and after (`PostToolUse`, transformation).
- `PostToolUse` normalises heterogeneous data — Unix timestamps, ISO 8601, numeric codes — before the model sees it.
- Outgoing call interception blocks a policy violation **and redirects** to an alternative workflow rather than just refusing.
- A rule in a hook behaves identically across every agent and does not depend on their prompts. A rule inside one agent's loop is copy-paste waiting to drift.
- Prompts remain the right tool for style, tone and preferences. Anything that needs a guarantee moves into hooks.
