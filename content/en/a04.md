# Module A4. Prompts are code

> **Level:** Junior AI · **Time:** ~50 minutes · **Format:** situation → theory → practice → quiz

---

## 🏢 The situation

Tuesday morning. Dasha, the CMO, writes in the chat:

> "The emails got worse. Yesterday they were fine, today they're formal and every single one starts with 'I hope this email finds you well'. What happened?"

You open the code. Last night you "tweaked the prompt a little" — added a request to be more polite, because one email felt blunt. One line.

Then come the uncomfortable questions you cannot answer:

- Which prompt worked yesterday? Git only has the latest version, and the commit is called "tweak prompt".
- Did quality actually drop — or did Dasha just happen to read different emails?
- If you roll back, does the blunt email that started all this come back?

Lena, the team lead, listens and says: "You just described deploying without versions and without tests. In ML we went through that five years ago."

## 🎯 Your task

1. Stop editing the prompt in place and start versioning it.
2. Separate what is a rule from what is data.
3. Build a set of checks that catches a regression before Dasha does.

---

## 📚 Theory

### A prompt is a release artifact

A prompt defines system behavior exactly like code does. So the same requirements apply:

| Requirement for code | What it looks like for a prompt |
| --- | --- |
| Version | A file `prompts/outreach/v3.md`, not a string in the source |
| Change history | What changed, why, and what the result was |
| Tests | A set of inputs with assertions about output properties |
| Rollback | Restore the previous version with one environment variable |
| Review | A second person reviews prompt edits — they change product behavior |

A prompt baked into an f-string in the middle of a function cannot be versioned, diffed or rolled back.

The practical warning sign: you find yourself concatenating an instruction with data into one string. The moment "and don't forget the format" appears in a user message, the rule is lost.

### Guardrails: three levels, not one

The prompt is the weakest level of protection, because the model may simply not comply.

1. **In the prompt:** prohibitions in words. Cheap, but not a guarantee.
2. **In the schema:** `enum`, required fields, type constraints. The provider will not let them be violated.
3. **In code after the response:** length checks, banned phrases, forbidden claims. The only level you fully control.

The rule is simple: **anything expensive is checked in code**. The prompt asks not to quote prices — the code looks for a currency symbol next to digits and rejects the draft.

### Regressions: the minimum viable check set

You do not need a big framework to catch last night's breakage. You need a file with a dozen inputs and assertions about output properties — not "this exact text", but "contains no price", "contains a question", "under 120 words", "references the trigger from the input".

Such a set runs in a minute before every prompt change. It will not prove the emails got better — but it will stop you from silently breaking what worked.

## 💻 Practice

Directory layout:

```
prompts/
  outreach.v1.md      # first version
  outreach.v2.md      # + ban on "I hope this email finds you well"
  outreach.v3.md      # current
checks/outreach.json  # regression set
```

```python
# pip install anthropic
import os, re, json, pathlib, anthropic

client = anthropic.Anthropic(api_key=os.environ["ANTHROPIC_API_KEY"])
MODEL = "claude-sonnet-5"

# Prompt version comes from the environment: rollback without touching code
PROMPT_VERSION = os.environ.get("OUTREACH_PROMPT", "v3")
SYSTEM = pathlib.Path(f"prompts/outreach.{PROMPT_VERSION}.md").read_text(encoding="utf-8")

# --- Level 3: checks in code. Never skip them, they are cheap ---
BANNED_OPENERS = ("hope this email finds you", "i hope you are doing well")
PRICE_RE = re.compile(r"[$€£]\s?\d|\b\d+\s?(usd|eur|gbp|dollars)", re.I)

def hard_checks(draft, lead):
    problems = []
    body = draft["body"]
    if len(body.split()) > 120:
        problems.append("longer than 120 words")
    if PRICE_RE.search(body):
        problems.append("mentions a price")
    if any(b in body.lower() for b in BANNED_OPENERS):
        problems.append("boilerplate opener")
    if "?" not in body:
        problems.append("no question")
    # the hook must be grounded in the input, not invented
    if lead["trigger"].split()[0].lower() not in draft["personalization"].lower():
        problems.append("hook unrelated to the lead's trigger")
    return problems


def generate(lead):
    resp = client.messages.create(
        model=MODEL, max_tokens=800, temperature=0.7, system=SYSTEM,
        tools=[DRAFT_TOOL], tool_choice={"type": "tool", "name": "save_draft"},
        messages=[{"role": "user", "content": json.dumps(lead)}],
    )
    return next(b for b in resp.content if b.type == "tool_use").input


# --- The regression run before every prompt change ---
def run_checks():
    cases = json.loads(pathlib.Path("checks/outreach.json").read_text(encoding="utf-8"))
    failures = []
    for case in cases:
        draft = generate(case["lead"])
        problems = hard_checks(draft, case["lead"])
        if problems:
            failures.append({"case": case["name"], "problems": problems})
    print(f"prompt {PROMPT_VERSION}: {len(cases) - len(failures)}/{len(cases)} passed")
    for f in failures:
        print(f"  ✗ {f['case']}: {', '.join(f['problems'])}")
    return not failures


if __name__ == "__main__":
    ok = run_checks()
    raise SystemExit(0 if ok else 1)   # non-zero exit code — do not ship
```

`checks/outreach.json` is a plain list of cases, including the ones that already broke you:

```json
[
  {"name": "ordinary lead", "lead": {"company": "NordFin", "role": "Head of Data",
    "trigger": "posted an ML engineer job opening"}},
  {"name": "very long company name", "lead": {"company": "Northern Financial Group Holdings",
    "role": "CTO", "trigger": "launched a new mobile app"}},
  {"name": "v2 regression: boilerplate opener", "lead": {"company": "Aurum", "role": "COO",
    "trigger": "opened an office in Warsaw"}}
]
```

What matters here:

1. **The prompt lives in a versioned file.** Rollback is `OUTREACH_PROMPT=v2`, not a panicked dig through git history.
2. **Checks in code do not depend on the model's obedience.** The price regex fires even if the model ignores the prohibition.
3. **A non-zero exit code.** The run plugs into CI: checks fail, the prompt does not ship.
4. **Regression cases are named.** "v2 regression: boilerplate opener" is the team's memory of what already burned them.

**Assignment.** Create two prompt files: the current one and an "improved" one. Run the set against both and compare the failure counts. If the new version is not better, you just saved yourself a week of arguing with Dasha.

## 📌 Remember

- A prompt is a release artifact: version, history, review, rollback. Not a string in the middle of a function.
- System holds rules and format, user holds one run's data. An instruction that drifted into data is lost.
- Guardrails go at three levels; anything expensive is checked by code, not by a polite request in the prompt.
- Ten named cases with assertions about output properties catch most regressions.
- Checks return a non-zero exit code and live in CI — otherwise people stop running them.
- "I just tweaked the prompt" is a deploy. Treat it like one.

**Further reading:** prompt-versioning practices in LangSmith/Braintrust (the idea, not the tool lock-in); chapters on property-based testing; and your own list of breakages — more useful than any article.
