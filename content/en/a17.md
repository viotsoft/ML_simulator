# Module A17. The improvement loop

> **Level:** Senior AI · **Time:** ~50 minutes · **Format:** situation → theory → practice → quiz

---

## 🏢 The situation

Six months in. The system is stable, rollbacks work, incidents are rare. And precisely then Marina asks the uncomfortable question:

> "Share of emails sent without edits: 78%. It was the same in February. We've been improving something for six months and the number hasn't moved. Are we going anywhere?"

You open your tickets for the quarter: fixed the prompt after Igor's complaint, added a check after the "1C" incident, tuned the temperature because Dasha felt it read dry. All of it reactions to individual cases. Not one was chosen because it was the **most frequent or most expensive**.

Meanwhile Igor edits emails every day — and his edits are saved nowhere. The most valuable quality signal you have goes in the bin.

## 🎯 Your task

1. Collect feedback so it becomes data rather than impressions.
2. Classify errors by type, so you fix classes instead of cases.
3. Choose what to fix by frequency and cost, not by how loudly it was reported.

---

## 📚 Theory

### Feedback: three sources, different prices

| Source | What it gives | Cost to collect |
| --- | --- | --- |
| **Implicit signal** — human edits before sending | Precise, plentiful, needs no asking | Almost zero: just store the diff |
| **Explicit signal** — 👍/👎 with a reason | Labeled causes, rare cases | Seconds of human time, but not everyone clicks |
| **Outcome** — replies, meetings, deals | The only truth about value | Weeks of delay, market noise |

Most teams' mistake is building only the third, suffering from the delay and ignoring the first. **An edit before sending is ready-made labeling**: before / after / who edited / when. That alone is enough to see what is systematically wrong.

The rule for error types: there should be **5–8 of them**, and they must differ in how they are fixed. "Bad email" is not a type. "The hook is unrelated to the lead's trigger" is a type, because the fix is clear: repair the context collector or require a source for the hook.

### The weekly review: thirty minutes that move the product

The format that works:

1. **Numbers** (5 minutes): edit rate, refusals, escalations, check failures, cost — versus last week.
2. **Top 3 error types** (10 minutes): what rose, what fell, and why.
3. **Five random runs** (10 minutes): read them in full, good ones included. This is where you find what metrics do not show.
4. **One decision** (5 minutes): what we fix next week and how we will know it helped.

The crucial part is that item 4 is singular. Three parallel changes mean you will not learn which one worked.

### Closing the loop

Edit → error type → golden-set case (A6) → change → canary (A16) → measurement → more edits. The loop is closed when **every step is automatic except deciding what to fix**. That decision stays human, because it is about business priorities, not data.

## 💻 Practice

```python
import os, json, difflib, collections, datetime as dt, anthropic

client = anthropic.Anthropic(api_key=os.environ["ANTHROPIC_API_KEY"])

ERROR_TYPES = [
    "weak_hook",        # the hook is generic or unrelated to the lead's trigger
    "too_long",         # longer than it should be
    "wrong_tone",       # tone does not fit the recipient
    "stale_fact",       # a product fact is out of date
    "hallucination",    # a claim absent from the facts
    "wrong_recipient",  # wrong person or wrong deal stage
    "formatting",       # structure, greeting, signature
]

CLASSIFY_TOOL = {
    "name": "classify_edit",
    "input_schema": {"type": "object", "properties": {
        "types": {"type": "array", "items": {"type": "string", "enum": ERROR_TYPES}},
        "severity": {"type": "string", "enum": ["cosmetic", "material", "harmful"]},
        "note": {"type": "string", "description": "What exactly the human fixed, one phrase"},
    }, "required": ["types", "severity", "note"]},
}


def capture_edit(trace_id, lead_id, original, final, editor):
    """The most valuable signal: the edit before sending. Always store it."""
    if original.strip() == final.strip():
        return None                                  # sent unedited — that is data too
    diff = "\n".join(difflib.unified_diff(
        original.splitlines(), final.splitlines(), lineterm="", n=1))
    resp = client.messages.create(
        model=MODELS["small"], max_tokens=400, temperature=0,
        system="You classify an edit a human made to a draft email before sending. Identify the "
               "problem types in the original text. Always call classify_edit.",
        tools=[CLASSIFY_TOOL], tool_choice={"type": "tool", "name": "classify_edit"},
        messages=[{"role": "user", "content": f"BEFORE:\n{original}\n\nAFTER:\n{final}\n\nDIFF:\n{diff}"}])
    cls = next(b for b in resp.content if b.type == "tool_use").input
    store_feedback({"trace_id": trace_id, "lead_id": lead_id, "editor": editor,
                    "diff": diff, "types": cls["types"], "severity": cls["severity"],
                    "note": cls["note"], "at": dt.datetime.now(dt.timezone.utc).isoformat()})
    return cls


# Cost per error type: what one occurrence costs (set by the team, not the model)
COST_WEIGHT = {"weak_hook": 1, "too_long": 1, "wrong_tone": 1, "formatting": 0.5,
               "stale_fact": 5, "wrong_recipient": 8, "hallucination": 20}

def weekly_report(days=7):
    fb = load_feedback(days)
    total_runs = count_runs(days)
    counter = collections.Counter(t for f in fb for t in f["types"])

    rows = []
    for etype, n in counter.items():
        rows.append({
            "type": etype,
            "cases": n,
            "share_of_runs": round(n / max(total_runs, 1), 3),
            "priority": round(n * COST_WEIGHT.get(etype, 1), 1),   # frequency × cost
        })
    rows.sort(key=lambda r: -r["priority"])

    return {
        "runs": total_runs,
        "edits": len(fb),
        "unedited_rate": round(1 - len(fb) / max(total_runs, 1), 3),
        "by_type": rows,
        "fix_first": rows[0]["type"] if rows else None,
    }


def promote_worst_to_golden(limit=5):
    """The week's worst cases automatically become golden-set cases (A6, A14)."""
    fb = sorted(load_feedback(7), key=lambda f: -COST_WEIGHT.get(f["types"][0], 1))[:limit]
    for f in fb:
        promote_to_golden(f["trace_id"],
                          name=f"{f['types'][0]} · {f['at'][:10]}",
                          expectation=f["note"])
    return len(fb)


if __name__ == "__main__":
    rep = weekly_report()
    print(f"Unedited: {rep['unedited_rate']:.0%} over {rep['runs']} runs")
    for r in rep["by_type"][:5]:
        print(f"  {r['type']:16} {r['cases']:4} cases · share {r['share_of_runs']:.1%} "
              f"· priority {r['priority']}")
    print("Fixing this week:", rep["fix_first"])
    print("Cases added to the golden set:", promote_worst_to_golden())
```

What changes after the very first report:

1. **Marina's answer becomes substantive.** Not "78%, same as February" but "the weak-hook edit share grew from 30% to 41% — that is our ceiling".
2. **Priority is computed, not debated.** "Invented" is 6% of cases, but at weight 20 it outranks "wrong tone" at 15%.
3. **Edits stop disappearing.** Every evening Igor labels data without knowing it.
4. **The week's worst cases ride into the golden set automatically** — the set grows without separate discipline.
5. **One decision per week.** After a quarter you have a history: what changed, and what it bought.

**Assignment.** Collect last week's edits (by hand from email if you must) and sort them by type. Compute frequency × cost. Almost certainly the top slot is not what you fixed most recently.

---

## 📌 Remember

- A human edit before sending is the cheapest and most precise quality signal. Always store it.
- There should be 5–8 error types, distinguished by how they are fixed, not by wording.
- Priority = frequency × cost. How loudly something was reported is irrelevant to priority.
- The weekly review: numbers, top types, five random runs read in full, one decision.
- One change at a time, or you will not know which one helped.
- The loop is closed when everything is automated except deciding what to fix. That decision is human.
