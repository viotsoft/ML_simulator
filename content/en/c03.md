## 📚 Theory

### Spawning mechanics: Task and allowedTools

Subagents are spawned through the **`Task`** tool. Hence a requirement the exam likes: **the coordinator's `allowedTools` must include `"Task"`** — otherwise it physically cannot delegate, and you get an agent that "for some reason does everything itself".

Each subagent type is described by an **`AgentDefinition`**: a description (when to invoke it), a system prompt (who it is and how it works), and **tool restrictions**. The restriction is not ceremony: a synthesis subagent has no business on the web, and a document reader has no business writing files.

```
Coordinator
  allowedTools: ["Task", ...]      ← without "Task" delegation is impossible
  │
  ├── AgentDefinition "web"    → tools: [WebSearch]        description: when external facts are needed
  ├── AgentDefinition "docs"   → tools: [Read, Grep]       description: when the answer may be internal
  └── AgentDefinition "synth"  → tools: []                 description: combine findings, gather nothing new
```

### Parallel spawning happens in one response

Kostya's complaint is cured by one detail the exam tests separately: **multiple `Task` calls are emitted in a single coordinator response**, not one per turn.

### Context is passed explicitly — as structure, not prose

We already know a subagent inherits nothing. The exam adds two refinements, both about the quality of the handoff.

**First: put the complete findings of prior agents into the synthesiser's prompt.** Not "see above", not a paraphrase — the findings themselves.

**Second: separate content from metadata using structure.** This is exactly where Dasha's report broke. Compare:

```
❌ prose                                  ✅ structure
"According to market research the         {"claim": "40% share",
share is 40%, while Forrester              "source_url": "https://...",
puts it at 35%..."                         "source_name": "Market Report 2026",
                                           "page": 12}
```

When the source is part of the structure rather than part of a sentence, the synthesiser cannot lose it while paraphrasing: attribution reaches the final report. This is precisely the technique the guide calls *preserving attribution*.

**A third refinement — how the task is phrased.** The coordinator prompt should state **goals and quality criteria**, not a step-by-step procedure. "Find how competitors position their pricing; at least three independent sources, every claim cited" works better than "open the site, find the Pricing section, copy the table". A procedural instruction strips the subagent of the ability to adapt — and adaptability was the reason for having it.

Point by point, because the exam asks this almost verbatim:

- **`--resume <session-name>`** — continue a named session. Right when the prior context is mostly valid. The mandatory companion: **tell the agent which files changed** since last time. Then it re-reads selectively rather than exploring everything again — and it stops reasoning from old reads, as in your situation.
- **`fork_session`** — create an independent branch from a shared analysis baseline. The classic case: the agent spent half an hour understanding the codebase and now you want to compare two testing strategies without repeating that analysis. Each branch goes its own way; the baseline is shared.
- **A new session with a structured summary** — when prior tool results have gone stale. The exam states it as a principle: **starting fresh with a clear summary is more reliable than resuming with stale tool results**. You control the summary; you do not control a day-old file read.

## 💻 Practice

A coordinator that passes context as structure and spawns independent subagents in one go. Attribution travels in its own field and survives into the report.

```python
# pip install anthropic
import os, json, anthropic
from concurrent.futures import ThreadPoolExecutor

client = anthropic.Anthropic(api_key=os.environ["ANTHROPIC_API_KEY"])
MODEL = "claude-sonnet-5"

# AgentDefinition: description, system prompt and tool restrictions
AGENTS = {
    "web": {
        "description": "Finds external facts. Invoke when data lives outside the company.",
        "system": "You find facts. Return each claim as a separate object with the fields "
                  "claim, source_name, source_url. Never merge a fact and its source into one sentence.",
        "tools": [],   # in production: [WebSearch]
    },
    "docs": {
        "description": "Analyses internal documents. Invoke when the answer may already be inside the company.",
        "system": "You analyse documents. Return objects with the fields claim, source_name, page. "
                  "If the data is not there, return an empty list — never invent it.",
        "tools": [],   # in production: [Read, Grep]
    },
    "synth": {
        "description": "Combines findings into an answer. Gathers no new data.",
        "system": "You combine the findings you are given. Use ONLY those. "
                  "Keep the source_name/source_url reference attached to every claim.",
        "tools": [],
    },
}

def run_subagent(role: str, goal: str, findings: list | None = None) -> str:
    """Context is passed explicitly and as structure: content in one field, metadata in another."""
    a = AGENTS[role]
    payload = ""
    if findings:
        payload = ("\n\nFindings from prior agents (JSON, attribution in the source_* fields):\n"
                   + json.dumps(findings, indent=2))
    resp = client.messages.create(
        model=MODEL, max_tokens=1500, system=a["system"],
        messages=[{"role": "user", "content":
            # goals and quality criteria, not a step-by-step procedure
            f"Goal: {goal}\n"
            "Quality criteria: every claim is backed by a source; "
            "missing data is stated explicitly rather than filled in with a guess."
            + payload}],
    )
    return "".join(b.text for b in resp.content if b.type == "text")

def research(goal: str) -> str:
    # Independent subagents start together — the analogue of several Task calls in one response
    with ThreadPoolExecutor(max_workers=2) as pool:
        futures = {role: pool.submit(run_subagent, role, goal) for role in ("web", "docs")}
        raw = {role: f.result() for role, f in futures.items()}

    findings = []
    for role, text in raw.items():
        try:
            findings.extend(json.loads(text) if text.strip().startswith("[") else [{"claim": text, "source_name": role}])
        except json.JSONDecodeError:
            findings.append({"claim": text, "source_name": role, "parse_error": True})

    # synth depends on the others — it starts only afterwards
    return run_subagent("synth", goal, findings)

if __name__ == "__main__":
    print(research("How do competitors position the price of agentic assistants? At least three independent sources."))
```

**Assignment.**

1. Replace the structured handoff with prose: join the findings into one string with `\n` and drop the `source_*` fields. Count how many claims in the final report still carry a citation. That is the bug behind Dasha's complaint.
2. Rewrite the goal procedurally ("step 1: open the pricing page; step 2: copy the table") and see how the subagent copes with a source that has no such page.
3. Run your own session experiment in Claude Code: start a named session analysing any module in this repository, change a file, then resume it two ways — plain `--resume`, and `--resume` plus the sentence "file X was rewritten, re-read it". Compare what the agent claims about the contents.

## 🎯 On the exam

- **Objective 1.3**: `Task` as the spawning mechanism, the mandatory `"Task"` in `allowedTools`, `AgentDefinition` (description, system prompt, tool restrictions), complete findings in the subagent prompt, structure over prose for attribution, parallel spawning via several `Task` calls in one response, goals over procedures.
- **Objective 1.7**: `--resume <session-name>`, `fork_session`, informing about changed files, choosing between resumption and a fresh start with an injected summary.
- Scenarios: **Multi-Agent Research System** (context passing and attribution), **Developer Productivity with Claude** and **Code Generation with Claude Code** (sessions, forking, resuming after edits).
- Trap: an option offering "give the subagent access to the coordinator's memory" or "enable shared memory between invocations" — subagents share no memory between invocations; context is explicit only.
- Parallelism trap: "call Task in separate turns so the coordinator can react to each result" sounds sensible, but for independent tasks it is exactly the wasted time the question is testing.
- Session trap: "always resume so no context is lost." When tool results are stale, the correct answer is a new session with a structured summary.

---

## 📌 Remember

- Subagents are spawned by the `Task` tool; without `"Task"` in `allowedTools` the coordinator cannot delegate.
- An `AgentDefinition` is a description (when to invoke), a system prompt, and the list of allowed tools. Tool restriction is part of the design, not paranoia.
- Several independent subagents are launched with several `Task` calls **in one response**.
- Context is passed in full and as structure: content in one field, source in another. That is how attribution survives into the report.
- A task is phrased as goals and quality criteria, not as a procedure.
- `--resume` when context is valid (and say what changed). `fork_session` when you need two branches from one baseline. A new session with a summary when prior results are stale.
