# Модуль A4. Промпты — это код

> **Уровень:** Junior AI · **Время:** ~50 минут · **Формат:** ситуация → теория → практика → квиз

---

## 🏢 Ситуация

Утро вторника. Даша, CMO, пишет в чат:

> «Письма стали хуже. Вчера были нормальные, сегодня какие-то формальные и все начинаются с "Надеюсь, у вас всё хорошо". Что случилось?»

Вы открываете код. Вчера вечером вы «чуть-чуть поправили промпт» — добавили просьбу писать вежливее, потому что одно письмо показалось резким. Одна строка.

Дальше — неприятные вопросы, на которые у вас нет ответов:

- Какой промпт работал вчера? В git только последняя версия, коммит называется «tweak prompt».
- Стало ли хуже объективно — или Даше просто попались другие письма?
- Если откатить, вернётся ли «резкое» письмо, из-за которого вы всё и начали?

Лена, тимлид, слушает и говорит: «Ты только что описал деплой без версий и без тестов. В ML мы это прошли лет пять назад».

## 🎯 Ваша задача

1. Перестать править промпт «на месте» и завести версии.
2. Разделить, что в промпте — правила, а что — данные.
3. Завести набор проверок, который ловит поломку до того, как её заметит Даша.

---

## 📚 Теория

### Промпт — это артефакт релиза

Промпт задаёт поведение системы так же, как код. Значит, к нему применимы те же требования:

| Требование к коду | Как выглядит для промпта |
| --- | --- |
| Версия | Файл `prompts/outreach/v3.md`, а не строка в исходнике |
| История изменений | Что поменяли, зачем, какой был результат |
| Тесты | Набор входов с ожидаемыми свойствами выхода |
| Откат | Вернуть предыдущую версию одной переменной окружения |
| Ревью | Правку промпта смотрит второй человек — она меняет поведение продукта |

Промпт, зашитый в f-строку посреди функции, невозможно ни версионировать, ни сравнить, ни откатить.

Практический признак ошибки: вы обнаруживаете, что склеиваете инструкцию с данными в одну строку. Как только в user-сообщении появляется «не забудь про формат», правило потеряно.

### Guardrails: три уровня, а не один

Промпт — самый слабый уровень защиты, потому что модель может его не выполнить.

1. **В промпте:** запреты словами. Дёшево, но не гарантия.
2. **В схеме:** `enum`, обязательные поля, ограничения типов. Провайдер не даст нарушить.
3. **В коде после ответа:** проверка длины, стоп-слов, запрещённых утверждений. Единственный уровень, который вы полностью контролируете.

Правило простое: **всё, что стоит дорого, проверяется в коде**. Промпт просит не называть цены — код ищет в тексте символ валюты и цифры и бракует черновик.

### Регрессии: минимальный набор проверок

Не нужен большой фреймворк, чтобы поймать вчерашнюю поломку. Нужен файл с десятком входов и утверждениями о свойствах выхода — не «вот такой текст», а «в тексте нет цены», «есть вопрос», «меньше 120 слов», «упоминается событие из входных данных».

Такой набор гоняется за минуту перед каждым изменением промпта. Он не докажет, что письма стали лучше — но не даст молча сломать то, что работало.

## 💻 Практика

Структура каталога:

```
prompts/
  outreach.v1.md      # первая версия
  outreach.v2.md      # + запрет на «Надеюсь, у вас всё хорошо»
  outreach.v3.md      # текущая
checks/outreach.json  # регрессионный набор
```

```python
# pip install anthropic
import os, re, json, pathlib, anthropic

client = anthropic.Anthropic(api_key=os.environ["ANTHROPIC_API_KEY"])
MODEL = "claude-sonnet-5"

# Версия промпта — переменная окружения: откат без правки кода
PROMPT_VERSION = os.environ.get("OUTREACH_PROMPT", "v3")
SYSTEM = pathlib.Path(f"prompts/outreach.{PROMPT_VERSION}.md").read_text(encoding="utf-8")

# --- Уровень 3: проверки в коде. Ими нельзя пренебречь, они дешёвые ---
BANNED_OPENERS = ("надеюсь, у вас всё хорошо", "hope this email finds you")
PRICE_RE = re.compile(r"[$€₽]\s?\d|\b\d+\s?(руб|usd|eur|долл)", re.I)

def hard_checks(draft, lead):
    problems = []
    body = draft["body"]
    if len(body.split()) > 120:
        problems.append("длиннее 120 слов")
    if PRICE_RE.search(body):
        problems.append("упоминает цену")
    if any(b in body.lower() for b in BANNED_OPENERS):
        problems.append("шаблонное вступление")
    if "?" not in body:
        problems.append("нет вопроса")
    # зацепка должна опираться на входные данные, а не на фантазию
    if lead["trigger"].split()[0].lower() not in draft["personalization"].lower():
        problems.append("зацепка не связана с событием лида")
    return problems


def generate(lead):
    resp = client.messages.create(
        model=MODEL, max_tokens=800, temperature=0.7, system=SYSTEM,
        tools=[DRAFT_TOOL], tool_choice={"type": "tool", "name": "save_draft"},
        messages=[{"role": "user", "content": json.dumps(lead, ensure_ascii=False)}],
    )
    return next(b for b in resp.content if b.type == "tool_use").input


# --- Регрессионный прогон перед каждым изменением промпта ---
def run_checks():
    cases = json.loads(pathlib.Path("checks/outreach.json").read_text(encoding="utf-8"))
    failures = []
    for case in cases:
        draft = generate(case["lead"])
        problems = hard_checks(draft, case["lead"])
        if problems:
            failures.append({"case": case["name"], "problems": problems})
    print(f"промпт {PROMPT_VERSION}: {len(cases) - len(failures)}/{len(cases)} прошли")
    for f in failures:
        print(f"  ✗ {f['case']}: {', '.join(f['problems'])}")
    return not failures


if __name__ == "__main__":
    ok = run_checks()
    raise SystemExit(0 if ok else 1)   # ненулевой код — не выкатываем
```

`checks/outreach.json` — обычный список случаев, включая те, на которых уже ломались:

```json
[
  {"name": "обычный лид", "lead": {"company": "NordFin", "role": "Head of Data",
    "trigger": "открыли вакансию ML-инженера"}},
  {"name": "длинное название компании", "lead": {"company": "Северная финансовая группа плюс",
    "role": "CTO", "trigger": "запустили новое мобильное приложение"}},
  {"name": "регрессия v2: шаблонное вступление", "lead": {"company": "Aurum", "role": "COO",
    "trigger": "открыли офис в Варшаве"}}
]
```

Что здесь важно:

1. **Промпт лежит в файле с версией.** Откат — это `OUTREACH_PROMPT=v2`, а не поиск по истории git в панике.
2. **Проверки в коде не зависят от послушности модели.** Регулярка на цену сработает, даже если модель проигнорирует запрет.
3. **Ненулевой код возврата.** Прогон встраивается в CI: не прошли проверки — промпт не выкатывается.
4. **Кейсы-регрессии именованные.** «регрессия v2: шаблонное вступление» — это память команды о том, на чём уже обжигались.

**Задание.** Заведите два файла промпта: текущий и «улучшенный». Прогоните набор на обоих и сравните число провалов. Если новая версия не лучше — вы только что сэкономили себе неделю разбирательств с Дашей.

## 📌 Запомнить

- Промпт — артефакт релиза: версия, история, ревью, откат. Не строка посреди функции.
- System — правила и формат, user — данные одного запуска. Инструкция, уехавшая в данные, потеряна.
- Guardrails ставят на трёх уровнях; всё дорогое проверяется кодом, а не просьбой в промпте.
- Десять именованных кейсов с утверждениями о свойствах выхода ловят большинство регрессий.
- Проверки возвращают ненулевой код и встраиваются в CI — иначе их перестанут запускать.
- «Чуть-чуть поправил промпт» — это деплой. Относитесь к нему соответственно.
