# Модуль A18. Дизайн доверия

> **Уровень:** Senior AI · **Время:** ~50 минут · **Формат:** ситуация → теория → практика → квиз

---

## 🏢 Ситуация

Систему решили дать всей команде продаж — не только Игорю. Пять новых менеджеров, обучение полчаса.

Через две недели вы смотрите статистику по людям и видите три разных поведения:

- **Двое** одобряют письма пачками не глядя. Доля правок у них — 2%. Не потому что письма лучше, а потому что они не читают.
- **Двое** переписывают каждое письмо почти полностью. Быстрее было бы написать самим.
- **Один** работает как задумано: смотрит, правит редкое, отправляет.

Интерфейс у всех одинаковый. Разница — в доверии: первые доверяют слепо, вторые не доверяют вовсе, и оба варианта хуже, чем осознанная проверка.

Марина формулирует задачу: «Сделай так, чтобы человеку было понятно, когда можно жать не глядя, а когда нужно вчитаться».

## 🎯 Ваша задача

1. Показывать неуверенность агента так, чтобы она меняла поведение человека.
2. Объяснять решения через основания, а не через «рассуждения» модели.
3. Дать возможность отменить действие — это влияет на доверие сильнее любых объяснений.

---

## 📚 Теория

### Калиброванное доверие

Цель интерфейса — не «максимальное доверие», а **соответствие доверия качеству**. Слепое доверие и полное недоверие одинаково плохи: в первом случае ошибки проходят, во втором автоматизация не окупается.

### Как показывать неуверенность

Три уровня, от бесполезного к полезному:

1. **Число «уверенность: 0.72»** — почти бесполезно. Люди не откалиброваны на вероятности и быстро перестают их замечать.
2. **Категория с последствием** — «требует внимания: зацепка слабая». Уже работает: понятно и что не так, и что делать.
3. **Разное поведение интерфейса** — уверенные письма собраны в пачку «одобрить все», сомнительные показываются по одному с подсветкой проблемного места. Работает лучше всего, потому что действует до того, как человек начал читать.

Ключ: **неуверенность должна менять интерфейс, а не только текст в нём**.

### Объяснение — это основания, а не рассуждения

Соблазн — показать «ход мыслей» модели. Проблема в том, что связный текст рассуждения повышает доверие независимо от того, верный ли вывод. Убедительное объяснение неверного письма опаснее, чем отсутствие объяснения.

Что показывать вместо этого — **проверяемые основания**:

| Плохо | Хорошо |
| --- | --- |
| «Я решил упомянуть их рост, потому что это уместно» | Зацепка: вакансия ML-инженера · источник: careers-страница, 12 марта |
| «Уверен в фактах о продукте» | 3 утверждения о продукте · все со ссылками на документацию |
| «Тон подобран корректно» | Проверки: длина ✓ · цена не упомянута ✓ · вопрос есть ✓ |

Разница в том, что основания можно **проверить за секунды**, а рассуждение можно только принять на веру.

### Отмена важнее объяснения

Самый сильный инструмент доверия — возможность отменить. Из A11 у нас уже есть окно отмены. В интерфейсе это должно быть видно: «уйдёт через 14 минут, отменить». Человек, который знает, что может остановить, спокойнее относится к автоматике — и, парадоксально, меньше вмешивается.

## 💻 Практика

Серверная часть, формирующая то, что видит менеджер:

```python
def review_item(draft, ctx, memory, checks, lead):
    """Собираем карточку для проверки: сигнал доверия + проверяемые основания."""
    # 1. Сигнал уверенности — из объективных признаков, а не из самооценки модели
    signals = {
        "есть_событие": bool(ctx.get("jobs") or ctx.get("news")),
        "зацепка_с_источником": bool(draft.get("hook_source")),
        "все_утверждения_с_источниками": all(c.get("source_index") for c in draft.get("claims", [])),
        "проверки_пройдены": not checks["problems"],
        "нет_открытой_сделки": not lead.get("has_open_deal"),
        "память_свежая": all(f.get("since", "") >= recent_cutoff() for f in memory),
    }
    weak = [k for k, v in signals.items() if not v]

    if not weak:
        band = "confident"       # можно одобрять пачкой
    elif len(weak) == 1 and weak[0] in {"память_свежая"}:
        band = "check"           # смотреть, но быстро
    else:
        band = "attention"       # только по одному, с подсветкой

    return {
        "band": band,
        "weak_signals": weak,
        # 2. Основания вместо рассуждений: каждое можно проверить за секунды
        "basis": {
            "зацепка": {"текст": draft.get("personalization"),
                        "источник": draft.get("hook_source"),
                        "дата": ctx.get("news_date") or ctx.get("jobs_date")},
            "утверждения": [{"текст": c["text"], "источник": source_link(c["source_index"])}
                            for c in draft.get("claims", [])],
            "память": [{"факт": f["value"], "с": f["since"]} for f in memory],
            "проверки": checks["passed"],
        },
        # 3. Отмена всегда на виду
        "undo": {"available_until": checks.get("send_at"), "action": "cancel"},
        "highlight": highlight_spans(draft, weak),   # подсветка проблемных мест в тексте
    }


def highlight_spans(draft, weak_signals):
    """Подсвечиваем ровно то, из-за чего письмо попало в 'attention'."""
    spans = []
    if "зацепка_с_источником" in weak_signals and draft.get("personalization"):
        spans.append({"text": draft["personalization"], "why": "зацепка без источника"})
    for c in draft.get("claims", []):
        if not c.get("source_index"):
            spans.append({"text": c["text"], "why": "утверждение без подтверждения в документации"})
    return spans


# --- Пачечное одобрение доступно только для уверенных ---
def batch_approve(item_ids, user_email):
    items = [load_item(i) for i in item_ids]
    blocked = [i["id"] for i in items if i["band"] != "confident"]
    if blocked:
        return {"error": "в пачке есть письма, требующие внимания", "items": blocked}
    for i in items:
        approve(i["id"], user_email)      # A11: каждое одобрение — запись в аудите
    return {"approved": len(items)}


# --- Метрика калибровки: доверие соответствует качеству? ---
def trust_calibration(days=14):
    """Если в 'confident' правок столько же, сколько в 'attention', сигнал бесполезен."""
    out = {}
    for band in ("confident", "check", "attention"):
        items = load_reviewed(days, band=band)
        out[band] = {
            "писем": len(items),
            "доля_правок": round(share(items, lambda i: i["edited"]), 3),
            "доля_отмен": round(share(items, lambda i: i["cancelled"]), 3),
        }
    ok = out["attention"]["доля_правок"] > out["confident"]["доля_правок"] * 2
    out["сигнал_полезен"] = ok
    return out
```

Что это меняет для тех пяти менеджеров:

1. **Пачечное одобрение доступно только для «confident».** Тот, кто жал не глядя, физически не может так поступить с сомнительным письмом.
2. **Подсветка показывает конкретную фразу**, из-за которой письмо требует внимания. Тому, кто переписывал всё подряд, становится видно, что править надо одно предложение.
3. **Основания вместо рассуждений.** Зацепка со ссылкой на careers-страницу проверяется за две секунды; «я решил, что это уместно» — никогда.
4. **Метрика калибровки честно проверяет сам сигнал.** Если правок в «confident» столько же, сколько в «attention», ваш сигнал — украшение, а не инструмент.

## 📌 Запомнить

- Цель — калиброванное доверие, а не максимальное: слепое доверие и полное недоверие одинаково вредны.
- Число уверенности почти бесполезно; работает изменение поведения интерфейса.
- Показывайте проверяемые основания, а не «ход мыслей»: убедительное рассуждение повышает доверие независимо от правильности.
- Подсвечивайте конкретное место, вызвавшее сомнение, а не письмо целиком.
- Пачечное одобрение допустимо только там, где система уверена; иначе гейт превращается в фикцию (A11).
- Доступная отмена повышает доверие сильнее любых объяснений — и снижает лишние вмешательства.
