# Модуль C10. CLAUDE.md: иерархия и область действия

> **Уровень:** Practitioner · **Время:** ~45 минут · **Формат:** ситуация → теория → практика → квиз
>
> **Цели экзамена CCAR-F:** 3.1 — Configure CLAUDE.md files with appropriate hierarchy, scoping, and modular organization · 3.3 — Apply path-specific rules for conditional convention loading

---

## 🏢 Ситуация

Datacore разворачивает Claude Code на всю инженерную команду — сорок человек, монорепозиторий из двенадцати пакетов. Через неделю у вас три обращения, и все три про конвенции.

**Первое.** Артём, тот же новичок: «У меня агент пишет тесты не в том стиле. У Кости почему-то в том.» Разбираетесь: Костя два месяца назад аккуратно описал конвенции тестирования — и положил их в `~/.claude/CLAUDE.md`. У себя. Файл не в репозитории, и в команду он никогда не попадал.

**Второе.** Корневой `CLAUDE.md` разросся до 900 строк: конвенции API, стиль тестов, правила terraform, релизный процесс, соглашения о миграциях. Он грузится в каждой сессии целиком. Разработчик, правящий CSS, получает в контекст двести строк про terraform.

**Третье, самое тонкое.** Даша из платформенной команды: «Мы положили конвенции тестов в `tests/CLAUDE.md`, но половина тестов лежит рядом с кодом — `components/Button.test.tsx`. Для них правила не грузятся.» Каталожный файл привязан к каталогу, а тесты размазаны по всему дереву.

## 🎯 Ваша задача

1. Разобрать три уровня иерархии и понять, где заканчивается «моё» и начинается «командное».
2. Разбить монолитный `CLAUDE.md` на модули, чтобы контекст не забивался нерелевантным.
3. Понять, когда правило привязывают к каталогу, а когда — к шаблону пути.

- **`~/.claude/CLAUDE.md`** — пользовательский. Применяется только к вам, **в систему контроля версий не попадает**. Личные предпочтения — да, командные стандарты — нет.
- **`CLAUDE.md` в корне или `.claude/CLAUDE.md`** — проектный. Живёт в репозитории, действует для всех.
- **`CLAUDE.md` в подкаталоге** — правила для своего поддерева.

Диагностика проблемы Артёма занимает одну команду: **`/memory`** показывает, какие файлы памяти сейчас загружены. Это же первый инструмент, когда поведение агента расходится между сессиями.

### Модульность: @import и .claude/rules/

Проблема второго обращения — монолит на 900 строк. Есть два способа его разрезать.

**`@import`** — ссылка на внешний файл прямо из `CLAUDE.md`:

```markdown
# Datacore — конвенции проекта

Общие принципы: типизация обязательна, ошибки не глотаем.

@import ./standards/testing.md
@import ./standards/api-conventions.md
```

Приём из гайда: у каждого пакета монорепозитория свой `CLAUDE.md`, который импортирует **только те** файлы стандартов, что относятся к его домену. Мейнтейнер пакета сам решает, что подключать.

**`.claude/rules/`** — каталог тематических файлов правил как альтернатива монолиту: `testing.md`, `api-conventions.md`, `deployment.md`. Разложить 900 строк по темам — само по себе улучшение читаемости.

### Правила по шаблону пути

А вот теперь третье обращение — самое интересное. Файлы в `.claude/rules/` умеют **YAML-фронтматтер с полем `paths`**, где перечислены glob-шаблоны:

```markdown
---
paths: ["**/*.test.tsx", "**/*.test.ts"]
---

# Конвенции тестов

Каждый тест начинается с описания сценария, а не с названия метода.
Моки — только для внешних систем; внутренние зависимости собираются фабриками.
```

Такое правило грузится **только когда редактируется подходящий файл**. Два следствия, и оба на экзамене:

1. **Экономия контекста.** Правила terraform не попадают в сессию, где правят CSS. Нерелевантный контекст — это не только шум, это ещё и токены.
2. **Правила по типу файла, а не по каталогу.** И это ровно случай Даши.

| | Каталожный `CLAUDE.md` | Правило с `paths` |
| --- | --- | --- |
| Область | одно поддерево | любой шаблон пути |
| Тесты рядом с кодом | не покрываются | покрываются |
| Пример | `packages/api/CLAUDE.md` | `paths: ["**/*.test.tsx"]` |

Формулировка гайда: **шаблонные правила предпочтительнее каталожных `CLAUDE.md`, когда конвенции должны применяться к файлам, разбросанным по кодовой базе**. Тесты рядом с компонентами, миграции в трёх сервисах, terraform-модули в разных пакетах — всё это про `paths`.

## 💻 Практика

Практика — в Claude Code на этом репозитории. Файлы вы создаёте сами, всё локально.

**Упражнение 1. Диагностика уровня.** В сессии Claude Code выполните `/memory` и посмотрите список загруженных файлов. Теперь создайте `~/.claude/CLAUDE.md` со строкой «В ответах всегда добавляй в конце строку ⚡». Перезапустите сессию, проверьте эффект, снова выполните `/memory`. Затем задайте себе вопрос: увидит ли этот файл коллега, склонировавший репозиторий?

**Упражнение 2. Разрезание монолита.** Создайте в проекте структуру:

```
.claude/rules/
  content-style.md      ← как писать модули курса
  server-conventions.md ← правила правки server.js
```

В `content-style.md` пропишите фронтматтер, ограничивающий правило файлами модулей:

```markdown
---
paths: ["content/**/*.md"]
---

# Стиль модулей курса

Структура: ситуация → задача → теория → практика → квиз.
Заголовок модуля — `# Модуль XN. Название`.
SVG-иллюстрации оборачиваются в `<figure class="viz">`.
Русская и английская версии обязаны совпадать по структуре.
```

В `server-conventions.md`:

```markdown
---
paths: ["server.js", "marketing/**/*.js"]
---

# Правки серверного кода

Комментарии на русском, объясняют «почему», а не «что».
Новые роуты повторяют форму существующих: 409 «скоро» проверяется до 402 paywall.
Изменения в публичных ответах API — только аддитивные.
```

Откройте сессию, попросите отредактировать `content/ru/c01.md` и спросите, какие правила загружены. Затем попросите тронуть `server.js` и спросите снова. Правила должны различаться.

**Упражнение 3. Каталог против шаблона.** Создайте `content/CLAUDE.md` с одной строкой конвенции и убедитесь, что она грузится при работе с любым файлом внутри `content/`. Затем задайте вопрос, на который отвечает эта цель: как покрыть той же конвенцией файл `public/js/app.js`, если конвенция про тексты интерфейса? Каталожный файл здесь бессилен — нужен `paths` с двумя шаблонами.

## 🎯 На экзамене

- **Цель 3.1**: три уровня иерархии, невидимость пользовательского уровня для команды, `@import`, `.claude/rules/`, диагностика через `/memory`.
- **Цель 3.3**: фронтматтер `paths` с glob-шаблонами, экономия контекста, преимущество шаблонов над каталожными файлами для разбросанных конвенций.
- Сценарии: **Code Generation with Claude Code** и **Developer Productivity with Claude**.
- Ловушка-классика: «новый участник команды не получает инструкции». Ответ почти всегда — инструкции лежат в `~/.claude/CLAUDE.md` вместо проектного файла.
- Ловушка про монолит: «увеличить контекстное окно» или «сократить CLAUDE.md, выбросив часть правил». Ожидаемый ответ — разбить на `.claude/rules/` и подключать по `paths`.
- Ловушка про тесты рядом с кодом: вариант «создать CLAUDE.md в каждом каталоге с тестами» технически сработает, но экзамен ждёт `paths: ["**/*.test.tsx"]` — одно правило вместо десятков файлов.

## 📌 Запомнить

- `~/.claude/CLAUDE.md` — только для вас и никогда не для команды. Командные стандарты живут в проектном файле в репозитории.
- Каталожный `CLAUDE.md` действует на своё поддерево; корневой — на весь проект.
- `@import` подключает внешние файлы стандартов, `.claude/rules/` разносит правила по темам вместо монолита.
- `/memory` показывает, какие файлы памяти загружены, — первый шаг при расхождении поведения между сессиями.
- Фронтматтер `paths` с glob-шаблонами грузит правило только при работе с подходящими файлами: меньше нерелевантного контекста и меньше токенов.
- Конвенции для файлов, разбросанных по дереву, задают шаблоном пути, а не каталожным файлом.
