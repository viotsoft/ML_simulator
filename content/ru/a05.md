## 🏢 Ситуация

Письмо ушло клиенту. В нём фраза: «Наша платформа поддерживает интеграцию с 1С из коробки».

Мы не поддерживаем интеграцию с 1С. Никак.

Виктор, CFO, пересылает письмо с одним словом: «Объясни». Игорь злее: клиент ответил «отлично, покажите на демо» — и теперь надо объяснять, что этого нет.

Модель не соврала специально. Её попросили написать убедительное письмо про платформу для ML-команд — она собрала правдоподобное утверждение из общих знаний о таких платформах. **Она не знает наш продукт.** Всё, что она о нём знает, — три строки в system-промпте.

## 🎯 Ваша задача

1. Дать агенту доступ к настоящим фактам о продукте: документация, страница цен, FAQ поддержки.
2. Сделать так, чтобы он опирался на найденное, а не на общие представления.
3. Понять, когда фактов не нашлось — и не дать написать письмо вообще.

---

## 📚 Теория

### Почему модель выдумывает

Модель предсказывает правдоподобное продолжение. Если в контексте нет факта, но задача требует утверждения — она выдаст статистически ожидаемое утверждение. Это не баг, это принцип работы.

Лечится не просьбой «не выдумывай» (мы это уже пробовали в A1), а **заземлением**: нужный факт должен физически лежать в контексте в момент генерации.

### Нарезка: где резать документ

Плохая нарезка — по 1000 символов подряд: заголовок раздела остаётся в одном куске, а факт — в другом, и поиск их не связывает.

Правила, которые работают:

- Режьте **по структуре** — по заголовкам, разделам, пунктам FAQ. Один кусок — одна законченная мысль.
- **Добавляйте контекст в кусок**: путь к разделу («Цены → Тарифы → Enterprise») в начало текста куска. Иначе кусок «Включено 5 рабочих мест» не найдётся по запросу про Enterprise.
- Держите **перекрытие** между соседними кусками в пару предложений, чтобы факт на границе не потерялся.
- Храните вместе с куском **источник**: файл, раздел, дата обновления. Без источника вы не сможете ни проверить ответ, ни показать ссылку.

### Признание незнания — это фича

Самое ценное поведение RAG-агента: сказать «в базе знаний нет ответа». Для этого нужно два условия:

1. В промпте: «отвечай только по найденным фрагментам; если их недостаточно — верни `insufficient_context`».
2. В коде: если модель вернула этот флаг или ни один кусок не набрал минимального сходства — не генерируем письмо, отдаём лида человеку.

Без второго условия первое не работает: модель под давлением задачи всё равно что-нибудь напишет.

## 💻 Практика

Минимальный RAG без внешней векторной базы — на numpy. Для тысяч кусков этого достаточно; отдельная БД нужна на десятках тысяч.

```python
# pip install anthropic numpy
import os, json, re, numpy as np, anthropic

client = anthropic.Anthropic(api_key=os.environ["ANTHROPIC_API_KEY"])
MODEL = "claude-sonnet-5"
MIN_SIMILARITY = 0.35        # ниже — считаем, что не нашли

# --- 1. Нарезка по структуре, с путём раздела внутри куска ---
def chunk_markdown(text, source):
    chunks, path, buf = [], [], []
    def flush():
        if buf:
            body = " ".join(buf).strip()
            if body:
                chunks.append({"text": " › ".join(path) + ": " + body, "source": source,
                               "section": " › ".join(path)})
    for line in text.splitlines():
        m = re.match(r"^(#{1,3})\s+(.*)", line)
        if m:
            flush(); buf = []
            level = len(m.group(1))
            path = path[:level - 1] + [m.group(2).strip()]
        else:
            buf.append(line)
    flush()
    return chunks

# --- 2. Эмбеддинги (любой провайдер; здесь — заглушка интерфейса) ---
def embed(texts):
    """Верните матрицу (n, d). Подставьте своего провайдера эмбеддингов."""
    raise NotImplementedError("подключите провайдера эмбеддингов")

KB = []
for path in ["docs/product.md", "docs/pricing.md", "docs/faq.md"]:
    KB += chunk_markdown(open(path, encoding="utf-8").read(), path)
KB_VECTORS = embed([c["text"] for c in KB])
KB_VECTORS /= np.linalg.norm(KB_VECTORS, axis=1, keepdims=True)

# --- 3. Поиск ---
def search(query, k=4):
    q = embed([query])[0]
    q /= np.linalg.norm(q)
    sims = KB_VECTORS @ q
    idx = np.argsort(-sims)[:k]
    return [(KB[i], float(sims[i])) for i in idx]

# --- 4. Генерация строго по найденному ---
SYSTEM = """Ты пишешь холодное письмо от лица Datacore.

Утверждения о продукте бери ТОЛЬКО из блока ФАКТЫ. Если для убедительного письма
фактов не хватает — верни insufficient_context=true и не сочиняй.
Каждое утверждение о возможностях продукта помечай источником из блока ФАКТЫ."""

def write_email(lead):
    query = f"{lead['industry']} {lead['role']} возможности продукта интеграции"
    found = search(query)
    if not found or found[0][1] < MIN_SIMILARITY:
        return None, "не нашли релевантных фактов о продукте"

    facts = "\n\n".join(f"[{i+1}] ({c['section']}, {c['source']})\n{c['text']}"
                        for i, (c, s) in enumerate(found))
    resp = client.messages.create(
        model=MODEL, max_tokens=900, temperature=0.7, system=SYSTEM,
        tools=[GROUNDED_DRAFT_TOOL],           # + поля claims[] и insufficient_context
        tool_choice={"type": "tool", "name": "save_draft"},
        messages=[{"role": "user",
                   "content": f"ЛИД:\n{json.dumps(lead, ensure_ascii=False)}\n\nФАКТЫ:\n{facts}"}],
    )
    draft = next(b for b in resp.content if b.type == "tool_use").input
    if draft.get("insufficient_context"):
        return None, "модель сообщила, что фактов недостаточно"

    # Проверка в коде: каждое утверждение о продукте должно ссылаться на источник
    for claim in draft.get("claims", []):
        if not claim.get("source_index"):
            return None, f"утверждение без источника: {claim['text'][:60]}"
    return draft, None


lead = {"company": "NordFin", "industry": "финтех", "role": "Head of Data",
        "trigger": "открыли вакансию ML-инженера"}
draft, why = write_email(lead)
if draft is None:
    print(f"— лид отдан человеку: {why}")     # это правильный исход, а не ошибка
else:
    print(draft["subject"]); print(draft["body"])
    for c in draft["claims"]:
        print(f"  · {c['text']} → источник [{c['source_index']}]")
```

Что здесь важно:

1. **Путь раздела внутри текста куска.** Без него кусок «Включено 5 рабочих мест» не найдётся по запросу про тариф Enterprise.
2. **Порог сходства.** Если лучший кусок ниже порога — базы знаний по этому вопросу просто нет, и генерировать нечего.
3. **Два независимых стоп-сигнала:** флаг от модели и порог в коде. Любой из них останавливает письмо.
4. **Утверждения с источниками.** Письмо, где каждое утверждение о продукте привязано к куску документации, можно проверить за минуту — и именно это спасло бы от «интеграции с 1С».

**Задание.** Возьмите три реальные страницы документации своего продукта, нарежьте, задайте пять вопросов, на которые ответа в них нет, — и убедитесь, что агент во всех пяти случаях отказался писать. Отказ на вопросе, ответа на который нет, — главный признак работающего RAG.

## 📌 Запомнить

- Модель выдумывает не со зла: без факта в контексте она выдаёт статистически правдоподобное утверждение.
- Просьба «не выдумывай» не работает; работает заземление — факт физически в контексте.
- Качество RAG определяется поиском, а не моделью. Отладку начинают с печати найденных кусков.
- Режьте по структуре и кладите путь раздела внутрь куска; храните источник рядом с текстом.
- Порог сходства и флаг `insufficient_context` — два независимых способа сказать «не знаю».
- Утверждение о продукте без ссылки на источник считается браком. Так проверяют письма за минуту.
