## 🏢 Ситуация

Клиент прислал скриншот письма, в котором ему предлагают «продолжить обсуждение внедрения, о котором мы говорили на конференции». Никакой конференции не было. Клиент вежливо интересуется, не перепутали ли его с кем-то.

Игорь пересылает вам. Вы открываете логи и находите:

```
2026-03-14 11:42:07 INFO  outreach lead=lead-8842 status=drafted
2026-03-14 11:42:09 INFO  outreach lead=lead-8842 status=sent
```

Всё. Больше ничего нет. Ни что нашёл сборщик контекста, ни какая версия промпта, ни что вернула модель, ни какие факты подставились из памяти.

Марина спрашивает: «Через сколько ты скажешь, почему так вышло?» Честный ответ — «не скажу»: воспроизвести прогон нельзя, а угадывать по одному письму бессмысленно.

## 🎯 Ваша задача

1. Понять, чем отладка агента отличается от отладки обычного сервиса.
2. Записывать прогон так, чтобы его можно было разобрать через месяц.
3. Научиться воспроизводить конкретный запуск, а не «примерно похожий».

## 📚 Теория

### Почему обычных логов не хватает

Обычный сервис детерминирован: тот же вход даёт тот же выход, и по стеку видно, где сломалось. Агент устроен иначе:

| | Обычный сервис | Агент |
| --- | --- | --- |
| Воспроизводимость | Тот же вход → тот же выход | Тот же вход → другой выход |
| Где ошибка | Видна в стеке | Может быть в любом из 6 шагов |
| Что записать | Вход, выход, исключение | Всю цепочку решений и данные каждого шага |
| Кто «виноват» | Строка кода | Промпт, найденный контекст, память, модель или их сочетание |

Поэтому запись прогона — не «логи для отладки», а **основной инструмент работы**. Без неё каждая жалоба превращается в гадание.

### Что писать в спан

Минимальный набор, без которого разбор невозможен:

- **Идентификаторы:** trace_id прогона, id задачи, lead_id — чтобы связать с жалобой клиента.
- **Вход и выход шага** целиком. Не «нашли 3 документа», а какие именно.
- **Версии:** промпта, модели, схемы инструментов, кода.
- **Метрики:** длительность, токены, стоимость.
- **Решения:** какая ветка выбрана и почему («режим hold, потому что открытая сделка»).

И правило гигиены из A10: персональные данные в трейсах живут по тому же сроку, что и в памяти, и удаляются той же операцией.

### Воспроизведение

Хороший трейс позволяет **переиграть** прогон: взять зафиксированные вход, контекст, версию промпта — и запустить снова. Два режима:

1. **Реплей как есть** — на той же версии, чтобы понять разброс модели.
2. **Реплей с изменением** — на новой версии промпта, чтобы проверить, чинит ли правка эту жалобу.

Второй режим превращает случайную жалобу в кейс golden set (A6) автоматически.

## 💻 Практика

```python
import os, json, time, uuid, contextvars, sqlite3, datetime as dt

trace_db = sqlite3.connect("traces.db", check_same_thread=False)
trace_db.execute("""CREATE TABLE IF NOT EXISTS spans (
    trace_id TEXT, span_id TEXT, parent_id TEXT, name TEXT, started TEXT,
    duration_ms INTEGER, status TEXT, lead_id TEXT,
    input TEXT, output TEXT, meta TEXT)""")
trace_db.execute("CREATE INDEX IF NOT EXISTS idx_trace ON spans(trace_id)")
trace_db.execute("CREATE INDEX IF NOT EXISTS idx_lead ON spans(lead_id)")

_ctx = contextvars.ContextVar("span_ctx", default=(None, None))   # (trace_id, parent_span)


class span:
    """Контекстный менеджер: любой шаг оборачивается в спан."""
    def __init__(self, name, lead_id=None, **meta):
        self.name, self.lead_id, self.meta = name, lead_id, meta
        self.input = self.output = None

    def __enter__(self):
        trace_id, parent = _ctx.get()
        self.trace_id = trace_id or uuid.uuid4().hex
        self.span_id, self.parent = uuid.uuid4().hex[:12], parent
        self.token = _ctx.set((self.trace_id, self.span_id))
        self.t0, self.started = time.monotonic(), dt.datetime.now(dt.timezone.utc).isoformat()
        return self

    def __exit__(self, exc_type, exc, tb):
        _ctx.reset(self.token)
        trace_db.execute(
            "INSERT INTO spans VALUES (?,?,?,?,?,?,?,?,?,?,?)",
            (self.trace_id, self.span_id, self.parent, self.name, self.started,
             int((time.monotonic() - self.t0) * 1000),
             "error" if exc else "ok", self.lead_id,
             json.dumps(self.input, ensure_ascii=False, default=str)[:20000],
             json.dumps(self.output, ensure_ascii=False, default=str)[:20000],
             json.dumps({**self.meta, "error": repr(exc) if exc else None},
                        ensure_ascii=False, default=str)))
        trace_db.commit()
        return False        # исключение не глотаем


# --- Использование: оборачиваем шаги, а не только вызовы модели ---
def handle_outreach_traced(lead, campaign_id):
    with span("outreach", lead_id=lead["id"], campaign=campaign_id) as root:
        root.input = lead
        with span("collect_context", lead_id=lead["id"]) as s:
            s.output = ctx = collect_context(lead)                    # A7
        with span("recall_memory", lead_id=lead["id"]) as s:
            s.output = memory = recall(lead["id"])                    # A10
        with span("write_email", lead_id=lead["id"],
                  prompt_version=PROMPT_VERSION, model=MODELS["large"]) as s:
            s.input = {"context": ctx, "memory": memory}              # ровно то, что ушло в модель
            resp = build_email(lead, memory, ctx)                     # A12
            s.output = draft = next(b for b in resp.content if b.type == "tool_use").input
            s.meta["tokens"] = {"in": resp.usage.input_tokens, "out": resp.usage.output_tokens}
        root.output = {"subject": draft["subject"]}
        return draft


# --- Разбор жалобы: найти прогон по клиенту и посмотреть цепочку ---
def explain(lead_id, date=None):
    rows = trace_db.execute(
        "SELECT trace_id, name, duration_ms, status, input, output, meta FROM spans "
        "WHERE lead_id = ? ORDER BY started DESC LIMIT 20", (lead_id,)).fetchall()
    for trace_id, name, ms, status, inp, out, meta in rows:
        print(f"[{status}] {name} · {ms} мс · {json.loads(meta)}")
        if name == "recall_memory":
            print("   факты в контексте:", json.loads(out))     # вот где нашлась «конференция»
        if name == "write_email":
            print("   версия промпта:", json.loads(meta).get("prompt_version"))


# --- Реплей: тот же вход, новая версия промпта ---
def replay(trace_id, prompt_version=None):
    row = trace_db.execute(
        "SELECT input, meta FROM spans WHERE trace_id=? AND name='write_email'",
        (trace_id,)).fetchone()
    saved_input, saved_meta = json.loads(row[0]), json.loads(row[1])
    version = prompt_version or saved_meta["prompt_version"]
    return regenerate(saved_input["context"], saved_input["memory"], version)


# --- Жалоба превращается в кейс golden set автоматически ---
def promote_to_golden(trace_id, name, expectation):
    row = trace_db.execute("SELECT input FROM spans WHERE trace_id=? AND name='outreach'",
                           (trace_id,)).fetchone()
    case = {"name": name, "lead": json.loads(row[0]), "expect": expectation, "from_trace": trace_id}
    cases = json.load(open("checks/golden_set.json", encoding="utf-8"))
    cases.append(case)
    json.dump(cases, open("checks/golden_set.json", "w", encoding="utf-8"),
              ensure_ascii=False, indent=2)
```

Как это меняет разбор жалобы:

1. **`explain(lead_id)` показывает цепочку за секунды.** В нашем случае в спане `recall_memory` виден факт «встреча на конференции» — дальше вопрос уже к тому, откуда он взялся, а не к промпту.
2. **В спане `write_email` записан ровно тот контекст**, который ушёл в модель. Не приблизительный — тот самый.
3. **`replay(trace_id, "v4")`** проверяет, чинит ли новая версия промпта конкретно эту жалобу.
4. **`promote_to_golden`** превращает инцидент в постоянный кейс — ровно та механика, о которой шла речь в A6.

## 📌 Запомнить

- Агент недетерминирован: обычных логов «вход-выход» не хватает, нужна вся цепочка решений.
- Трейс — дерево спанов; в спане записывают вход, выход, версии, метрики и принятое решение.
- Оборачивают все шаги, а не только вызовы модели: виноват часто поиск или память.
- Записанный контекст должен быть точным, а не приблизительным, иначе воспроизведение бессмысленно.
- Реплей с новой версией промпта отвечает на вопрос «чинит ли правка именно эту жалобу».
- Персональные данные в трейсах живут по тем же правилам, что в памяти, и удаляются вместе с ней.
