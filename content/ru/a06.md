# Модуль A6. Откуда вы знаете, что оно работает

> **Уровень:** Junior AI · **Время:** ~55 минут · **Формат:** ситуация → теория → практика → квиз

---

## 🏢 Ситуация

Марина зовёт вас на разговор. На столе — распечатка:

> «Месяц назад ты обещал: доля черновиков без правок. Игорь говорит "вроде получше". Даша говорит "стало суше". Ты говоришь "модель поменяли, должно быть лучше". Никто из вас не назвал ни одного числа. Мы принимаем решения по ощущениям трёх человек — при том что у нас в компании двадцать дата-сайентистов, которые за такое на ревью убивают.»

Она права, и это неприятно. В ML-треке вы никогда бы не выкатили модель без офлайн-метрики на отложенной выборке. Здесь вы месяц меняли промпты и модели, глядя на пять писем.

## 🎯 Ваша задача

1. Собрать golden set — размеченный набор, на котором меряют качество.
2. Научиться оценивать то, что не сводится к одному правильному ответу.
3. Сделать так, чтобы «стало лучше» превратилось в число, которое можно показать Марине.

## 📚 Теория

### Три уровня проверок

| Уровень | Что проверяет | Стоимость | Когда гонять |
| --- | --- | --- | --- |
| Детерминированные проверки | Длина, стоп-слова, наличие вопроса, схема | Бесплатно, миллисекунды | На каждый ответ в проде |
| LLM-as-judge | Тон, релевантность, обоснованность фактами | Копейки, секунды | На каждое изменение промпта |
| Человек | Спорные случаи, калибровка судьи | Дорого, минуты | Раз в неделю, на выборке |

Ошибка новичка — прыгнуть сразу к третьему уровню («покажем Игорю двадцать писем») или застрять на первом («длина в порядке, значит, всё хорошо»). Работает связка: код ловит грубое, судья — качественное, человек калибрует судью.

### Golden set: что это и откуда берётся

Это набор входов с **эталонными свойствами** выхода. Не эталонный текст (двух одинаковых писем не бывает), а именно свойства: должен упомянуть событие лида, не должен обещать цену, должен закончиться вопросом.

Откуда брать:

1. **Из реальных данных** — 30–50 строк CRM разного качества, включая мусорные.
2. **Из инцидентов** — каждый случай «письмо ушло не такое» становится кейсом навсегда. Это самая ценная часть набора.
3. **Из крайних случаев** — очень длинное название компании, отсутствующее событие, экзотическая отрасль.

Пятьдесят кейсов достаточно, чтобы ловить регрессии. Тысяча не нужна.

Ещё две ловушки: судья склонен хвалить длинные ответы и ответы, сгенерированные той же моделью, что судит. Лечится сравнением пар в случайном порядке и явным критерием.

### Что мерить в нашем случае

- **Обоснованность** (доля утверждений с источником) — детерминированно, из A5.
- **Соблюдение запретов** (нет цены, нет выдумки) — код + судья.
- **Персонализация** (зацепка связана с событием лида) — судья.
- **Прокси-метрика продукта** — доля черновиков, отправленных Игорем без правок. Единственное настоящее число, но приходит с задержкой.

Офлайн-метрики нужны, чтобы не ждать неделю. Продуктовая метрика решает, кто прав.

## 💻 Практика

```python
# pip install anthropic
import os, json, random, statistics, anthropic

client = anthropic.Anthropic(api_key=os.environ["ANTHROPIC_API_KEY"])
JUDGE_MODEL = "claude-sonnet-5"

JUDGE_TOOL = {
    "name": "verdict",
    "description": "Вердикт по одному критерию",
    "input_schema": {
        "type": "object",
        "properties": {
            "answer": {"type": "string", "enum": ["yes", "no", "unclear"]},
            "evidence": {"type": "string", "description": "Цитата из письма, обосновывающая вердикт"},
        },
        "required": ["answer", "evidence"],
    },
}

CRITERIA = {
    "grounded": "Все утверждения о продукте подтверждаются блоком ФАКТЫ? "
                "Ответь no, если есть хоть одно утверждение, которого нет в фактах.",
    "personalized": "Зацепка письма опирается на конкретное событие из данных лида "
                    "(а не на общие слова об отрасли)?",
    "no_price": "Письмо свободно от упоминаний цен, скидок и сроков?",
}

def judge(criterion_key, email, context):
    resp = client.messages.create(
        model=JUDGE_MODEL, max_tokens=300, temperature=0,
        system="Ты строгий проверяющий. Отвечай по одному критерию. Всегда вызывай verdict. "
               "Если сомневаешься — unclear, это не стыдно.",
        tools=[JUDGE_TOOL], tool_choice={"type": "tool", "name": "verdict"},
        messages=[{"role": "user", "content":
                   f"КРИТЕРИЙ: {CRITERIA[criterion_key]}\n\nКОНТЕКСТ:\n{context}\n\nПИСЬМО:\n{email}"}],
    )
    return next(b for b in resp.content if b.type == "tool_use").input


def evaluate(golden_set, generate_fn):
    """Прогон набора: детерминированные проверки + судья по каждому критерию."""
    scores = {k: [] for k in CRITERIA}
    hard_fails = []
    for case in golden_set:
        draft, ctx = generate_fn(case["lead"])
        if draft is None:
            hard_fails.append((case["name"], "отказ генерации"))
            continue
        problems = hard_checks(draft, case["lead"])       # из A4
        if problems:
            hard_fails.append((case["name"], ", ".join(problems)))
        for key in CRITERIA:
            v = judge(key, draft["body"], ctx)
            scores[key].append(1 if v["answer"] == "yes" else 0)
    report = {k: round(statistics.mean(v), 3) if v else None for k, v in scores.items()}
    return report, hard_fails


# --- Калибровка судьи: без неё числам верить нельзя ---
def calibrate(labeled):
    """labeled: [{email, context, criterion, human: 'yes'|'no'}] — 20 случаев, размеченных руками."""
    agree = sum(1 for x in labeled
                if judge(x["criterion"], x["email"], x["context"])["answer"] == x["human"])
    rate = agree / len(labeled)
    print(f"согласие судьи с человеком: {rate:.0%}")
    if rate < 0.8:
        print("  ⚠ судья ненадёжен — уточните формулировку критерия перед использованием")
    return rate


if __name__ == "__main__":
    golden = json.load(open("checks/golden_set.json", encoding="utf-8"))
    report, fails = evaluate(golden, write_email)      # write_email из A5
    print("Метрики:", report)
    print("Жёсткие провалы:", len(fails))
    for name, why in fails[:5]:
        print(f"  ✗ {name}: {why}")
```

Как это использовать:

1. **Перед каждым изменением** промпта или модели — прогон на golden set. Числа записываются рядом с версией промпта.
2. **Сравнение версий** — не «стало лучше», а «grounded 0.82 → 0.94, personalized 0.71 → 0.69». Видно и улучшение, и цену за него.
3. **Калибровка судьи** — раз в месяц и после каждой смены модели судьи.
4. **Инцидент → кейс.** Каждое плохое письмо от Игоря добавляется в набор с именем. Набор растёт вместе с вашим пониманием продукта.

**Задание.** Соберите golden set из 20 кейсов (10 обычных, 5 крайних, 5 из реальных жалоб). Прогоните текущую версию, запишите числа. Затем ухудшите промпт намеренно — уберите строку про запрет цен — и убедитесь, что метрика это поймала. Если не поймала, ваш набор ещё не работает.

## 📌 Запомнить

- «Вроде получше» — не результат. Результат — число на фиксированном наборе.
- Golden set фиксирует свойства выхода, а не эталонный текст. Пятидесяти кейсов достаточно.
- Каждый инцидент превращается в кейс навсегда — так набор становится памятью команды.
- LLM-судья работает при четырёх условиях: один критерий, короткая шкала, сравнение пар, калибровка.
- Некалиброванный судья — это измерение шума. Меряйте согласие с человеком, прежде чем верить числам.
- Офлайн-метрики нужны для скорости, продуктовая метрика — для правоты. Нужны обе.
