# Модуль A3. Симулятор входящих: агент разбирает ответы на рассылку

> **Уровень:** Junior AI · **Время:** ~55 минут · **Формат:** ситуация → теория → практика → квиз

---

## 🏢 Ситуация

Прошло десять дней. Агент пишет черновики, Игорь отправляет. И вот приходит то, ради чего всё затевалось: **ответы**.

За неделю — 180 писем. Игорь открывает почту и звереет:

> «Смотри, что тут: три реальных "давайте созвонимся", два "уберите меня из рассылки" — и сто семьдесят пять автоответов "я в отпуске до 14-го". Я трачу час в день, чтобы найти три письма, которые важны. Раньше я хотя бы знал, кому пишу.»

Марина спрашивает на планёрке: «А агент не может сам разобрать входящие?»

Может. И это **другая задача**, чем письмо: тут нет творчества, тут нужна одинаковость. Одинаковое письмо обязано всегда попадать в одну и ту же категорию — иначе Игорь перестанет доверять папкам.

## 🎯 Ваша задача

1. Классифицировать входящие: интерес, отказ, отписка, автоответ, «не тот человек», мусор.
2. Извлечь из письма факты, которые нужны CRM: когда вернётся, кого рекомендует вместо себя, какие возражения.
3. Смаршрутизировать: что показать Игорю сегодня, что положить в CRM, что не показывать никогда.

---

## 📚 Теория

### Классификация — это не генерация

| | Черновик письма (A2) | Разбор входящих (A3) |
| --- | --- | --- |
| Температура | 0.7 — разнообразие полезно | **0** — одинаковость обязательна |
| Выход | Свободный текст в схеме | Строгий enum из фиксированного списка |
| Цена ошибки | Человек поправит перед отправкой | Письмо ушло не в ту папку и потерялось |
| Как мерить | Доля правок | Точность по категориям на размеченном наборе |

Главное правило: **список категорий закрыт и описан в схеме как enum**. «Придумай подходящую категорию» — это гарантированный зоопарк из «Интерес», «интересно», «Interested», «возможно интерес».

### Категории проектируются от действия, а не от смысла

Плохой список категорий описывает оттенки чувств. Хороший — описывает, **что после этого произойдёт**:

| Категория | Что делает система | Кто видит |
| --- | --- | --- |
| `interested` | В топ списка Игоря, пометка в CRM | Игорь, сегодня |
| `not_now` | Дата возврата в CRM, напоминание | Игорь, в дату |
| `wrong_person` | Достаём рекомендованный контакт | Игорь, сегодня |
| `unsubscribe` | **Немедленно** в стоп-лист | Никто, но обязательно логируется |
| `auto_reply` | Тихо в архив | Никто |
| `other` | Ручная разборка | Игорь, раз в неделю |

Категория `other` обязательна. Без неё модель будет впихивать странное письмо в ближайшую категорию — и вы об этом не узнаете.

Отсюда практическое правило: **для дорогих категорий понижаем порог**. Если модель хоть немного считает письмо отпиской — это отписка. Потерять один тёплый лид дешевле, чем нарушить прямую просьбу человека.

### Few-shot: примеры сильнее объяснений

Описать словами разницу между «мне сейчас не до этого, напишите в марте» (`not_now`) и «нам это не нужно» (`rejected`) можно, но три примера в промпте работают лучше двух абзацев инструкций. Берите примеры из реальной почты — особенно **пограничные**, на которых модель ошибалась.

## 💻 Практика

```python
# pip install anthropic
import os, json, anthropic

client = anthropic.Anthropic(api_key=os.environ["ANTHROPIC_API_KEY"])
MODEL = "claude-sonnet-5"

CATEGORIES = ["interested", "not_now", "rejected", "wrong_person",
              "unsubscribe", "auto_reply", "other"]

TRIAGE_TOOL = {
    "name": "triage",
    "description": "Разобрать входящее письмо и вернуть решение",
    "input_schema": {
        "type": "object",
        "properties": {
            "category": {"type": "string", "enum": CATEGORIES},   # закрытый список
            "confidence": {"type": "number", "description": "0..1, уверенность в категории"},
            "return_date": {"type": ["string", "null"], "description": "ISO-дата, если просят написать позже"},
            "referred_contact": {"type": ["string", "null"], "description": "Кого рекомендуют вместо себя"},
            "objection": {"type": ["string", "null"], "description": "Возражение одной фразой, если есть"},
            "reason": {"type": "string", "description": "Почему выбрана эта категория, одно предложение"},
        },
        "required": ["category", "confidence", "reason"],
    },
}

# Пограничные примеры важнее объяснений
SYSTEM = """Ты разбираешь ответы на исходящую рассылку B2B. Всегда вызывай triage.

Примеры:
"Спасибо, интересно, но давайте в марте — сейчас закрываем квартал" → not_now, return_date март
"Я не занимаюсь этим, напишите Анне Ковалёвой, она у нас за данные" → wrong_person
"Отпишите меня" / "stop" / "не пишите больше" → unsubscribe
"Я в отпуске до 14 октября, пишите после" → auto_reply (это автоответ, не интерес!)
"У нас уже есть похожее решение, мы довольны" → rejected, objection про существующее решение
Если письмо не подходит ни к одной категории — other. Не выдумывай новые категории."""


def triage(email_text):
    resp = client.messages.create(
        model=MODEL, max_tokens=500,
        temperature=0,                    # одинаковое письмо — одинаковая категория
        system=SYSTEM, tools=[TRIAGE_TOOL],
        tool_choice={"type": "tool", "name": "triage"},
        messages=[{"role": "user", "content": email_text}],
    )
    return next(b for b in resp.content if b.type == "tool_use").input


# Асимметрия ошибок: отписку не «угадываем», а перестраховываемся
UNSUB_HINTS = ("отпиш", "unsubscribe", "не пишите", "stop", "удалите меня")

def route(email_text, result):
    text = email_text.lower()
    if any(h in text for h in UNSUB_HINTS) or result["category"] == "unsubscribe":
        return "STOP_LIST", "отписка — в стоп-лист немедленно"
    if result["confidence"] < 0.6:
        return "MANUAL", f"низкая уверенность ({result['confidence']:.2f}) — на ручную разборку"
    return {
        "interested":  ("TODAY", "показать Игорю сегодня"),
        "wrong_person": ("TODAY", "достать рекомендованный контакт"),
        "not_now":     ("CRM", "поставить напоминание на дату возврата"),
        "rejected":    ("CRM", "записать возражение и закрыть"),
        "auto_reply":  ("ARCHIVE", "тихо в архив"),
        "other":       ("MANUAL", "недельная разборка"),
    }[result["category"]]


INBOX = [
    "Здравствуйте! Интересно, расскажите подробнее. Можем созвониться в четверг?",
    "Я в отпуске до 14 октября. По срочным вопросам — к Марине.",
    "Отпишите меня от рассылки, пожалуйста.",
    "Спасибо, но я этим не занимаюсь. Напишите Анне Ковалёвой, она у нас за данные.",
]

for text in INBOX:
    r = triage(text)
    bucket, why = route(text, r)
    extra = r.get("referred_contact") or r.get("return_date") or ""
    print(f"[{bucket:8}] {r['category']:12} conf={r['confidence']:.2f} · {why}")
    if extra:
        print(f"           извлечено: {extra}")
```

Что здесь важно:

1. **`enum` в схеме закрывает список категорий.** Модель физически не может вернуть «возможно интерес».
2. **`temperature=0`** — тот же текст всегда даёт ту же категорию. Иначе Игорь увидит, что вчерашнее письмо лежало в другой папке, и перестанет доверять системе.
3. **Отписка обрабатывается вне модели.** Простая проверка по словам плюс решение модели: срабатывает любое из двух. Это тот случай, когда перестраховка дешевле точности.
4. **Порог уверенности** отправляет сомнительные письма человеку вместо тихой ошибки.
5. **Извлечение вместе с классификацией.** Один вызов даёт и категорию, и дату возврата, и рекомендованный контакт — не нужно вызывать модель дважды.

**Задание.** Возьмите 20 реальных (или придуманных) ответов, разметьте их руками, прогоните через агента и посчитайте: сколько совпало, где ошибся, и попала ли хоть одна отписка не в стоп-лист. Последнее число должно быть нулём — если нет, чините правило, а не промпт.

## 📌 Запомнить

- Классификация — задача про одинаковость: температура 0 и закрытый `enum`, а не свободный текст.
- Категории проектируют от действия системы, а не от оттенка смысла. Категория `other` обязательна.
- Ошибки классификации стоят по-разному: систему настраивают так, чтобы она ошибалась в дешёвую сторону.
- Отписку не угадывают. Дублируйте проверку простым правилом вне модели.
- Порог уверенности — дешёвый способ превратить тихую ошибку в задачу для человека.
- Пограничные примеры в промпте работают лучше, чем абзац объяснений.
