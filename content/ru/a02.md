# Модуль A2. Первый агент: черновик письма из строки CRM

> **Уровень:** Junior AI · **Время:** ~50 минут · **Формат:** ситуация → теория → практика → квиз

---

## 🏢 Ситуация

Design Doc подписан. Марина дала две недели на первый срез: **20 черновиков писем в день, отправляет человек**.

Игорь, Head of Sales, приносит выгрузку из CRM — 340 строк. Компания, отрасль, роль, дата последнего события. Он смотрит на вас с недоверием:

> «Мой SDR тратит на письмо 12 минут. Если твоя штука будет писать мусор, я потрачу больше времени на правки, чем написал бы сам. И ещё: у нас в CRM есть строки, где вместо должности стоит "n/a", а вместо компании — "ООО". Что тогда?»

Хороший вопрос. Он про то, что отличает демо от системы: **демо работает на красивой строке, система — на всех 340**.

## 🎯 Ваша задача

1. Собрать агента, который из одной строки CRM делает черновик письма.
2. Получить от модели не текст, а **структуру**, с которой сможет работать следующий шаг конвейера.
3. Пережить плохие данные, сетевые сбои и «творчество» модели, не уронив всю пачку.

---

## 📚 Теория

### Что делает LLM агентом, а не текстовым генератором

Три вещи, которых нет у «просто промпта»:

1. **Инструменты** — модель может вызвать вашу функцию (поиск по CRM, проверка домена) и получить результат.
2. **Цикл** — она видит результат вызова и решает, что делать дальше.
3. **Контракт на выход** — результат приходит в формате, который читает код, а не человек.

Сегодня мы строим самый простой вариант: один вызов, жёсткий контракт на выход, без цикла. Это не «ненастоящий агент» — это правильная первая ступень. Цикл добавим в A7, когда будет что зацикливать.

### Структурированный вывод: контракт вместо надежды

Свободный текст от модели невозможно передать дальше по конвейеру. «Вот письмо, надеюсь, тема на первой строке» — это не интеграция.

| Подход | Что происходит при сбое | Годится в прод |
| --- | --- | --- |
| Просить текст и парсить регуляркой | Модель поменяла формулировку — парсер молча сломался | Нет |
| Просить JSON в промпте | Иногда приходит с преамбулой «Конечно! Вот JSON:» | С проверкой — да |
| Tool calling со схемой | Модель обязана заполнить поля схемы | Да |

**Tool calling** — это не только «сходить в API». Это ещё и способ заставить модель отвечать по схеме: вы описываете функцию `save_draft(subject, body, self_check)`, модель её «вызывает», а вы просто читаете аргументы. Схему проверяет провайдер, а не ваша регулярка.

### Плохие данные — это норма, а не исключение

Игорь прав насчёт «n/a» и «ООО». Правило: **фильтруйте до модели, а не после**. Проверка обязательных полей стоит доли миллисекунды, вызов модели — секунды и деньги. Строка без роли и без события не даст персонализации — её честнее пропустить, чем получить письмо «Здравствуйте, n/a!».

### Ретраи: что повторять, а что нет

| Ошибка | Повторять? | Почему |
| --- | --- | --- |
| Таймаут, 429, 5xx | Да, с экспоненциальной паузой | Временная проблема на той стороне |
| Модель вернула невалидную схему | Да, один раз | Бывает; второй раз — уже симптом промпта |
| 401, неверный ключ | Нет | Повтор ничего не изменит |
| Строка не прошла валидацию | Нет | Данные не станут лучше от повтора |

И главное: один сбойный лид не должен ронять пачку из 340. Ошибку ловим на уровне одной единицы работы.

## 💻 Практика

```python
# pip install anthropic
import os, time, json, anthropic

client = anthropic.Anthropic(api_key=os.environ["ANTHROPIC_API_KEY"])
MODEL = "claude-sonnet-5"

# Контракт на выход: модель обязана заполнить эти поля
DRAFT_TOOL = {
    "name": "save_draft",
    "description": "Сохранить черновик письма лиду",
    "input_schema": {
        "type": "object",
        "properties": {
            "subject": {"type": "string", "description": "Тема, до 60 символов"},
            "body": {"type": "string", "description": "Тело письма, до 120 слов"},
            "personalization": {"type": "string", "description": "Конкретная причина, почему пишем именно им"},
            "self_check": {
                "type": "object",
                "properties": {
                    "invented_facts": {"type": "boolean"},
                    "mentions_price": {"type": "boolean"},
                    "has_question": {"type": "boolean"},
                },
                "required": ["invented_facts", "mentions_price", "has_question"],
            },
        },
        "required": ["subject", "body", "personalization", "self_check"],
    },
}

SYSTEM = """Ты пишешь первое холодное письмо от лица Datacore — платформы для команд,
внедряющих ML в продукт. Всегда вызывай инструмент save_draft.

ЗАПРЕТЫ: не называй цены и сроки; не выдумывай факты о получателе; не более 120 слов.
ОБЯЗАТЕЛЬНО: одна конкретная причина, почему пишешь именно им, и один вопрос в конце."""


def usable(lead):
    """Фильтруем до модели: без роли и события персонализации не будет."""
    if not lead.get("company") or len(lead["company"]) < 3:
        return False, "нет названия компании"
    if not lead.get("role") or lead["role"].lower() in {"n/a", "-", "unknown"}:
        return False, "нет должности"
    if not lead.get("trigger"):
        return False, "нет события для зацепки"
    return True, None


def draft_for(lead, attempts=3):
    for attempt in range(1, attempts + 1):
        try:
            resp = client.messages.create(
                model=MODEL, max_tokens=800, temperature=0.7, system=SYSTEM,
                tools=[DRAFT_TOOL], tool_choice={"type": "tool", "name": "save_draft"},
                messages=[{"role": "user", "content": json.dumps(lead, ensure_ascii=False)}],
            )
            block = next(b for b in resp.content if b.type == "tool_use")
            return block.input, resp.usage
        except anthropic.APIStatusError as e:
            if e.status_code in (429, 500, 502, 503, 529) and attempt < attempts:
                time.sleep(2 ** attempt)   # экспоненциальная пауза
                continue
            raise
        except StopIteration:
            if attempt < attempts:
                continue               # модель не вызвала инструмент — пробуем ещё раз
            raise RuntimeError("модель не вернула черновик по схеме")


LEADS = [
    {"company": "NordFin", "industry": "финтех", "role": "Head of Data",
     "trigger": "открыли вакансию ML-инженера"},
    {"company": "ООО", "industry": "", "role": "n/a", "trigger": ""},   # мусорная строка Игоря
]

ok_count = skipped = failed = 0
for lead in LEADS:
    fine, why = usable(lead)
    if not fine:
        skipped += 1
        print(f"— пропуск {lead.get('company')!r}: {why}")
        continue
    try:
        draft, usage = draft_for(lead)
    except Exception as e:                 # один плохой лид не роняет пачку
        failed += 1
        print(f"✗ {lead['company']}: {e}")
        continue
    c = draft["self_check"]
    if c["invented_facts"] or c["mentions_price"] or not c["has_question"]:
        failed += 1
        print(f"✗ {lead['company']}: не прошёл самопроверку {c}")
        continue
    ok_count += 1
    print(f"✓ {lead['company']} · {draft['subject']}")
    print(f"  зацепка: {draft['personalization']}")

print(f"\nИтог: готово {ok_count}, пропущено {skipped}, брак {failed}")
```

Что здесь важно:

1. **`tool_choice` заставляет модель вызвать инструмент.** Мы не парсим текст и не надеемся на JSON — схему проверяет провайдер.
2. **Валидация до модели.** Мусорная строка Игоря не доходит до платного вызова и не превращается в письмо «Здравствуйте, n/a».
3. **Ретраятся только временные ошибки**, с растущей паузой. Ошибку схемы повторяем один раз — дальше это симптом плохого промпта, а не невезения.
4. **Счётчики готово/пропущено/брак.** Это первая версия вашей метрики качества: если «брак» растёт — виноват промпт, если «пропущено» — данные в CRM.

**Задание.** Прогоните 10 строк из своей выгрузки (или придумайте их). Посчитайте, сколько отсеялось на валидации и сколько не прошло самопроверку. Ответьте на вопрос Игоря числом: сколько писем из 20 придётся переписывать руками?

## 📌 Запомнить

- Первый агент — это один вызов с жёстким контрактом на выход, а не автономный цикл.
- Просить JSON в промпте можно, но заставить моделью вызвать инструмент со схемой — надёжнее.
- Температура выбирается по цене разнообразия: 0 там, где результат читает код; выше — там, где читает человек и выбирает.
- Фильтруйте плохие строки до вызова модели: это дешевле, быстрее и честнее.
- Ретраи — только для временных ошибок. Неверный ключ и плохие данные повтором не лечатся.
- Ошибка на одном лиде не должна ронять пачку. Единица работы — единица отказа.
