## 🏢 Ситуация

Research-система Datacore теперь ходит в шесть MCP-серверов. Даша довольна охватом, но приносит два наблюдения, которые вы обязаны объяснить.

**Наблюдение первое.** «Иногда она пересказывает содержимое сайта так, будто это наш внутренний документ, с номерами страниц.» Смотрите список инструментов. Две записи:

```
analyze_content  — "Analyzes content and returns key findings."
analyze_document — "Analyzes a document and returns key findings."
```

Первый — про веб-страницы, второй — про PDF из внутреннего архива. Различить их по описанию невозможно даже человеку. Модель выбирает почти случайно.

Дальше хуже. `analyze_document` умеет три разные вещи: вытащить показатели, сделать саммари и проверить утверждение по источнику. Одно имя, три задачи, один невнятный контракт на выходе.

И совсем рядом — третья деталь: в системном промпте написано «при работе с документами обязательно уточняй детали». Слово «документ» в этой фразе перетягивает на `analyze_document` даже запросы про веб-страницы, потому что модель ловит ключевое слово раньше, чем читает описания.

**Наблюдение второе.** «Она подолгу зависает, а потом пишет, что не смогла.» В логах — один и тот же ответ от всех инструментов при любой проблеме:

```
{"error": "Operation failed"}
```

Агент видит это и делает единственное, что может: повторяет вызов. Пять раз подряд. При этом в трёх случаях из пяти повтор бессмыслен: у клиента нет прав на архив, а это не изменится ни через секунду, ни через час.

## 🎯 Ваша задача

1. Переписать описания так, чтобы выбор инструмента перестал быть лотереей.
2. Разрезать универсальный `analyze_document` на инструменты с чёткими контрактами.
3. Сделать ошибки структурированными: чтобы агент понимал, что повторять, а что — объяснять клиенту.

## 📚 Теория

### Описание — это интерфейс выбора

Главный тезис домена: **описание инструмента — основной механизм, по которому модель выбирает инструмент**. Не имя, не схема параметров, а именно описание. Минимальные описания приводят к ненадёжному выбору среди похожих инструментов.

Что обязано быть в описании:

- **назначение** — что инструмент делает и, главное, чего не делает;
- **формат входа** — что именно принимает (URL веб-страницы? идентификатор документа? свободный текст?);
- **примеры запросов** — один-два типичных;
- **краевые случаи** — что вернётся, если ничего не найдено;
- **границу с соседями** — «в отличие от `X`, используйте это, когда…».

И отдельный пункт, который легко пропустить: **системный промпт способен перебить хорошие описания**. Фраза «при работе с документами уточняй детали» создаёт ассоциацию по ключевому слову. Экзамен требует навыка **пересматривать системные промпты на предмет таких формулировок** — то есть при разборе неверной маршрутизации смотреть не только на описания, но и на промпт.

### Ошибка — это тоже интерфейс

Второе наблюдение Даши — про то, что агент не может принять разумное решение, потому что все ошибки на вид одинаковые. Гайд формулирует прямо: **единообразные ответы вида «Operation failed» мешают агенту выбрать правильное восстановление**.

Категории ошибок, которые нужно различать:

| Категория | Примеры | Повторять? |
| --- | --- | --- |
| `transient` | таймаут, сервис недоступен, 503 | да, с задержкой |
| `validation` | неверный формат id, отсутствует обязательное поле | нет — исправить вход |
| `business` | нарушение политики, лимит превышен | нет — объяснить клиенту |
| `permission` | нет прав на архив | нет — эскалация или запрос доступа |

Формат ответа MCP на ошибку строится вокруг флага **`isError`** и структурированных метаданных:

```json
{
  "isError": true,
  "errorCategory": "permission",
  "isRetryable": false,
  "message": "Нет доступа к архиву юр. документов",
  "customerMessage": "Этот документ доступен только сотрудникам юридического отдела."
}
```

Поле `isRetryable` экономит буквально деньги: агент не тратит пять попыток на то, что не изменится. Поле `customerMessage` нужно для бизнес-ошибок — чтобы агент объяснил человеку причину нормальным языком, а не пересказал техническую ошибку.

### Два тонких различия

**Локальное восстановление против проброса.** Транзиентную ошибку субагент чинит сам: повторил, получилось, пошёл дальше. Наверх, координатору, уходит только то, **что не удалось решить локально** — вместе с частичным результатом и описанием, что уже было предпринято. Иначе координатор получает поток шума и не может отличить настоящую проблему от икоты сети.

**Отказ доступа против пустого результата.** Это разные вещи, и путать их дорого:

```
{"isError": true, "errorCategory": "permission"}   ← не смогли посмотреть
{"results": [], "total": 0}                        ← посмотрели, ничего нет
```

Первое требует решения (повторить? эскалировать?), второе — валидный успешный ответ, и агент должен спокойно сказать «ничего не найдено». Инструмент, возвращающий ошибку на пустой результат, заставляет агента искать несуществующую проблему.

## 💻 Практика

MCP-инструменты с внятными описаниями и структурированными ошибками. Обратите внимание на длину описаний — это не многословие, это интерфейс.

```python
# pip install anthropic
import os, json, time, anthropic

client = anthropic.Anthropic(api_key=os.environ["ANTHROPIC_API_KEY"])
MODEL = "claude-sonnet-5"

TOOLS = [
    {
        "name": "extract_web_results",
        "description": (
            "Извлекает факты из ПУБЛИЧНОЙ ВЕБ-СТРАНИЦЫ по её URL. "
            "Вход: полный http(s)-адрес страницы. Выход: список объектов "
            "{claim, quote, source_url}. "
            "Пример: extract_web_results(url='https://example.com/pricing') → тарифы конкурента. "
            "Если страница недоступна — вернёт isError с категорией. Если фактов нет — "
            "вернёт пустой список results, это НЕ ошибка. "
            "В отличие от extract_data_points, работает только с веб-страницами "
            "и не имеет доступа к внутреннему архиву компании."
        ),
        "input_schema": {"type": "object", "properties": {"url": {"type": "string"}}, "required": ["url"]},
    },
    {
        "name": "extract_data_points",
        "description": (
            "Извлекает числовые показатели из ВНУТРЕННЕГО ДОКУМЕНТА архива по его идентификатору. "
            "Вход: doc_id формата DOC-XXXX. Выход: список {metric, value, unit, page}. "
            "Пример: extract_data_points(doc_id='DOC-1042') → выручка по кварталам со страницами. "
            "Используйте, когда нужны ЦИФРЫ из документа. "
            "Для пересказа документа используйте summarize_content, "
            "для проверки конкретного утверждения — verify_claim_against_source, "
            "для веб-страниц — extract_web_results."
        ),
        "input_schema": {"type": "object", "properties": {"doc_id": {"type": "string"}}, "required": ["doc_id"]},
    },
    {
        "name": "summarize_content",
        "description": (
            "Возвращает краткое изложение внутреннего документа по doc_id. "
            "Выход: {summary, key_topics[]}. Цифры не извлекает — для этого extract_data_points."
        ),
        "input_schema": {"type": "object", "properties": {"doc_id": {"type": "string"}}, "required": ["doc_id"]},
    },
    {
        "name": "verify_claim_against_source",
        "description": (
            "Проверяет КОНКРЕТНОЕ утверждение по конкретному документу. "
            "Вход: claim (текст утверждения) и doc_id. "
            "Выход: {verdict: supported|contradicted|not_found, evidence, page}. "
            "Используйте для фактчекинга, а не для извлечения новых данных."
        ),
        "input_schema": {"type": "object",
                         "properties": {"claim": {"type": "string"}, "doc_id": {"type": "string"}},
                         "required": ["claim", "doc_id"]},
    },
]

def mcp_error(category: str, message: str, retryable: bool, customer: str | None = None):
    err = {"isError": True, "errorCategory": category, "isRetryable": retryable, "message": message}
    if customer:
        err["customerMessage"] = customer
    return err

CALLS = {"extract_data_points": 0}

def run_tool(name, args):
    if name == "extract_web_results":
        if not args["url"].startswith("http"):
            return mcp_error("validation", "url должен начинаться с http(s)://", retryable=False)
        return {"results": []}          # валидный пустой результат, не ошибка

    if name == "extract_data_points":
        CALLS["extract_data_points"] += 1
        if args["doc_id"] == "DOC-9000":
            return mcp_error("permission", "Нет доступа к архиву юр. документов", retryable=False,
                             customer="Этот документ доступен только сотрудникам юридического отдела.")
        if CALLS["extract_data_points"] == 1:
            return mcp_error("transient", "Таймаут архива (503)", retryable=True)
        return {"results": [{"metric": "выручка Q3", "value": 12.4, "unit": "млн", "page": 12}]}

    if name in ("summarize_content", "verify_claim_against_source"):
        return {"summary": "…", "key_topics": ["цены", "рынок"]}
    return mcp_error("validation", f"неизвестный инструмент {name}", retryable=False)

def agent(question: str, max_iterations: int = 12):
    messages = [{"role": "user", "content": question}]
    system = ("Ты research-агент. Транзиентные ошибки повторяй один раз. "
              "Ошибки с isRetryable=false не повторяй: объясни причину, используя customerMessage, "
              "если оно есть. Пустой список результатов — это валидный ответ «ничего не найдено».")
    for _ in range(max_iterations):
        resp = client.messages.create(model=MODEL, max_tokens=1024, system=system,
                                      tools=TOOLS, messages=messages)
        if resp.stop_reason != "tool_use":
            return "".join(b.text for b in resp.content if b.type == "text")
        messages.append({"role": "assistant", "content": resp.content})
        results = []
        for b in resp.content:
            if b.type != "tool_use":
                continue
            out = run_tool(b.name, b.input)
            print(f"    → {b.name}({b.input}) = {json.dumps(out, ensure_ascii=False)[:100]}")
            results.append({"type": "tool_result", "tool_use_id": b.id,
                            "content": json.dumps(out, ensure_ascii=False),
                            "is_error": bool(out.get("isError"))})
        messages.append({"role": "user", "content": results})
    return None

if __name__ == "__main__":
    print(agent("Достань выручку за Q3 из документа DOC-1042."))
    print("\n---\n")
    print(agent("Достань показатели из документа DOC-9000."))
```

**Задание.**

1. Замените описания на односложные («Analyzes content», «Analyzes a document») и задайте десять запросов вперемешку про веб-страницы и документы. Посчитайте долю неверной маршрутизации.
2. Добавьте в системный промпт фразу «при работе с документами обязательно уточняй детали» и посмотрите, как запросы про веб-страницы начнут уходить в документные инструменты. Это ловушка ключевого слова из гайда.
3. Уберите структуру из ошибок — верните `{"error": "Operation failed"}` во всех случаях — и посчитайте, сколько раз агент повторит `DOC-9000`, который недоступен навсегда.

## 🎯 На экзамене

- **Цель 2.1**: описание как механизм выбора, что в нём должно быть, переименование ради устранения пересечения, разделение универсального инструмента, влияние ключевых слов системного промпта.
- **Цель 2.2**: флаг `isError`, четыре категории ошибок, `isRetryable`, `customerMessage` для бизнес-ошибок, локальное восстановление против проброса координатору, отличие отказа доступа от пустого результата.
- Сценарии: **Multi-Agent Research System** и **Customer Support Resolution Agent** — оба построены вокруг MCP-инструментов.
- Ловушка по 2.1: «добавить в системный промпт правило, какой инструмент когда использовать». Иногда помогает, но экзамен ждёт исправления **описаний** — промпт не должен компенсировать плохой интерфейс.
- Ловушка по 2.2: «добавить экспоненциальные ретраи для всех ошибок». Ретраи полезны только для транзиентных; структурированные метаданные существуют ровно для того, чтобы не тратить попытки впустую.
- Отдельно помните про пустой результат: инструмент, отвечающий ошибкой на «ничего не найдено», порождает бессмысленные повторы.

## 📌 Запомнить

- Модель выбирает инструмент по описанию. Описание — это интерфейс: назначение, формат входа, примеры, краевые случаи и граница с похожими инструментами.
- Пересекающиеся описания лечатся переименованием и уточнением; универсальный инструмент — разделением на целевые с чёткими контрактами.
- Ключевое слово в системном промпте может перебить хорошее описание. При разборе неверной маршрутизации проверяйте и промпт тоже.
- Ошибка возвращается со структурой: `isError`, категория (`transient`/`validation`/`business`/`permission`), `isRetryable`, понятное сообщение и `customerMessage` там, где ответ пойдёт человеку.
- Транзиентное чинится локально; наверх уходит только нерешённое — с частичным результатом и описанием предпринятого.
- Пустой результат — не ошибка. Это успешный ответ «совпадений нет».
