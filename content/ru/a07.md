# Модуль A7. Workflow или агент?

> **Уровень:** Middle AI · **Время:** ~50 минут · **Формат:** ситуация → теория → практика → квиз

---

## 🏢 Ситуация

Успех: доля черновиков без правок — 78%, Игорь доволен. Марина расширяет задачу:

> «Теперь пусть агент сам собирает информацию о лиде. Зайдёт на сайт компании, посмотрит вакансии, найдёт последние новости — и напишет действительно персональное письмо. Дадим ему инструменты, пусть работает.»

Вы делаете автономного агента: даёте четыре инструмента и цель «собери контекст и напиши письмо». Запускаете на 20 лидах.

Результат через сорок минут:

- один агент сделал 34 вызова поиска по одной компании и остановился по лимиту;
- второй решил, что данных мало, и написал письмо про «вашу отрасль в целом»;
- третий залез на страницу вакансий конкурента, потому что она была в выдаче;
- четырнадцать отработали отлично;
- счёт за час — как за прошлую неделю целиком.

Лена смотрит на трейсы: «А зачем ты вообще дал ему решать, в каком порядке ходить? Ты же сам знаешь порядок».

## 🎯 Ваша задача

1. Понять, где автономия даёт ценность, а где только дисперсию и счёт.
2. Переписать сбор контекста как детерминированный граф.
3. Оставить агентность там, где она действительно нужна.

### Тест на три вопроса

Перед тем как дать модели решать порядок действий, ответьте:

1. **Знаю ли я порядок шагов заранее?** Если да — это workflow. «Сайт → вакансии → новости → письмо» вы знаете.
2. **Конечно ли число вариантов?** Пять типов лидов с разными маршрутами — это ветвление в коде, а не рассуждения модели.
3. **Что я делаю, если агент выбрал плохо?** Если ответ «не знаю» или «замечу через неделю» — автономию давать рано.

В нашем случае ответы: знаю, конечно, замечу поздно. Значит, граф.

### Где автономия оправдана

- **Исследование:** «найди, кто в компании отвечает за данные» — маршрут зависит от того, что нашлось.
- **Отладка и разбор:** «разберись, почему этот прогон упал» — шаги зависят от находок.
- **Длинный хвост:** случаи, для которых нет смысла писать отдельную ветку.

Признак: заранее нельзя написать список шагов, потому что второй шаг зависит от результата первого **непредсказуемым** образом.

### Бюджеты вместо надежды

Если автономия всё-таки нужна, она ограничивается явно:

| Ограничение | Зачем |
| --- | --- |
| Максимум шагов цикла | Защита от зацикливания (34 вызова у первого агента) |
| Максимум вызовов на инструмент | Один инструмент не съест весь бюджет |
| Бюджет токенов на задачу | Предсказуемый счёт |
| Таймаут на всю задачу | Пользователь не ждёт вечно |
| Белый список доменов | Агент не уйдёт на сайт конкурента |

Достигнут лимит — это не ошибка, а штатный исход. Возвращаем частичный результат и отмечаем причину остановки.

## 💻 Практика

Тот же сбор контекста — но как граф. Модель вызывается на каждом шаге, порядок задан кодом.

```python
import os, json, anthropic
from urllib.parse import urlparse

client = anthropic.Anthropic(api_key=os.environ["ANTHROPIC_API_KEY"])
MODEL = "claude-sonnet-5"
ALLOWED_HOSTS = {"careers.", "jobs.", "blog.", "www."}     # белый список префиксов

# --- Шаги графа: каждый делает одно и возвращает структуру ---
def step_company_page(lead):
    html = fetch(lead["website"])                       # ваша функция загрузки
    return extract(html, "Опиши, чем занимается компания, 2 предложения", max_tokens=200)

def step_jobs(lead):
    url = find_careers_url(lead["website"])
    if not url or not same_site(url, lead["website"]):   # не уходим на чужой сайт
        return None
    return extract(fetch(url), "Перечисли открытые вакансии, связанные с данными и ML", max_tokens=300)

def step_news(lead):
    items = search_news(lead["company"], limit=3)        # ваш источник новостей
    return items or None

def collect_context(lead):
    """Порядок известен — значит, он в коде. Каждый шаг необязателен."""
    ctx, notes = {}, []
    for name, fn in [("about", step_company_page), ("jobs", step_jobs), ("news", step_news)]:
        try:
            value = fn(lead)
        except Exception as e:
            notes.append(f"{name}: ошибка ({type(e).__name__})")
            continue
        if value:
            ctx[name] = value
        else:
            notes.append(f"{name}: пусто")
    return ctx, notes


def write_with_context(lead):
    ctx, notes = collect_context(lead)
    # Ветвление в коде, а не «пусть модель решит»
    if not ctx.get("jobs") and not ctx.get("news"):
        return None, f"нет зацепки: {'; '.join(notes)}"    # честный отказ вместо общих слов
    draft = generate_grounded(lead, ctx)                   # из A5
    return draft, None
```

А вот где автономия остаётся — исследовательский подшаг «найди ответственного за данные», где маршрут заранее неизвестен:

```python
MAX_STEPS = 6
MAX_PER_TOOL = 3

def find_data_owner(company, tools):
    """Автономный подшаг с жёстким бюджетом. Достигнут лимит — штатный исход."""
    messages = [{"role": "user", "content": f"Найди, кто в компании {company} отвечает за данные или ML."}]
    used = {}
    for step in range(MAX_STEPS):
        resp = client.messages.create(model=MODEL, max_tokens=700, tools=tools, messages=messages)
        if resp.stop_reason != "tool_use":
            return {"answer": resp.content[0].text, "steps": step, "stopped": "answered"}
        messages.append({"role": "assistant", "content": resp.content})
        results = []
        for block in [b for b in resp.content if b.type == "tool_use"]:
            used[block.name] = used.get(block.name, 0) + 1
            if used[block.name] > MAX_PER_TOOL:
                results.append({"type": "tool_result", "tool_use_id": block.id,
                                "content": "лимит вызовов этого инструмента исчерпан",
                                "is_error": True})
                continue
            if block.name == "fetch_url" and not allowed(block.input.get("url", "")):
                results.append({"type": "tool_result", "tool_use_id": block.id,
                                "content": "домен не в белом списке", "is_error": True})
                continue
            results.append({"type": "tool_result", "tool_use_id": block.id,
                            "content": run_tool(block.name, block.input)})
        messages.append({"role": "user", "content": results})
    return {"answer": None, "steps": MAX_STEPS, "stopped": "budget"}   # не ошибка, а исход


def allowed(url):
    host = urlparse(url).netloc
    return any(host.startswith(p) or host.endswith(".com") for p in ALLOWED_HOSTS)
```

Что изменилось по сравнению с «дадим четыре инструмента и цель»:

1. **Порядок шагов — в коде.** Тридцать четыре вызова по одной компании стали невозможны структурно.
2. **Отказ вместо общих слов.** Нет вакансий и новостей — не пишем «про вашу отрасль в целом», а отдаём лида человеку.
3. **Белый список доменов.** Агент не уйдёт на сайт конкурента, даже если тот в выдаче.
4. **Лимиты на инструмент и на цикл.** Остановка по бюджету — нормальный, логируемый исход с частичным результатом.

**Задание.** Возьмите свой автономный прототип и посчитайте по трейсам: сколько шагов в среднем, какой разброс, сколько стоит худший прогон. Затем перепишите известную часть маршрута в граф и сравните числа. Обычно средняя стоимость падает в 2–4 раза, а дисперсия — на порядок.

## 📌 Запомнить

- Автономия — не уровень развития системы, а плата за неизвестность маршрута.
- Знаете порядок шагов — зашейте его в код. Это дешевле, предсказуемее и проще чинить.
- Три вопроса перед выдачей автономии: знаю ли порядок, конечны ли варианты, замечу ли плохой выбор.
- Автономия оправдана в исследовании, отладке и длинном хвосте — там, где второй шаг зависит от первого непредсказуемо.
- Любой цикл ограничивают: шаги, вызовы на инструмент, токены, время, домены.
- Остановка по бюджету — штатный исход с частичным результатом, а не исключение.
