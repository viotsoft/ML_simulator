# Модуль A13. Когда агент ломается

> **Уровень:** Middle AI · **Время:** ~50 минут · **Формат:** ситуация → теория → практика → квиз

---

## 🏢 Ситуация

Пятница, 16:40. Тимур из инфраструктуры пишет в общий чат:

> «У провайдера моделей деградация, отвечает через раз. Ваш сервис ретраит в бесконечном цикле и выел все воркеры. Заодно я вижу в CRM восемь одинаковых заметок по одному лиду и три письма одному человеку за десять минут. Я вас выключил.»

Разбор показывает три отдельные поломки:

- **Ретраи без потолка.** Провайдер отвечал 529, код повторял бесконечно, очередь встала.
- **Повторы после таймаута.** Запрос уходил, ответ не приходил вовремя, повтор создавал вторую заметку — а первая тоже доезжала.
- **Нет деградации.** Система умеет только «работать полностью» и «стоять». Промежуточного состояния нет.

Марина спрашивает то, что спросит любой руководитель: «А что должно было произойти вместо этого?»

## 🎯 Ваша задача

1. Сделать так, чтобы сбой провайдера не превращался в лавину.
2. Гарантировать, что повтор не создаёт второе действие во внешнем мире.
3. Спроектировать деградированный режим: что система делает, когда моделей нет.

### Предохранитель (circuit breaker)

Ретраи с паузой (из A2) защищают от единичного сбоя, но не от **массового**. Когда провайдер лежит, три тысячи задач одновременно начинают повторять запросы — и добивают и провайдера, и себя.

Предохранитель работает как в электрике: считает свежие ошибки и при превышении порога **размыкает цепь** — перестаёт пробовать вообще на минуту. Потом пропускает один пробный запрос: получилось — замыкает обратно, нет — ждёт дальше.

| Состояние | Что делает | Переход |
| --- | --- | --- |
| Замкнут | Пропускает запросы | 5 ошибок подряд → разомкнут |
| Разомкнут | Мгновенно отказывает, не тратя время и деньги | Через 60 секунд → полуоткрыт |
| Полуоткрыт | Пропускает один пробный запрос | Успех → замкнут, ошибка → разомкнут |

### Идемпотентность на уровне процесса

В A9 мы сделали идемпотентной запись в CRM. Но повтор бывает не только внутри одного прогона: воркер упал после отправки письма, но до записи «отправлено» — и следующий воркер отправит его снова.

Лечится **ключом задачи**: `outreach:{lead_id}:{campaign_id}`. Перед действием — попытка занять ключ в хранилище с TTL. Занял — работаешь; не занял — задача уже выполняется или выполнена. Это дешёвая блокировка, которая закрывает 99% дублей.

Правило: **ключ вычисляется из бизнес-смысла**, а не из времени или случайного числа. `uuid4()` на каждый запуск не защищает ни от чего.

### Таймауты и бюджет времени

У каждого вызова — свой таймаут, и у всей задачи — общий бюджет. Без общего бюджета сумма «разумных» таймаутов даёт минуты ожидания: пять шагов по 30 секунд — это две с половиной минуты на одно письмо.

Практика: таймаут одного вызова 20–30 секунд, бюджет задачи — 90 секунд, дальше частичный результат или очередь.

## 💻 Практика

```python
import os, time, json, hashlib, threading, anthropic

client = anthropic.Anthropic(api_key=os.environ["ANTHROPIC_API_KEY"], timeout=25.0)


class CircuitBreaker:
    """Защита от лавины: когда провайдер лёг, перестаём стучаться."""
    def __init__(self, threshold=5, cooldown=60):
        self.threshold, self.cooldown = threshold, cooldown
        self.failures, self.opened_at = 0, None
        self.lock = threading.Lock()

    def allow(self):
        with self.lock:
            if self.opened_at is None:
                return True
            if time.time() - self.opened_at >= self.cooldown:
                self.opened_at = None          # полуоткрыт: пропускаем один пробный
                self.failures = self.threshold - 1
                return True
            return False

    def record(self, ok):
        with self.lock:
            if ok:
                self.failures, self.opened_at = 0, None
            else:
                self.failures += 1
                if self.failures >= self.threshold:
                    self.opened_at = time.time()

    @property
    def is_open(self):
        return self.opened_at is not None


breaker = CircuitBreaker()

# Ключ идемпотентности — из бизнес-смысла, а не из времени
def task_key(kind, **parts):
    raw = kind + ":" + ":".join(f"{k}={parts[k]}" for k in sorted(parts))
    return hashlib.sha256(raw.encode()).hexdigest()[:32]


def claim(key, ttl=3600):
    """Занять задачу. False — её уже кто-то делает или сделал."""
    return redis.set(f"task:{key}", "1", nx=True, ex=ttl)      # ваш Redis/БД


def call_model(task, **kw):
    if not breaker.allow():
        raise Degraded("предохранитель разомкнут: провайдер недоступен")
    try:
        resp = client.messages.create(**kw)
        breaker.record(True)
        return resp
    except anthropic.APIStatusError as e:
        breaker.record(e.status_code in (429, 500, 502, 503, 529))
        raise
    except anthropic.APITimeoutError:
        breaker.record(False)
        raise


class Degraded(Exception):
    pass


# --- Деградированный режим ---
MODE = {"level": "normal"}          # normal | degraded | stopped

def health_loop():
    """Режим переключается автоматически по состоянию зависимостей."""
    while True:
        if breaker.is_open:
            MODE["level"] = "degraded" if small_model_alive() else "stopped"
        else:
            MODE["level"] = "normal"
        time.sleep(10)


def handle_outreach(lead, campaign_id, deadline_s=90):
    key = task_key("outreach", lead=lead["id"], campaign=campaign_id)
    if not claim(key):
        return {"status": "skipped", "why": "задача уже выполнена или выполняется"}

    if MODE["level"] == "stopped":
        enqueue_for_later(key, lead, campaign_id)      # ничего не теряем
        return {"status": "queued", "why": "модели недоступны, задача отложена"}

    if MODE["level"] == "degraded":
        # Исходящие могут подождать; входящие — нет. Приоритет — не тишина, а выбор.
        enqueue_for_later(key, lead, campaign_id)
        return {"status": "queued", "why": "деградированный режим: исходящие отложены"}

    started = time.monotonic()
    try:
        ctx = collect_context(lead)                     # A7
        if time.monotonic() - started > deadline_s * 0.6:
            raise Degraded("бюджет времени почти исчерпан на сборе контекста")
        draft = build_email(lead, recall(lead["id"]), ctx)   # A10, A12
        return {"status": "drafted", "draft": draft}
    except Degraded as e:
        enqueue_for_later(key, lead, campaign_id)
        return {"status": "queued", "why": str(e)}
    except Exception as e:
        release(key)                                    # ошибка не по вине задачи — можно повторить
        raise
```

Что здесь важно:

1. **Предохранитель заменяет лавину на быстрый отказ.** Когда провайдер лежит, вы не тратите воркеры и деньги на заведомо провальные попытки.
2. **`claim()` до действия.** Ключ из бизнес-смысла (`lead + campaign`) не даст отправить второе письмо тому же человеку, даже если воркер упал посередине.
3. **Три режима, и в каждом система осмысленна.** В «стоп» задачи принимаются и складываются — потерять входящее хуже, чем обработать позже.
4. **Бюджет времени проверяется в середине.** Если сбор контекста съел 60% бюджета, письмо уходит в очередь, а не начинает генерироваться в никуда.
5. **`release(key)` при чужой ошибке.** Ключ не должен блокировать задачу навсегда, если упало по не связанной причине.

## 📌 Запомнить

- Ретраи с паузой спасают от единичного сбоя; от массового спасает предохранитель.
- У системы должно быть три режима: норма, деградация, стоп. В любом из них задачи не теряются.
- Ключ идемпотентности выводится из бизнес-смысла — `lead + campaign`, а не `uuid4()`.
- Занимайте задачу до действия, а не после: воркер может упасть между отправкой и записью.
- У каждого вызова свой таймаут, у задачи — общий бюджет времени, который проверяют по ходу.
- Учения с заглушённым провайдером — единственный способ узнать, что всё это работает.
