# Модуль A1. Идея CEO в понедельник: «сделаем маркетинговую фабрику»

> **Уровень:** Junior AI · **Время:** ~50 минут · **Формат:** ситуация → теория → практика → квиз

---

## 🏢 Ситуация

Понедельник, 9:40. Вы — AI Engineer в **Datacore**. Той же компании, где вы прошли ML-трек: маркетплейс, 2 млн активных пользователей, финтех-продукт. Только теперь у вас две шляпы — классический ML и агентные системы.

В общий чат падает сообщение от **Марины, CEO**:

> «Коллеги, конкурент запустил AI-агента, который ведёт весь их исходящий маркетинг. Хочу такую же **маркетинговую фабрику** у нас — к концу квартала. Кто у нас по AI? Давайте в переговорке в 10:00.»

В 10:00 в переговорке трое, и каждый слышит в слове «фабрика» своё:

- **Даша, CMO:** «Мне нужно в десять раз больше контента. У меня два копирайтера и они горят.»
- **Игорь, Head of Sales:** «Мне контент не нужен. Мне нужны письма конкретным лидам, которые не стыдно отправить.»
- **Виктор, CFO:** «Сколько это стоит в месяц и что мы перестанем платить, когда оно заработает?»

Марина смотрит на вас: «Ну что, за квартал сделаем?»

Здесь принимается решение, которое определит следующие три месяца. Не техническое — **постановочное**. Никто в комнате не сказал, что именно должен делать агент. «Маркетинговая фабрика» — это не задача, это желание.

## 🎯 Ваша задача

1. Превратить фразу CEO в конкретный проект: что агент делает, чего не делает **никогда**, как измеряется успех.
2. Выбрать уровень автономии — исходя из цены ошибки, а не из того, что умеет модель.
3. Нарезать «фабрику» на первый срез, который можно показать через две недели, а не через квартал.

## 📚 Теория

### Что вообще такое «агентная система»

Агент — это **LLM + инструменты + цикл + цель**. Модель не просто отвечает текстом: она решает, какой инструмент вызвать, смотрит на результат и решает снова — пока не достигнет цели или не упрётся в лимит.

Между «просто промптом» и «автономным агентом» есть целый спектр, и большинство рабочих систем живут не на правом краю:

| Уровень | Что это | Пример у нас |
| --- | --- | --- |
| Промпт | Один вызов, один ответ | Переписать абзац |
| Цепочка | Несколько вызовов подряд, порядок задан | Сжать → перевести → отформатировать |
| Workflow | Ветвление и инструменты, маршрут задан кодом | Разобрать письмо → если жалоба, завести тикет |
| Агент | Модель сама выбирает следующий шаг | Собрать данные о лиде и написать письмо |

Чем правее, тем выше потолок пользы — и тем выше цена ошибки, сложность отладки и счёт за токены. **Правый край — не цель, а инструмент.**

### Три вопроса, которые решают судьбу проекта

Их задают до первой строчки кода. Если на них нет ответов, проект закончится демо, которое никто не внедрит.

**1. Что такое единица работы?**

Не «фабрика», а то, что можно назвать в единственном числе: *одно письмо конкретному лиду*, *один разобранный ответ*, *один пост*. Всё, что нельзя посчитать поштучно, нельзя ни оценить по времени, ни измерить по качеству, ни посчитать по деньгам.

**2. Что значит «сделано хорошо» — в числах?**

Не «качественный контент», а метрика, которую считает скрипт без человека:

| Плохая метрика | Почему плохая | Хорошая замена |
| --- | --- | --- |
| «Контент стал лучше» | Нельзя посчитать | Доля черновиков, отправленных без правок |
| «Агент работает быстро» | Не про пользу | Ответов на 100 отправленных писем |
| «Сэкономили время» | Кто мерил? | Часов копирайтера на 20 писем: было/стало |

**3. Сколько стоит ошибка?**

Опечатка в черновике, который человек всё равно вычитает, стоит ноль. Письмо пяти тысячам клиентов с ценой, которой нет в прайсе, стоит денег, репутации и разговора с юристами.

Цена ошибки — единственный честный аргумент в споре об автономии. Не «модель уже достаточно умная», а «если она ошибётся здесь, мы потеряем столько-то».

Правило простое: **автономию зарабатывают числами**. «200 черновиков подряд, 92% отправлены без правок, ноль случаев выдуманных фактов» — это аргумент. «Мне кажется, оно уже хорошо пишет» — нет.

### Agent Design Doc на одну страницу

Документ, который вы приносите Марине вместо ответа «за квартал сделаем». Заполняется за час, экономит недели.

| Раздел | Для маркетинговой фабрики |
| --- | --- |
| Работа, которую нанимают сделать | Заполнить воронку исходящих писем без роста команды |
| Единица работы | Одно персональное письмо одному лиду из списка ICP |
| Входы | Строка CRM: компания, отрасль, роль, недавнее событие |
| Инструменты | Чтение CRM, поиск по сайту компании, черновик в почте |
| Выходы | Тема, тело письма, самопроверка по чек-листу |
| **Запреты** | Не называть цены и сроки, которых нет в прайсе; не выдумывать факты о получателе; не отправлять без подтверждения |
| Гейт человека | Отправка — только после нажатия «Отправить» человеком |
| Метрика успеха | Доля черновиков, отправленных без правок; ответов на 100 писем |
| Режимы отказа | Нет данных о лиде → пропустить; модель недоступна → очередь |
| Бюджет | Стоимость запуска × 20 писем в день × 22 дня ≤ лимит от CFO |

Раздел «Запреты» — самый важный и самый пропускаемый. Именно он превращается в system-промпт, в чек-лист самопроверки и в тест-кейсы.

## 💻 Практика

Единица работы уже определена — один лид даёт один черновик. Собираем её целиком: запреты из Design Doc уходят в system-промпт, ответ приходит структурированным, а стоимость считается сразу, чтобы к Виктору идти с числом, а не с ощущением.

```python
# pip install anthropic
import os, json, anthropic

client = anthropic.Anthropic(api_key=os.environ["ANTHROPIC_API_KEY"])
MODEL = "claude-sonnet-5"

# Цены за миллион токенов — подставьте актуальные из прайса вашей модели
PRICE_IN, PRICE_OUT = 3.0, 15.0

# Единица работы: одна строка CRM → один черновик
LEAD = {
    "company": "NordFin",
    "industry": "финтех, 400 сотрудников",
    "name": "Ирина",
    "role": "Head of Data",
    "trigger": "на прошлой неделе открыли вакансию ML-инженера",
}

# Раздел «Запреты» из Design Doc дословно становится частью промпта
SYSTEM = """Ты пишешь первое холодное письмо от лица Datacore — платформы для команд,
которые внедряют ML в продукт.

ЗАПРЕТЫ (нарушение = брак, письмо не отправляется):
- не называй цены, сроки, скидки и гарантии;
- не выдумывай факты о компании получателя — используй только то, что дано;
- не обещай результатов в цифрах;
- не более 120 слов в теле письма.

ОБЯЗАТЕЛЬНО: одна конкретная причина, почему пишешь именно им, и один вопрос в конце.

Верни строго JSON:
{"subject": str, "body": str,
 "self_check": {"invented_facts": bool, "mentions_price": bool, "has_question": bool, "words": int}}"""

resp = client.messages.create(
    model=MODEL,
    max_tokens=800,
    temperature=0.7,          # для черновиков разнообразие полезно, для разбора почты — нет
    system=SYSTEM,
    messages=[{"role": "user", "content": json.dumps(LEAD, ensure_ascii=False)}],
)

draft = json.loads(resp.content[0].text)
check = draft["self_check"]

# Гейт качества: агент сам себя проверил, мы решаем, показывать ли человеку
ok = (not check["invented_facts"] and not check["mentions_price"]
      and check["has_question"] and check["words"] <= 120)

print("ТЕМА:", draft["subject"])
print(draft["body"])
print("\nСамопроверка:", check, "→", "в очередь на подтверждение" if ok else "БРАК, переписать")

# Экономика: с этим числом идут к CFO
cost = (resp.usage.input_tokens * PRICE_IN + resp.usage.output_tokens * PRICE_OUT) / 1_000_000
print(f"\nЗапуск: ${cost:.4f} · 20 писем/день × 22 дня = ${cost * 20 * 22:.2f}/мес")
```

Что здесь важно и переносится в любой следующий агент:

1. **Запреты живут в промпте дословно.** Не «пиши вежливо», а проверяемые правила.
2. **Ответ структурирован.** JSON вместо свободного текста — иначе следующий шаг конвейера не сможет ничего с ним сделать.
3. **Самопроверка — часть выхода.** Дешёвый фильтр до того, как черновик увидит человек. Он не заменяет эвалы (модуль A6), но отсекает грубый брак.
4. **Стоимость печатается сразу.** Цифра «$X в месяц» превращает разговор с CFO из спора в арифметику.

## 📌 Запомнить

- «Сделайте нам AI-агента» — это не постановка задачи. Постановка начинается с единицы работы, которую можно назвать в единственном числе.
- Уровень автономии выводится из цены ошибки, а не из возможностей модели.
- Метрика, которую нельзя посчитать скриптом, — это не метрика, а надежда.
- Первый релиз — один узкий лейн насквозь, с человеком в цикле. Автономию зарабатывают статистикой.
- Раздел «Запреты» в Design Doc — будущий system-промпт и будущие тест-кейсы. Пропустите его — и будете чинить это в проде.
- Джун строит автономного агента сразу и месяц отлаживает. Сеньор выпускает «черновик + подтверждение» за две недели и приносит числа.

**Что почитать:** Anthropic, «Building effective agents» (про спектр workflow → агент); Teresa Torres о формулировке работы-которую-нанимают-сделать; внутренние разборы инцидентов с автоматической рассылкой в любой крупной компании — лучший источник понимания цены ошибки.
