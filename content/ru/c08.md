## 🏢 Ситуация

Описания вы починили в C7, и маршрутизация стала предсказуемой. Через две недели она снова портится — но по другой причине.

За это время команда подключила ещё три MCP-сервера. Инструментов стало **восемнадцать**, и они выданы всем четырём субагентам одинаковым списком, «чтобы никто ничего не ждал». Результат:

- субагент-синтезатор, который по определению не должен добывать новые данные, лезет в веб-поиск и приносит факты мимо источников;
- субагент, читающий документы, вызывает `fetch_url` с идентификатором документа вместо адреса и получает ошибку валидации;
- на простом запросе стало в среднем на три вызова больше — модель перебирает похожие инструменты.

Параллельно всплывает конфигурационная неразбериха. Костя добавил Jira-сервер себе, Даша просит его же, но у неё не работает. Смотрите: Костя прописал сервер у себя в пользовательском конфиге и вписал туда токен прямым текстом. Ещё один сервер, командный, лежит в репозитории — вместе с ключом в открытом виде, который теперь надо ротировать.

И последнее: агент упорно ищет по репозиторию через `Grep`, хотя подключён MCP-сервер кода с индексированным поиском, который справляется лучше. Его описание — «Search code.»

## 🎯 Ваша задача

1. Раздать инструменты по ролям и понять, почему восемнадцать хуже пяти.
2. Разобраться с `tool_choice`: когда `auto`, когда `any`, когда принудительный вызов.
3. Развести конфигурацию MCP на проектную и личную, убрать секреты из репозитория.

## 📚 Теория

### Слишком много инструментов — это не «богатый выбор»

Принцип из гайда: **выдача агенту слишком большого числа инструментов (например, 18 вместо 4–5) ухудшает надёжность выбора**, потому что растёт сложность решения. И отдельно: агенты с инструментами вне своей специализации склонны их использовать не по назначению — ровно как ваш синтезатор с веб-поиском.

Приёмы, которые проверяет экзамен:

- **ограничить набор каждого субагента** его ролью;
- **заменить универсальный инструмент ограниченным**: вместо `fetch_url`, который тянет что угодно откуда угодно, — `load_document`, который валидирует, что это адрес документа;
- **дать узкий кросс-ролевой инструмент под частую нужду**: синтезатору — `verify_fact`, чтобы не гонять каждую проверку через координатор, но сложные случаи всё равно маршрутизировать через него.

### tool_choice: три режима

| Значение | Что делает | Когда нужно |
| --- | --- | --- |
| `"auto"` | модель решает сама, звать ли инструмент | обычная работа агента |
| `"any"` | модель обязана вызвать какой-нибудь инструмент | когда болтовня вместо действия недопустима |
| `{"type": "tool", "name": "..."}` | вызывается именно этот инструмент | когда первый шаг фиксирован |

Пример принудительного выбора из гайда: заставить `extract_metadata` отработать **первым**, до инструментов обогащения, а дальнейшие шаги обрабатывать в следующих ходах. То есть принуждение — это способ задать первый шаг, а не весь маршрут.

`"any"` решает отдельную проблему: модель отвечает текстом вместо того, чтобы вызвать инструмент. Если контракт вашего шага — «должен быть вызов», `"any"` его гарантирует.

### Конфигурация MCP: проект против личного

Два уровня, и путать их — источник ровно той неразберихи, что у Кости с Дашей:

- **`.mcp.json` в проекте** — общие командные серверы. Лежит в репозитории, применяется ко всем, кто работает с проектом.
- **`~/.claude.json` пользовательский** — личные и экспериментальные серверы. Не касается коллег.

Секреты в проектный файл не пишут. Для этого есть **подстановка переменных окружения**:

```json
{
  "mcpServers": {
    "jira": {
      "command": "npx",
      "args": ["-y", "@company/jira-mcp"],
      "env": { "JIRA_TOKEN": "${JIRA_TOKEN}" }
    }
  }
}
```

Файл коммитится, токен — нет. Каждый разработчик держит `JIRA_TOKEN` у себя в окружении.

Ещё три факта из этой цели:

- **Инструменты всех настроенных серверов обнаруживаются при подключении и доступны одновременно.** Отсюда и разрастание списка — подключили три сервера, получили восемнадцать инструментов.
- **MCP-ресурсы** — механизм показать агенту каталог доступного содержимого (сводки задач, иерархия документации, схемы БД), чтобы он не тратил вызовы на разведку. Ресурс отвечает на вопрос «что тут вообще есть», инструмент — «сделай вот это».
- **Для стандартных интеграций берут готовый community-сервер** (та же Jira), а собственный пишут только под специфичные командные процессы.

И причина последней жалобы: агент предпочитает `Grep` вашему индексированному поиску, потому что у MCP-инструмента описание в два слова. Гайд требует **дорабатывать описания MCP-инструментов**, объясняя их возможности и формат вывода, — иначе встроенные инструменты выигрывают выбор просто потому, что понятнее.

## 💻 Практика

Раздача по ролям, принудительный первый шаг и проектный конфиг без секретов.

```python
# pip install anthropic
import os, json, anthropic

client = anthropic.Anthropic(api_key=os.environ["ANTHROPIC_API_KEY"])
MODEL = "claude-sonnet-5"

ALL_TOOLS = {
    "search_web": {"name": "search_web", "description":
        "Ищет страницы по запросу в открытом вебе. Возвращает список {title, url, snippet}.",
        "input_schema": {"type": "object", "properties": {"query": {"type": "string"}}, "required": ["query"]}},
    "load_document": {"name": "load_document", "description":
        "Загружает документ архива по URL. Валидирует, что адрес указывает на документ "
        "(pdf/docx) во внутреннем домене; произвольные адреса отклоняет с validation-ошибкой. "
        "Замена универсальному fetch_url.",
        "input_schema": {"type": "object", "properties": {"url": {"type": "string"}}, "required": ["url"]}},
    "extract_metadata": {"name": "extract_metadata", "description":
        "Извлекает метаданные документа: тип, дату, автора, число страниц, язык. "
        "Вызывается ПЕРВЫМ: остальные инструменты обогащения опираются на её вывод.",
        "input_schema": {"type": "object", "properties": {"doc_id": {"type": "string"}}, "required": ["doc_id"]}},
    "enrich_entities": {"name": "enrich_entities", "description":
        "Обогащает документ сущностями (компании, суммы, даты). Требует метаданных документа.",
        "input_schema": {"type": "object", "properties": {"doc_id": {"type": "string"}}, "required": ["doc_id"]}},
    "verify_fact": {"name": "verify_fact", "description":
        "Проверяет ОДНО утверждение по уже найденным источникам. Узкий кросс-ролевой инструмент: "
        "доступен синтезатору для частых простых проверок. Сложные разбирательства — через координатор.",
        "input_schema": {"type": "object", "properties": {"claim": {"type": "string"}}, "required": ["claim"]}},
}

# Каждой роли — только её инструменты (4–5), плюс один кросс-ролевой там, где он реально нужен
ROLE_TOOLS = {
    "web":    ["search_web"],
    "docs":   ["load_document", "extract_metadata", "enrich_entities"],
    "synth":  ["verify_fact"],          # НЕ search_web: синтезатор не добывает новые данные
    "report": [],
}

def tools_for(role: str):
    return [ALL_TOOLS[n] for n in ROLE_TOOLS[role]]

def call(role: str, prompt: str, tool_choice=None, max_tokens: int = 1024):
    kwargs = {"model": MODEL, "max_tokens": max_tokens,
              "messages": [{"role": "user", "content": prompt}]}
    tools = tools_for(role)
    if tools:
        kwargs["tools"] = tools
        if tool_choice:
            kwargs["tool_choice"] = tool_choice
    resp = client.messages.create(**kwargs)
    return resp

if __name__ == "__main__":
    # 1. auto — обычный режим: модель сама решает
    r = call("docs", "Разбери документ DOC-1042 и расскажи, что в нём.")
    print("auto      →", [b.name for b in r.content if b.type == "tool_use"] or "текст без вызова")

    # 2. any — гарантируем, что будет вызов, а не рассуждение
    r = call("docs", "Разбери документ DOC-1042 и расскажи, что в нём.", tool_choice={"type": "any"})
    print("any       →", [b.name for b in r.content if b.type == "tool_use"])

    # 3. принудительный первый шаг: сначала метаданные, обогащение — следующим ходом
    r = call("docs", "Обогати документ DOC-1042 сущностями.",
             tool_choice={"type": "tool", "name": "extract_metadata"})
    print("forced    →", [b.name for b in r.content if b.type == "tool_use"])

    # 4. синтезатор физически не может уйти в веб-поиск
    r = call("synth", "Проверь утверждение «доля рынка 40%» и, если надо, поищи в вебе.")
    print("synth     →", [b.name for b in r.content if b.type == "tool_use"] or "текст без вызова")
```

Проектный конфиг (`.mcp.json` в корне репозитория) — коммитится без секретов:

```json
{
  "mcpServers": {
    "jira":  { "command": "npx", "args": ["-y", "@community/jira-mcp"],
               "env": { "JIRA_TOKEN": "${JIRA_TOKEN}" } },
    "code":  { "command": "npx", "args": ["-y", "@company/code-index-mcp"],
               "env": { "INDEX_URL": "${CODE_INDEX_URL}" } }
  }
}
```

Личный экспериментальный сервер живёт в `~/.claude.json` и коллег не касается.

## 📌 Запомнить

- Много инструментов ухудшают выбор. Ориентир гайда — 4–5 на роль, а не общий список на всех.
- Инструмент вне специализации агента будет использован не по назначению. Синтезатору не нужен веб-поиск.
- Универсальный инструмент заменяют ограниченным с валидацией входа; для частой простой нужды дают узкий кросс-ролевой, оставляя сложные случаи координатору.
- `tool_choice`: `auto` — обычно, `any` — когда нужен вызов, а не текст, принудительный выбор — чтобы зафиксировать первый шаг.
- `.mcp.json` — командные серверы в репозитории, `~/.claude.json` — личные. Секреты только через `${VAR}`.
- Инструменты всех подключённых серверов доступны одновременно; MCP-ресурсы показывают каталог и экономят разведочные вызовы.
- Скудное описание MCP-инструмента проигрывает встроенным: описание — это по-прежнему интерфейс выбора.
